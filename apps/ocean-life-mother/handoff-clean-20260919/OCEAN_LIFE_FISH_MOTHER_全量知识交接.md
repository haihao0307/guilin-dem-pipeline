## 一、这个项目到底要做什么

长期目标不是做一个“鱼模型展示器”，而是建立 **Ocean Life Mother——热带海洋与海岛生命体系**，最终给 Stone Money Island / Survivor Palau 游戏提供真实、精致、可持续扩展的生命系统。

完整体系以后可以包含：

- Fish：鱼类形体、材质、动作、鱼群、捕食与躲避；
- Bird：海鸟、岸鸟、飞行、停驻、觅食；
- Coral：珊瑚形态、群落、材料、栖息关系；
- Tropical Island Life：岛上植物、蝙蝠、低频漂入动物等；
- Habitat：沙滩、礁盘、内礁、通道、外礁坡、深海；
- Time / Tide / Weather：时段、潮水、季节、风暴；
- Food Web：饵鱼、捕食鱼、海龟、鳐、鲨鱼、鸟等关系；
- Game Mother 接口：观察、钓鱼、生存、记录、生态事件。

但这次重开以后，必须收住：

## 五、鱼体函数体系

用户的核心理解是：鱼体不是必须靠传统模型文件保存，它可以通过横向、纵向、截面和时间关系表达。

一个合格的鱼体坐标至少需要：

- 从头到尾的纵向位置；
- 每一节的宽度函数；
- 每一节的高度函数；
- 中轴和局部方向；
- 左右、背腹关系；
- 头部和尾柄的特殊变化；
- 局部非对称和物种特征；
- 时间 / 成长阶段参数；
- 所有器官的稳定附着坐标。

重要原则：

- 横向和纵向不是乱噪声；
- 每一个位置都要在统一身体坐标中有意义；
- 噪声只能提供受约束的细节变化，不能代替解剖结构；
- 函数表达不能把鱼做成简陋的椭球；
- 函数只是表达手段，最终必须和真实鱼对得上。

### 头、嘴、眼、鳃、鳍必须是真结构

必须分别处理：

- 头骨和头部体积；
- 上下颌、口腔、开口边缘；
- 眼球、角膜、瞳孔、转动范围；
- 鳃盖、鳃缝、呼吸动作；
- 躯干；
- 尾柄；
- 尾鳍根部和尾鳍形状；
- 背鳍、臀鳍、胸鳍、腹鳍的根部和表面；
- 鳞片或无鳞表面；
- 左右结构和真实不对称。

禁止：

- 嘴只画一条黑线；
- 鳃只画一道颜色；
- 鳍像纸片一样悬空；
- 眼睛固定死；
- 所有鱼都共享同一个错误头部。

## 六、材质、PBR、色彩和变体

材质必须在稳定的鱼体坐标里表达，不能随世界位置滑动。

至少需要分别处理：

- Base Color / Albedo；
- Alpha / 透明度；
- Roughness；
- Specular / F0；
- Normal / 微表面；
- 必要时的其他光学参数；
- 鳞片方向；
- 鳍条方向；
- 条纹、斑点、网纹、边缘色；
- 头部、腹部、背部、鱼鳍等区域掩码。

色彩可以使用标准 PBR、明确颜色空间、Pantone 等现有系统，不要发明混乱的颜色编号。

必须区分：

1. 不同物种；
2. 雌雄差异；
3. 幼体 / 成体；
4. 地区 / 个体色型；
5. 生理状态变色；
6. 环境光照造成的颜色变化；
7. 单纯实验配色。

第二张鱼类合集图左侧的圆盘形鱼说明：相似形体可以有多种色彩配方。但这不能自动证明它们是同一种鱼、同一拓扑或同一成长阶段。

## 七、从幼鱼到成鱼

最终每一种鱼都应考虑生命周期，但不能简单等比例缩放。

需要真实资料支持的变化包括：

- 头身比；
- 眼睛相对大小；
- 嘴、颌和口裂；
- 身体高宽；
- 尾柄和鱼鳍比例；
- 鳞片可见程度；
- 花纹、色区和颜色；
- 游速、摆尾频率、动作幅度；
- 食性；
- 捕食者；
- 栖息区域；
- 群游角色。

只有一个成年参考时，幼体必须保持未知，不能把成年鱼缩小以后称为幼鱼。

## 八、动作体系

模型里的动画只能作为观察，不是最终动作资产。

动作内核需要逐步拆成：

- 身体中线弯曲；
- 振幅沿身体的变化；
- 相位延迟；
- 摆尾频率；
- 尾鳍动作；
- 背鳍 / 臀鳍稳定；
- 胸鳍 / 腹鳍控制；
- 转弯；
- 加速；
- 眼球转向；
- 张嘴、闭嘴；
- 鳃盖呼吸；
- 水流中的世界位移。

必须有多种状态，而不是一个循环动画：

- 稳定巡游；
- 慢速转向；
- 加速；
- 逃跑；
- 追逐；
- 摄食；
- 躲藏；
- 返回栖息点；
- 群游；
- 休息或低活动状态。

动画播放时长不能直接当作真实游速。没有真实尺度、相机、流速、轨迹，就只能记录相对量。

### 水流和游速

重要原则：

- 鱼相对水体的游速，决定它自身运动和摆尾；
- 水流决定鱼在世界坐标中的输运；
- 逆流时鱼可能世界位置不动，但仍在游动；
- 不能用世界位移直接驱动摆尾；
- 这条原则只在有对应证据时转成具体数值，不能一套参数套所有鱼。

## 九、鱼群 / BIOS

鱼群不是整段烘焙动画，也不是每条鱼观察全世界。

目标体系：

- 每条鱼只观察附近少量邻居；
- 前方负责发现食物、路线和危险；
- 侧面 / 后方维持群体关系和传播警戒；
- 分离、对齐、凝聚是不同作用；
- 群体边缘、内部、带头个体可以有不同角色；
- 行为有记忆和状态，不能每帧抖动切换；
- 鱼群受到捕食者、玩家、礁体、潮水和食物影响。

已有 school-of-fish 文件只能帮助观察作者做出的轨迹，不能证明自主群游已经完成。

## 十、海洋生态关系

鱼不能随机均匀撒满场景。每种鱼有自己的空间、速度、群聚、时间和食物关系。

主要栖息分区：

- 沙滩 / 浪打边界；
- 礁盘；
- 内礁 / 潟湖；
- 珊瑚斑块；
- 通道；
- 外礁坡；
- 陡降 / 深海；
- 远洋水体；
- 水面层。

帕劳特点：

- 外礁盘保护内侧，很多内礁不是持续大浪环境；
- 近岸、礁盘、通道、外礁和深海外观及生态不同；
- 外礁外侧可以迅速变深；
- 潮水、时段、季节、通道和饵鱼决定大型鱼出现概率；
- 吞拿鱼可能跟随饵鱼进入通道 / 礁区，但不是绝对；
- 沙丁鱼等饵鱼有季节和路线；
- Barracuda、GT、鲨鱼等会响应饵鱼，但生态关系不能写成单线脚本。

目标动物群：

- 沙丁鱼 / 饵鱼群；
- Tuna；
- Barracuda；
- GT；
- Shark；
- Snapper，包括以后补充的 red / black snapper；
- 小丑鱼和宿主海葵关系；
- 其他珊瑚礁观赏鱼；
- 海龟；
- Manta Ray；
- Eagle Ray；
- 其他 Ray；
- Seabird 等后续联系。

“大鱼吃小鱼”只是最粗的开始。最终要考虑：物种、体型、生命周期、饥饿、食物、季节、深度、潮水、遮挡、速度和栖息地。

## 十一、玩家与鱼

玩家在游戏中不仅是捕鱼，也要观察自然。

目标行为：

- 玩家接近，礁鱼躲开；
- 鱼不能瞬移；
- 玩家离开、危险解除后，鱼回到宿主 / 栖息点；
- 鱼始终在水中；
- 鱼不能钻进沙滩下面；
- 观察笔记记录真实看到的内容；
- 未识别的鱼不能被系统自动假装识别；
- 后续和钓鱼、食物、背包、Game Mother 接口连接。

## 十二、物理底线

任何视觉优化都不能破坏：

- 鱼不穿沙；
- 鱼不穿岸；
- 鱼不穿岩石；
- 鱼不穿珊瑚；
- 鱼不越出水面，除非是明确的跃出动作；
- 海床显示和碰撞必须读取同一世界定义；
- 要检查整个身体和鱼鳍，不只是中心点；
- 不安全移动要拒绝，不能瞬移；
- 朝向必须跟运动一致；
- 相机远近不能重置物理历史；
- 单位、坐标、时间、潮位基准必须明确；
- 未知流速不能偷偷填 0。

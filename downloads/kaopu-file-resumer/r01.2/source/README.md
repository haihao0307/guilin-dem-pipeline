# 靠谱文件续传器 · r01.2

Python 3.12 标准库本地工具。统一深色窗口，默认 3 个任务并行（可选 1–6），可随时粘贴多个 HTTPS 下载链接。每个任务独立保存检查点，断网退避重试，完成后自动补上排队任务。无需 pip 或第三方运行库。

## Windows 启动

1. 将 ZIP 全部解压到固定、可写、仅自己使用的文件夹。不要直接在压缩包里运行。
2. 双击 `launch.vbs`。它查找已有 Python 3.12，使用 pythonw 启动，不需要打开 IDLE。
3. 需要桌面图标时，双击一次 `create-shortcut.vbs`。只在你运行后创建，不添加开机启动或计划任务。
4. 默认保存到用户 Downloads 下的“靠谱文件续传”；可在粘贴前选择其它目录。
5. Ctrl+V 粘贴或点“粘贴并入队”即开始。不会后台监听剪贴板。

若系统禁用 VBScript，可运行 `py -3.12 app.py`；`diagnose.cmd` 用于排查。缺 Python 时启动器只提示官方网站 python.org，不静默安装。已安装 Python 3.12.10 通常可直接使用，但需要 Tcl/Tk 组件。

## 迁入目前的香港 ZIP 进度

不要删除原脚本、Chrome 残片或“恢复工作副本”。先停止旧工具，避免两个工具同时处理源文件。

在新窗口点“导入旧分段…”，选择旧工具的“恢复工作副本”（或其父目录），阅读一次复制/完整性提示，再粘贴对应原文件的当前官方 HTTPS 链接。可先导入一份，再导入另一份。

仅支持旧工具已记录的 `11-NW-25C.zip`、`11-SW-5A.zip` 检查点。新工具核对固定文件身份、原前段 SHA256、每个已提交块 SHA256，再复制至独立子目录，从已有偏移继续。额外空间约等于已下载部分，最终两份约需 3.1 GiB 新空间。原目录及第三个残片不修改。没有可信检查点的任意 `.crdownload` 不会按大小猜测接续。

截图中的第二个窗口是 IDLE 重复日志，第三个窗口是旧工具的试恢复确认。新版本不需要反复开 IDLE，也不会在每次网络重连弹同样确认；身份变化、CRC失败、认证失败会停在“需要处理”。

## 续传、重启与安全

- 只接受 HTTPS（测试服务器仅测试代码显式启用 localhost HTTP）。TLS正常验证。
- 续传要求强 ETag、Range/206、准确 Content-Range、Content-Length 和 identity 编码。200 响应绝不追加；不自动重定向。
- 每块 1 MiB：完整收到后刷盘并原子提交检查点；未提交尾块可安全丢弃。恢复前核验已提交块，不靠文件尺寸认身份。
- 网络超时约 20 秒，短期指数退避（2 秒至约 4 分钟）；连续 8 次失败后按看门狗间隔（默认 10 分钟，可选30分钟）低频重试。手动暂停、403/登录/验证码、身份变化及TLS安全异常不会被看门狗重新启动。
- 完成 ZIP 必须通过所有条目的 CRC；其它文件校验长度和本地块 SHA256，不冒称与源站独立发布的哈希一致。
- 最终文件放在独立任务子目录，避免同名覆盖。需要处理的旧进度原地隔离保留；不会悄悄整包重下。
- Windows 使用当前用户 DPAPI 加密保存完整下载 URL；日志不写 URL 查询密钥。队列在程序目录 `data`。不要公开 `data` 或有效下载链接。跨 Windows 账户/机器迁移时可能需重新粘贴链接。
- 关闭再开会恢复排队/重试任务，手动暂停仍暂停。非 Windows 测试环境不持久保存 URL，重启需更新链接。
- 更新链接只支持同一站点和同一路径的查询密钥刷新；不同文件/跳转到不同路径请新建任务，旧进度保留。
- “打开来源登录”打开默认浏览器的来源站首页，不是内置登录系统。浏览器登录状态不会自动共享给 Python；请获取新的直接下载链接。程序不读取 Chrome Cookie/密码，不绕过登录或验证码。
- 主程序保持打开时自动恢复；关闭后不后台运行，不创建定时任务。

## r01.1 启动诊断改进

- `launch.vbs` 改用正常窗口样式；pythonw本身不显示控制台，不再额外要求隐藏窗口。
- 优先从注册表和既有安装目录找Python，备用Launcher查询有10秒上限。
- 新增 `bootstrap.pyw`：主窗口初始化失败时给出明确提示并写入 `startup.log`；Tk组件缺失也有Windows消息框。
- 正常使用不需要控制台；失败时才运行 `diagnose.cmd`。不联网安装软件。
- r01仍保留。若已在r01创建下载任务，不要同时启动两个版本。迁移前先关闭r01，将其整个 `data` 文件夹复制到当前新版目录，再从新版启动；仍使用原任务保存位置。没有创建过任务则无需复制。
- 聊天里的ZIP附件点不开属于文件交付问题，不能据此判断Python或启动器失败；本补丁不声称能修复聊天附件下载。

新增无显示环境故障注入已验证：启动失败生成日志、输出提示并返回非零状态。Windows消息框/真实桌面仍待实机确认。

## r01.2 解压检查

启动与创建快捷方式之前都会检查同目录下的 launch.vbs、app.py、core.py、bootstrap.pyw、dpi_support.py。缺少任何一项会用中文提示“请先全部解压，不能在ZIP里运行”，不生成指向缺失文件的快捷方式。

若目录位于当前账户临时文件夹，会建议迁到固定目录，但可自行确认继续。解压后先运行 launch.vbs，主窗口正常后再运行 create-shortcut.vbs。曾在ZIP里创建的旧桌面快捷方式应由新目录中的脚本替换。

本次不改变下载核心。Windows脚本仍需要实际电脑验收。

正确的四彩图标原件尚待提供。本候选版不采用用户已否决的旧图，也不重画。可通过“更多→选择个人图标”明确选择本地ICO或PNG；ICO可由重新运行create-shortcut.vbs同步到桌面图标，PNG仅用于窗口。

从任何既有新版升级到r01.2前：正常关闭旧窗口，保留旧版本；如旧版已建立任务，将旧版整个data文件夹复制到r01.2目录后再启动。不要同时运行两个版本处理同一批任务。

## r01.2 清晰度与紧凑界面

标题为 KAOPU File Resumer。创建Tk窗口之前尝试启用Windows Per-Monitor DPI Awareness v2，较旧Windows使用兼容回退，不改变系统缩放设置、不强制倍增字号。实际字体清晰度与多显示器切换仍须在用户Windows屏幕确认。

窗口默认900×600，可缩到360×260。较窄或高度不足时自动显示紧凑布局，保留粘贴入队、任务选择与进度、暂停/继续、更多操作。设置为可滚动的小窗口；输入链接、更新地址、旧进度导入与日志也可从更多菜单访问。

正确四彩图标缺失，因此品牌图标替换仍未完成，不应将个人图标选择功能描述为已替换成用户指定图标。

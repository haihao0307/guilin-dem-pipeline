# KAOPU Crab 项目全量协调状态 R04（2026-09-30）

## 一、用户最新裁决

- 不再把最初椰子蟹模型的导出分块当作运动结构。
- 最初椰子蟹必须作为一个整体观察和重构。
- 不同结构通过骨架和连续权重驱动，不能通过零件平移制造动作。
- 当前椰子蟹仍有可见破碎、裂缝、错误姿态和缺乏真实物理支撑的问题，尚未验收。
- 新上传的普通螃蟹模型带骨骼和动画。必须先对它完成一比一表面程序化重构，再从中学习螃蟹骨架、蒙皮、动作和耦合知识。
- 普通螃蟹只做骨架/动作老师；椰子蟹的最终外形仍以最初椰子蟹老师为准。

## 二、现有阶段

### R01
完成最初椰子蟹全表面采样与函数曲面谱。工程边界可保留，但视觉未获用户批准。

### R02
加入纹理图集和基础生命模式，但错误地把来源导出块提升为运动对象，造成开裂和不自然动作。该运动路线作废。

### R03
改为一个正式蒙皮绘制对象、53 根骨骼、最多 3 个权重影响、42 个关节膜和固定长度足链。它证明了整体蒙皮架构可运行，但骨架是从静态椰子蟹表面推断而来，缺少真实老师；用户仍判定外形和动作不对，因此不能作为最终形态基线。

## 三、新普通螃蟹老师审计摘要

- glTF 2.0
- 1 个网格
- 51,686 个顶点
- 92,491 个三角形
- 1 套 skin
- 126 个 joints
- 1 套动画，66 个通道
- 动画时长约 0.48 秒
- 包含左右四对步足链、左右螯足链、眼柄链及 IK 控制节点
- 具备 `JOINTS_0`、`WEIGHTS_0`、126 个 inverse bind matrices 和逐节点旋转动画

完整层级、绑定矩阵、权重统计和动画关键帧位于文本交接包的 `animated_teacher/`。

## 四、二进制事实

GitHub 当前连接只能直接写 UTF-8 文本或由文本传入的 blob，不能从本地挂载路径直接上传几十 MB 的原始 ZIP、纹理和二进制缓冲。该分支已经保存所有可直接提交的源码、状态、审计、骨架、绑定矩阵、权重统计、动画关键帧、原始 glTF JSON 分片、哈希和文件尺寸。

原始二进制源仍必须按 `source_registry/SOURCE_REGISTRY_R04.json` 中的 SHA-256 补入仓库发布资产或 Git LFS。任何代理不得假称这些大文件已在 GitHub 中。

## 五、下一阶段验收顺序

1. 普通螃蟹静态一比一程序化重构。
2. 普通螃蟹重构结果与老师六视图、腹面及局部表面误差验收。
3. 读取老师真实 skin、骨架和动画，建立通用蟹类运动声部。
4. 回到最初椰子蟹完整表面，先消除所有裂缝和断面。
5. 根据椰子蟹形态重新定位骨架和权重，迁移知识而非复制普通螃蟹。
6. 足端接触、承重、摆动、身体重心、螯钳、触角和眼柄统一耦合。
7. 固定公开 URL、桌面和移动端 QA、用户视觉与动作验收。

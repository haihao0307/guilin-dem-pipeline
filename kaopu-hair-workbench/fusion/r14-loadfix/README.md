# R14.2-L01 — 只修启动，不改发型

用户截图的界面已加载，但停在“原 GNM · 2.7 MB”，报“资源读取停滞，请重试”。旧 AssetLoader 连续20秒没有新数据即终止，90秒总时限。原主资源为9,930,135字节gzip；回退为34,937,952字节raw，两个地址都使用raw.githubusercontent.com。2.7MB表示已收到字节数，不是总大小。截图不足以区分用户网络、代理、浏览器连接调度或远端链路的具体停滞原因。

本修订从冻结R14.2 `c40a86c92b2fe37179e29a67628bf26303745d60`继承。只新增r14-loadfix及专用工作流。原r14及更早版本不改，不采用已拒绝R14.3几何。

## 修复

原GNM gzip无损嵌入网页，运行时不再次请求模型服务器；皮肤、眼球、眉毛、Three.js仍随页内嵌。解码分块让出主线程，解压输出严格限制原始字节数，原GNM SHA-256必须一致，不移除校验、不换白模、不降采样。

界面明确区分随页数据读取、本地解压、SHA校验、原人物材质及毛发生成。启动失败时不再误称“旧造型未被替换”，显示未生成人物；提供重试和诊断复制。解码阶段失败可原页重试，已创建部分渲染对象后的失败通过明确标注的整页重载恢复，避免重复头模/资源泄漏。

## 验证

Node受控断流：旧加载器在接收2.7MB后停止读入，使用加速的30ms空闲计时复现原错误文案；不冒充用户真实网络抓包。

新加载器校验完整、截断、哈希错误、体积越界和取消。浏览器阻断GNM模型网络请求，仍须实际渲染原人物与头发；三预设根点/发丝/头部hash、导向数、可见发数、几何缓冲与冻结R14.2一致。受控缺失payload触发失败后，通过真实重试按钮恢复且仅一个头部。另测保存恢复及390×844手机视口。最终需重新打开固定公网URL实际操作。

## 边界

网页本身依然需要网络下载。单文件因内嵌模型变大，约21MB；这修复的是“页面已开，另一个大模型下载中途失败”的薄弱环节，不意味着离线首次访问、任意网络都成功或所有设备不再崩溃。首次解码/解压需要CPU与额外临时内存；原64k发丝缓冲约201MB不变，多开重型三维页面仍可能有独立GPU内存风险。只测手机视口，不冒充手机实机。没有改进冠部残余视觉缺陷，也没有新增动态物理。

方法核对：MDN DecompressionStream https://developer.mozilla.org/en-US/docs/Web/API/DecompressionStream 。保留原项目全部许可和来源记录，无新模型版权引入。

# KAOPU 毛发：参考图驱动路线与基础内核优先级

日期：2026-10-13。
状态：用户方向确认；以下工程分层与验收是开发约定，不代表相应运行时已经实现或验收。
本文件只新增文档，不修改旧短发、旧长发、人物、灯光或其他工作台。

## 用户确定的目标

用户给发型图片，或给名字由助手检索对应参考图片。图片决定目标形状、长度、分缝、层次和卷曲。助手负责整理证据、推断不可见区域并构建完整方案；用户不承担逐个滑块塑造发型的工作。通用系统优先建设生长域、稳定根点、发丝形态与基础物理，其余参数可调。已认可短发保留冻结；有问题的中长/长发独立推进。

允许在许可证与依赖审查通过后复用研究代码；修改参数不改变原许可，也不把第三方代码转换成自主版权。代码、权重、训练数据、示例头模、材质及参考照片的使用边界分别核查。

## 必须纠正的前提

1. Example-Based Hair Geometry Synthesis 是 SIGGRAPH 2009 的已有三维发型几何示例合成，不是开箱即用的单照片重建与物理系统。借鉴头皮参数空间、分层发束、粗到细细节转移和轨迹方向一致性；本次未找到可直接接入的官方开源实现与许可证。
2. 单图约束的是可见轮廓和局部方向，不能唯一确定背面、内层、完整发丝弧长或真实毛囊。隐藏区域允许合理补全，但标记 inferred，不冒充 measured。生成的背面图片只能作为假设先验，不能当新观测反复验证自身。
3. 图片中的最终发型不是物理材料参数。设计静态形状、无应力参考形状、重力平衡形状和运动状态分开，避免把照片的下垂再用重力重复下垂。
4. 生长域、剃短/显示范围、分缝方向、造型轮廓分开。不能让刘海遮盖到额头就把根点种到额头；不能通过挖掉大块根点制造分缝；不能用加密发丝掩盖错误方向或起根穿面。

## 统一架构

参考证据 ReferenceEvidence -> 可编辑 HairRecipe -> 原生头皮绑定的 GuideGroom -> HairPhysicsState 与 DenseStrandRenderer。

ReferenceEvidence 保存图片引用与哈希、来源/使用边界、视角/尺度、可见轮廓、方向、发梢范围、分缝、遮挡与推断状态。名字只是检索入口；同一个人不同年代/不同发型不能混成一套，最终锁定实际参考图片集合。

HairRecipe 保存目标人物拓扑/版本、生长域引用、根点种子、区域分组、分缝/冠旋、方向/起根角度场、物理弧长分布、导向曲线、卷曲/发束细节、约束、材料及来源证据。颜色改变不重生成根点；镜头旋转不重新拟合照片。

GuideGroom 是从根到梢的真实三维曲线，有静态设计形状、区域归属和稳定原生绑定。根点由 triangleId + barycentric + localFrame 引用人物表面，不使用另一个外部头模替换目标人物。

HairPhysicsState 只保存当前曲线状态、速度、约束乘子等瞬态量，不覆盖静态方案。物理少量导向曲线，大量渲染跟随发共享同一组根域/方向/造型数据；插值跟随发仍要做身体穿入检查。

原图和大体积曲线缓存按项目母本保存为资产引用；正式方案与版本/撤销分开管理。参考原图不默认提交公开 GitHub。新照片/新头型使旧拟合任务失效，旧任务不能覆盖新方案。

## 四个大步骤

### 1. 共用毛发底座：生长域、稳定根点、起根方向、三维导向曲线

收尾S01B前额、额角、鬓角、耳上、耳后、枕部与后颈范围。轮廓、填色、根点启用使用同一数据。保留已认可短发和原有稳定绑定；诊断采样数量不冒充真实毛囊数量。增加区域方向、冠旋/分缝、独立弧长、静态曲线和局部形态参数，停止把统一起根角度或全头放射方向当正式造型答案。

验收：原生头型变化、密度和观察角度改变不重新随机搬根；正常默认方案无激活根点落到禁长区；边界与根点一致；稀疏导向发能显示完整前后结构。尚未验证的人物体型和参数范围明确列出。

### 2. 基础物理：先小规模跑稳，再放大

第一版选择一个约束式求解器，不叠加多套相互争夺同一曲线的物理系统。采用XPBD风格的长度/弯曲约束、参考曲率/形状保持、根部位置与方向约束、阻尼、重力和风。固定时间步/受控子步；头、耳、颈、肩和上胸使用同一人物的碰撞表示。结合距离场或加速曲面查询，检查有半径的发丝段及快速运动，不能只检查少数端点。

先用少量导向发验证静止、缓慢/快速转头、低头、风起停与肩部接触；观察拉长、爆炸、持续抖动、根漂移与穿入。发发自接触先采用明确标注的发束/密度近似，复杂编辫、盘发和精确逐丝互碰不纳入第一批无条件承诺。静态造型要能在重力下保持，不因启用物理而整体换发型。

### 3. 图片/名称到完整可编辑方案

最短路径先由助手分析参考图并输出HairRecipe，形成图片驱动、助手参与的完整闭环，不等待从零训练万能识别模型。分析相机、尺度、轮廓、发际线、分缝、发束层级、发梢、卷曲与遮挡，把约束投射到同一人物和稀疏导向发。隐藏部分按照可见接续、区域长度、连续方向及不穿头耳肩原则补全；重要歧义保留少量替代候选。

建立原图视角重投影对照，同时检查左右侧/后脑/顶部。第二张图到来时更新低可信补全部分，保留确认过的部分。照片估算的长度要换算到目标人物尺度；曲线弧长不等于照片中发梢到根部的直线距离。

自动分割、方向估计及GPU逆向拟合后续通过可替换适配器加入。重拟合可以是异步准备任务，网页观察、已有模型播放和简单参数修改不能等它重跑完。

### 4. 密发、材质、流畅度与公网验收

只有导向轮廓正确后才生成跟随发与发束细节，禁止形成两层互不一致的生长系统。发丝半径/尖端、卷曲、发束离散、颜色、粗糙度、各向异性高光及阴影按方案可调。解决透明露皮和远景闪烁，不以额外黑帽片或重复外层遮挡替代真实根域。

生成、运行时物理、渲染分开计时。缓存已生成资产；改颜色只更新材质，改风只更新模拟，局部改造型只重建相应区域。主线程不执行大批同步生成；重算可取消；后台窗口暂停昂贵运行。

性能目标而非已测成绩：秒级可操作/稀疏预览、目标桌面接近60fps；具体密发数量、设备、分辨率和物理档位以实测决定。复杂照片首次重建不承诺几秒完成。公网HTTPS固定版本验收真实渲染、主要交互、刷新恢复及版本；手机视口不冒充实机，未通过写“交付未完成”。

## 最快实施批次

第一批合并步骤1与步骤2的基础版，交付可转头、受风、具备头耳肩接触的稀疏导向工作台，不再只交一张蒙版检查页。前额/耳后/后颈必须可查，旧短发不动。

第二批合并步骤3与步骤4的第一套参考图闭环，交付符合指定图片、背面补全可解释、可以实时运动与调参的三维毛发方案。先选参考图支持的普通中长披发或较简单卷曲作为端到端验证；复杂束发/盘发/编辫后续增加明确约束，不把所有类型一次性承诺为已支持。

## 外部老师与复用结论（2026-10-13核查）

- Example-Based Hair Geometry Synthesis：方法老师，已有三维示例->分层发束->方向一致性->细节；不是单照片重建器。页面只列论文、视频、附录；未确认可复用官方源码。
- PositionBasedDynamics：主仓MIT，包含距离/弯曲XPBD、弹性杆、碰撞等参考实现。选择最小适用数学内核，移植并测试为自己的WebGPU/TypeScript运行层，不照搬整个C++演示工程。
- AMD TressFX：MIT条款；参考根部绑定、局部形状保持、碰撞、GPU调度与LOD。公开工程面向DirectX/Vulkan；需要浏览器适配，不宣称直接贴入Three.js即可运行。
- Digital Salon：主代码MIT，但项目明确示例头模未随仓库提供，演示中Adobe内部资产与公开替代数据不同；CUDA/C++和Python依赖不是网页即插即用。学习交互与数据分层，合规复用经筛选的源码；AI生成照片不代替真实3D验收。
- Perm：主代码MIT，适合学习全局造型与局部卷曲解耦。README当前说明公开单视图重建流程仍待重实现，个别模型/原始单视图流程需联系作者获独立许可。不能把MIT主仓误称为完整公开照片入口。
- Im2Haircut（ICCV2025）：更直接对应单照片->发丝三维，包含mask/orientation/depth/camera预处理。README说明3DGS部分另有条款，其余CC BY-NC-SA4.0；不直接作为可商用生产依赖。CUDA11.8、作者A100测试条件不是普通浏览器部署证明，也不等于A100是最低硬件要求。研究其外部观测+全局先验+局部优化架构，必要时另行授权。
- HairOrbit（2026）：论文把单图通过视频生成先验转为校准多视图任务，再估计方向并生长三维曲线，适合学习不可见区域补全。本次未确认可运行官方源码与授权；不把它设为首批阻塞依赖。生成视图保持inferred标记。

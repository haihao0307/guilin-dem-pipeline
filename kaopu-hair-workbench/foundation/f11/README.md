# F11 · 从真实根区长出的密集完整发丝

上一版只显示 43 个体积子束，虽然有 114171 根的数量预算，密集发丝并未生成。F11 将默认预算中的 **114171 根全部生成**，每根有独立的原生三角面/重心根绑定和 49 个三维路径点，共 5480208 段。不是把 192 根辅助导向计为完整头发，也没有用面片纹理假装数量。

人物仍是自己平台的完整「清俊 P01」，原生公共拓扑 25417 顶点 / 50624 三角面，渲染 266098 顶点。人物、皮肤、骨架和原生 viewer.mesh 保持平台所有权；没有导入第三方头部或发型资产。

## 生长与分层

已通过的头皮域 → 11 个主源区 → 默认 43 个有独立源面积的子束 → 连续二维截面体积与扭转 → 按实际源面积抽样的独立毛根 → 每根完整发丝。每根均从自己的真实根点开始，穿过同束场的不同位置，保留宽度、厚度和内外层关系；没有从外壳随机撒线。

六个可检查层组是前额刘海、左右贴脸长束、左右外长束、顶后与遮挡内层。密度按完整人物的实际源区面积约 634.2812 cm² 计算。180 根/cm² 是工程设定，不是从照片测得的真实毛囊密度。80–260 的密度调整会实际增减生成和绘制的发丝，源区不随密度移动。

每根的小幅连续变化沿发束自己的宽度轴与厚度轴展开，扭转仍使用平行运输截面。近根变化归零；发尾有连续长度分布和少量错落，刘海末端另做横向展开，避免全部挤成粗束尖角。侧后方及裁切外的发顶属于依据正面照片的人工补足。

## 查看与交接

默认显示全部密集发丝，采用便于判断走向的中性灰色。可切换分层着色、独立子束、真实头皮源区、半透明发束体积、截面方向和原生转头。体积与实际发丝可以分别开关。

“导出全部发丝路径”输出 `KAOPU_DenseHair_F11.bin.gz`，包含全部实际路径、每根原生绑定、层组、子束、采样参数、人物存档、当前原生表面位置散列和一次 placement。解码模块是 `src/StrandExchange.mjs`。坐标为 `native-common-viewer-Yup`，单位米，后续表现工作台可沿这些路径添加自己的细发几何和材质。

原有 `GuideGroom@5` 仍交接 192 根导向、源区、体积截面、数量和保型规则，并明确标识对应的独立完整发丝文件。导向包本身不冒充全部发丝。

## 自查边界

生成时检查每根的每段中心线是否穿过当前原生身体，并做局部修正。它不代表有限半径发丝、发丝之间、自碰撞或动态摆动已经通过。原始根绑定保持不动；转头时每根用自己的原生表面局部框架随动。非刚性大变形下的全长身体避让未认证。

当前发丝是独立三维曲线，预览使用屏幕像素宽的线段绘制，尚非真实圆柱半径的最终渲染。这不影响三维路径、总体积、数量和绑定交接；最终材质与动态物理由另一个工作台继续处理。发型相似度仍需用户审阅，数值检查不证明已经复现照片。

## 验证

`tests/bundle-core.mjs` 检查既有源区、截面、导向、原生交接和规则。`tests/dense-core.mjs` 检查全部实际数量、每根根绑定、有限路径、独立末端、实际中心线和二进制交接。`tests/dense-browser.mjs` 在独立无界面 Chrome 中检查真实 WebGL、全部实际几何、分组、密度、扭转、原生转头、下载文件、恢复和手机布局。截图在 evidence/candidate 与 evidence/public，不控制桌面鼠标。

源码提交、压缩人物 payload、不可变预览和公开复查分别固定，并核对源散列与运行时散列。旧版目录保持不变。

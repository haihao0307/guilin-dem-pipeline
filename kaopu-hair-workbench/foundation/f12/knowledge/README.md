# F12 · 三维发束构建、错误与检查依据

## 用户最终方向

原始照片和用户给出的发束分析示例为造型依据。用户否定助手的线稿表达和手绘分区，明确要求直接构建三维；这些助手图稿已从公开源码和生成输入移出，私有 QA 仅保留失败历史。当前保留六个主要层组和 11 个原生头皮主源区；默认裁分为 43 个体积子束，每束从自己的源区长出，保留二维截面、独立收尾和连续扭转。

## 本轮实际失败

1. F07：先造全局外壳再按高度/方位给面分组，缺少源区到完整发束的关系；刘海与外壳的视觉关系被用户否定。
2. F08：虽然根绑定与整条路径连续，线和窄带仍不能表达用户要求的完整发束体量。技术检查通过不等于造型正确。
3. F09 手绘区域：没有严格贴合真实发纹，用户要求停用。它不是三维区域或数量的来源。
4. 第一轮三维：在源区边界重新调用分类，左侧分缝边界可能被分成右侧，刘海边界可能被分成长发，导致突兀外鼓和跨面拉伸。改为显式传递不可变 bundleId，并由其决定侧向。新增各组边界归属、最大横向范围和刘海最低高度检查，实际前后和双侧再审。
5. 只检验穿面无法发现绕目标盘圈；保留所有导向到达各自终点高度的检查。
6. 版本名的文本替换曾误碰到包含 f08 的原生索引散列。原生索引校验拒绝了该版本；恢复原始标识，并用实际 native 输入重新核验。以后改版本仅针对标识字段，不替换散列子串。

7. F09 的闭合盖面仍呈薄帘。F12 改为根区二维坐标到椭圆截面的连续映射；中段直接检查真实几何宽厚，不以“双面材质”或“封口”代替体积。
8. 初次在截面场上逐样本避让耳朵时，同一个目标过多滑移尝试让个别内层导向绕行到约 723 mm。限制每个场进度的局部追随步数，检查实际弧长及终点误差；当前未保留该失败路径。
9. 子束过早收尖会将齐肩发型拆成粗绳。主体改到最后约 10% 路径才适度收拢，保持大形衔接；小刘海单独减薄。仍需美术复查，技术通过不等于与参考一致。

## 观察与推定

正面可观察偏分、斜刘海和少量碎束、贴脸层与外层的覆盖、肩部附近的内收。隐藏根区、后脑厚度、后颈内层和真实发丝数量不能从单图确认。P01 上的长度、宽厚和密度均为工程造型初值。

## 函数归属与数据权威

NativeSurface：固定 P01 公共表面、根绑定和源区映射。BundlePlan：固定工程根点与整束身份、内外层归属和导向配额。PortraitBob：按明确身份的贴头梳理、下落和发梢目标；边界不可重新分类。BundleVolumes：在头皮上裁分源区，核对实际三维面积，从该源区沿同束场生长体量，按源区面积计算预算和稳定采样。SweptClumps：双坐标源区到二维截面映射、最小旋转运输及轴向扭转；导向和显示体积使用同一截面目标场，导向另做原生身体避让。ShapeView：半透明三维体量、子束隔离、截面和不透明轮廓检查，和显示用 0.8mm 源区盖面抬高，不修改绑定。GuideExchange：原生重建、source cells/数量/体量交接与一致性检查。NativeApp：同一个 P01 场景、轻微原生转头和一次 placement。StyleRules：未标定的工程形体、弯曲、扭转及截面保型权重。

## 不把原则当效果证明

此前参考的 Disney Hair Pipeline、Tonic、Hair Meshes 和 Holding the Shape in Hair Simulation 仅作为造型、导向、模拟和表现分离的原则来源。本轮主要依据用户直接纠正的规则和给定发型，没有导入第三方头、发型或材质，也未声称复现研究的完整方法。

证据在 evidence/bundle-core.json 和 candidate/public 浏览器报告、当前真实 WebGL 图中。面积守恒、正确归属、数量可生成、绑定随动和形体美术验收是不同条件，不能互相替代。


## F11 密集发丝自查

用户指出 F10 仍过于概括，要求几乎全部头发都有表达。确认 F10 的 114171 只是数量预算，43 个体积代理和 192 根导向不构成完整密集头发。F11 按实际原生 source-cell 面积 CDF 在各子束中抽样全部目标毛根，逐根经过同一二维体积场；保留原生面与重心坐标，根点不抬高。

第一轮密集画面仍有 5 个粗尖刘海和整排发尾，因此增加平滑发尾长度分布与刘海末端展开；变化在近根归零。第一次用邻近身体平面缓存避让时，44352 个抽查段中有 31 个穿面，集中在耳侧。不能用稀疏导向检查替代密集发丝检查，改为对全部段做原生三角面中心线检查并局部修正。极少数凹处经法向修正仍失败，缩短该段的前进距离，保持根绑定不动，继续跟随后续场；记录修正、缩短和未解决数量。

默认中性灰是阅读走向的显示选择，不是完成的发色或材质。逐根三维曲线的屏幕线宽不是物理半径；体积、路径和最终圆柱/发片渲染应分别判断。DenseStrands 管完整路径生成，StrandView 管真实全量显示及自己的根框架随动，StrandExchange 管原生坐标完整路径交接。参考位图未发布，助手旧区域图不进入生成。


## F12 连续发流与定型

F11 的平均路径加 rootDelta 逐段收拢会制造成排转折；发顶宽直缝由硬左右方向和过早归并共同形成。第一轮 CrownFlow 只沿头皮一段再混回旧场，产生环状折痕，已移除。RootFlow 改为每根沿统一的头皮相对梳理场、下落与内收走完整路径。前部偏分缓慢变化并允许少量几何交叠，后部逐渐转为发旋；真实根和源区标签不动。实际体积截面须与生成框架分开测量，禁止修改测量包络后反过来改变发丝生成。

定型原则参考 Pixar 作者 Iben 等 2019 的 Holding the Shape in Hair Simulation：可以通过额外的软约束保持造型局部关系，不只依靠逐点硬锁定。论文原文存档：https://history.siggraph.org/wp-content/uploads/2022/09/2019-Talks-Iben_Holding-the-Shape-in-Hair-Simulation.pdf 。本项目没有复现 Taz 求解器，只建立自己的局部权重与交接。

发型产品的束级弯曲测试提示产品与纤维组合的效果需要单独测量，不能从“gel”一词推定真实刚度。原始研究索引：https://pubmed.ncbi.nlm.nih.gov/20939974/ 。当前 free/wax/gel 系数均为自定工程优先级，非从实验读出的物理参数；材料常数保持 null。

Styling.mjs 负责区域与独立区间；StyleRules@3 负责逐导向物理权重；NativeDenseHair@2 保留每根内在源坐标与同一配置，消费者可按真实弧长重建。对自然、发泥、凝胶的比较必须保持几何与输入一致，检查真实导出权重，而非把预制摆动动画称作物理。

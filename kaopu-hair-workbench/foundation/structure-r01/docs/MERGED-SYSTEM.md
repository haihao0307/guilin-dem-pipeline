# 同一工作台的结构 / 发质 / 物理边界

用户于 2026-10-16 明确授权把发型与发质物理两边合到这个工作台。保留用户指南的顺序：先静态结构，后子发丝及质感，最后运动。合入源提交为 `539907a343d93e8c058d1dfff8445bd910faec75`；来源快照不再追随另一个运行目录的未完成修改。

## 当前已实际接上的部分

- `integrations/fiber-runtime-r08` 保存来源、逐文件散列、完整依赖及既有报告；不是以旧演示替换当前人物和发型。
- 本工作台的 `StructureRuntimeInput` 从实际结构创建可变 Guide 数量的连续缓冲区：原生三角面/重心坐标、稳定根身份、完整节点、弧长、运输坐标、发丝物理直径与三级束链。当前为 144 条、13,968 节点，既不强制旧演示的 96 条，也不强制 F14 的 43 条。
- 页面实际建立此输入，物理开关经过同一 R08 接入门禁。未获得对应结构的人工视觉验收前，后台创建函数不会执行。
- `RuntimeController` 已合入，动作时钟与求解频率分离；不自行注册帧循环；可有界调整近远求解预算。用实际结构数据检查复制无损、根身份不变、局部位移保持在运输截面内，并检查静态门禁与近远时钟。
- 局部子发丝接口按照每条 Guide 的运输坐标取偏移。没有导入旧世界坐标加权混合，也没有把 Guide 当成最终密集发丝。

## 按用途逐项保留，而非全部启用

| 来源系统 | 合并决策 | 后续适配条件 |
|---|---|---|
| 动作 / 求解时钟分离、预算迟滞 | 复用控制器，现有检查覆盖 | 静态通过后让当前人物的动作端口驱动本结构 |
| 原生姿态缓存 | 冻结实现与研究记录 | 要求匹配现有人物着色与姿态版本，再实测多通道收益 |
| 身体接触场与碰撞缓存 | 保存实现，保留按姿态失效机制 | 必须使用当前原生身体和真实发束半径，不能只靠中心线 |
| 束群摩擦 / Guide 求解 | 保存算法，不创建旧 Groom | 改用本结构可变数量、区域权重、RestShape 和束链；先测弧长漂移 |
| 细发 / 静止形态缓存 | 保存策略，不分配 GPU 纹理 | 消费当前运输坐标子发丝布局，正确按发型和绑定版本失效 |
| 远处预算 / 惯性 | 保存方案 | 连续变化，不切换发型，不丢整个局部发区 |
| 透明度 / 阴影合成 | 保存实现，第一轮不启用 | 后续重新检验头型透出、背面深度和多通道复用，不能把旧效果称为已修复 |
| 来源 Groom / app | 仅参考来源 | 不替代这里的发型生成器和页面入口 |

## 当前未完成项

当前是结构研究与统一接口的基线，**尚无可驱动本结构的完整物理/密集渲染后端**。F14 适配只支持既有 F14 对象，不冒充本结构的适配。来源性能报告的压力测试总门槛为未通过；不能依据正常机器结果宣称低配达标。

结构、粗细、根中梢、碰撞、加载分别需要视觉和性能验收。第一轮静态页面不加载来源的 app、Groom、Three.js 副本、密集渲染器或求解器；打包器仅引入无副作用的控制器与门禁。动作资源随成果冻结，静态轮次不下载或播放。

下一步继续研究时，结论记录在 `RESEARCH.md`，规则进入 `HairStyleProfile` 和数据合同。物理不能反过来寻找发型；三种长度必须各自设计其静止结构。

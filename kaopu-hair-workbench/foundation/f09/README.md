# F09 · 从原生头皮源区长成三维发束

本版直接在完整「清俊 P01」上构建半透明发束体量。原始发型照片和用户提供的分束参考用于人工三维造型；助手绘制的分区图已被用户否定并停用，不是生成输入。用户优先要求形体、出根方向、完整发束和后续资产匹配，表现材质和真实物理留给后续工作。

## 当前结构

照片参考的六个主要层组是前额刘海、左右贴脸长束、左右外长束、顶后与遮挡内层。三维内部使用 11 个独立头皮子域，分别处理斜刘海/中央少量碎束、贴脸层、外层、耳侧、后上层和后颈的不同路径。左右按正面画面描述。

`NativeSurface` 将既有 F02.1 头皮域精确映射到同一个 P01 原生三角面。`BundleVolumes.splitRootPatches` 先在这些头皮小三角形中裁分源区，保留原生面编号、重心坐标和实际三维面积。所有源区面积相加仍为约 634.2812 cm²，未改变发际线或人物网格。

每个源区独立向自己的发梢生长：192 条原生根点导向定义该束的方向场；源区边界及内部终点通过同束场延伸，形成有宽度和厚度的三维体量。根部、侧面、发梢继承同一源区拓扑。六组共 11 个体量，原生根点工程样本仍为 3067 个。没有先造一个通用头发外壳再给其块面取名。

根区边界的归属在生成全过程固定。边界点恰好落在分缝上时，必须继承当前发束的身份和侧向，不重新分类。初稿曾在此处把左侧点归入右侧，造成用户指出的突兀鼓包；已修正并加入对应的整束范围、边界归属和刘海终点检查。

两侧在头顶沿头皮铺开，在面颊外侧形成弧度，末端向内收。长短与少量外突连续变化，保持固定根部。中心碎束已缩小源区并减少导向占比。所有形体数值是 P01 上可调的造型初值，不是照片测量得到的真实尺寸。

## 查看方式

默认显示 28% 不透明度的完整发束体量，导向线仅作辅助，可单独打开。支持全身、正面、两侧、斜前、后脑和头顶，单独查看整组，并突出其头皮出发面积。显示用源区盖面抬高 0.8 mm 以避免与人物高密度渲染皮肤互相遮盖；真实源区、导向根点及导出重心绑定仍位于原生表面，未移动。

半透明体量用于结构检查，不是最终发卡、发丝或材质。后脑、侧向深度、耳后与后颈层的细节为推定；当前没有自动照片重建或用户美术验收的承诺。

## 数量从哪里来

每个源区保存完整面积分布。目标数量按实际 P01 根区面积 × 可调目标密度分配，默认基准为 180 根/cm²，总预算约 114171 根；这只是工程目标，不是从照片测得的真实毛囊数。整数数量通过余数分配，确保子域、层组和总数一致。

`samplePatchRoots` 按三维面积加权，在原生面上以稳定种子生成可复现的重心坐标根点；数量增加时保留已有随机序列前缀。192 条导向和 3067 个固定工程根点样本不等于最终头发数量。当前显示发束体量，尚未生成这些密集跟随发丝或接入表现资产。

## 人物与交接

人物仍来自总平台提交 d413d108704af47cf531ee8c25d93f682c3176e3 的完整 P01；25417 顶点/50624 三角面的公共拓扑、266098 顶点的原生渲染表面、骨架、皮肤、面部和眉毛由原平台负责。保持同一个 viewer.mesh，根区和体量分别通过各自的原生源面随头部移动，placement 只应用一次。

`GuideGroom@5` 导出人物档案、原生导向、根区归属、同组覆盖、完整源面面积分布、稳定生成种子、每束数量、体量生成约定和保型规则。消费方可按同一源区和方向场匹配后续头发资产。不是任意材质或图片自动套用的承诺。详见 CONTRACT.md。

物理规则保留固定根、段长和逐点活动初值。无应力参考、重力平衡、运行时求解和材料标定未完成。中心线静态避让和轻微转头绑定不证明有限厚度体量或密发丝的动态接触正确。

## 复现与验证

设置 `NATIVE_PERSON_HTML` 为已核对的原生人物 HTML、`ESBUILD` 为 esbuild 程序，运行 `python build.py`。源码提交由 `GITHUB_SHA` 写入；压缩分块固定后用 `NATIVE_PAYLOAD_REF` 指定其提交生成公开预览。每块和完整运行时均检查 SHA256。

```
node tests/bundle-core.mjs
node tests/bundle-browser.mjs <url> <candidate-or-public>
```

实际原生输入放在忽略的 `.build/native-input.json`。检查覆盖真实源区面积、边界归属、鼓包范围、刘海终点、目标数量和采样、真实浏览器显示、双侧及前后视角、原生转头、保存恢复和实际导出重绑。截图来自独立无界面 Chrome，不控制桌面鼠标。技术检查不能替代用户对发型的形体验收。最终不可变构建和证据在 DELIVERY.json。

交接文件默认无损压缩为 `GuideGroom_F09.json.gz`；`decodeGroom` 可读入压缩或普通 JSON。直接调用 `exportGroom` 仍返回普通对象，所有原生面和面积分布保持原精度。

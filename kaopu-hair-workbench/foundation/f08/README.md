# F08 · 从头皮根区到完整发束，再到发梢

本版纠正 F07 的构建顺序。F07 先生成独立的封闭外壳，再按高度和方位标记块面；这些块面不等于从毛囊长出的发束，刘海又独立于外壳显示，用户明确否定了这个结构。F07 的测试通过只代表当时的技术条件，不构成形体或分组正确的证明。

F08 的生成权威改为：**已通过的头皮根区 → 每组自己的连续导向 → 每条导向自己的发梢**。没有闭合外壳，没有按高度重分组的发尾面，也没有为遮住问题另贴帽子。每条半透明带完全由同一条导向生成，根点、中间路径、发梢属于同一组。

## 根区与发束的实际对应

`src/BundlePlan.mjs` 在既有 3067 个激活根点中作互斥归属，不新增、不移动发际线或毛根。11 组共选 192 个导向根点，保证小面积刘海也有独立的导向配额。组是一整束从根到梢的路径；额头、发顶、发尾是路径经过的位置，不是另切的发组。

`src/PortraitBob.mjs` 从精确原生三角面/重心坐标开始，采用各组的侧向走向、过渡点和独立发梢目标，沿当前完整人物表面避让。刘海起点位于已通过前额根区，连续越过发际线向额头下方生长。长发先从根部贴头铺开，再向下；末端有轻微内收。所有毫米数是 P01 上的造型初值，不是从照片标定的人体尺寸。

轮廓由逐束路径共同形成。长度有稳定的逐束错落，部分外层有少量外突，幅度可调；扰动在出根处为零，不移动根点。不是靠切一圈齐平的壳边产生轮廓。没有足够照片证据的细节保持简化。

## 半透明检查

默认显示按整束着色的导向与 18% 不透明度的发束带；不透明度可在 3%–50% 调整。可开关头皮采样点、发束带、透视背面导向，单独查看任一根区对应的整束。背面透视会穿透人物显示，属于检查工具。半透明带是宽度代理，非最终发卡、细发丝、发丝半径或物理求解结果。

## 接后续表现工作台

`GuideGroom@4` 导出完整人物参数档案、每条连续路径、原生绑定、11 组根区、3067 根区归属和同组 K=3 导向覆盖、独立发梢、逐点保型初值。UV 仅为每条带横向 U / 根到梢 V。没有旧版大型外壳、外壳 UV 或单独材质替换 API；表现资产应沿路径生成，不能通过换壳掩盖根部关系。

覆盖距离是原头皮图表中的样本距离，只在同一根区内取近邻；不是精确曲面测地距离，也未生成密集跟随发丝。最终表现接入后仍需检查轮廓、有限宽度穿面和发发接触。

保型/活动约定沿用 `RULES.md`，原生根固定，近根强保型，中段和梢部逐渐放开。无应力参考、重力平衡、运行时物理状态仍为 null；本版没有真实摆动求解或材质标定。

## 构建与验证

`NATIVE_PERSON_HTML` 指向同字节的人物平台 HTML，`ESBUILD` 指向 esbuild。运行 `python build.py`。源码提交由 `GITHUB_SHA` 写入；分块压缩数据记录为 payload 提交后，以 `NATIVE_PAYLOAD_REF` 再构建固定预览。线稿内联 SVG 与图例，可单独查看，也可在工作台弹窗中查看。

实际人物输入放在忽略的 `.build/native-input.json`，不以独立参考头回退。

```
node tests/bundle-core.mjs
node tests/bundle-browser.mjs <local-or-public-url> <candidate-or-public>
```

数值测试检验真实根区、连续连接、终点、静态穿面和覆盖边界；浏览器测试检验真实人物、半透明显示、逐束单看、原生转头、导出重绑和线稿。截图来自独立无界面 Chrome，不控制桌面鼠标。技术检查和截图均不等于用户已认可照片相似度或发型造型。

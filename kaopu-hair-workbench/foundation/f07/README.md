# F07 · 正面参考的大型、分组与保型规则

本版在人物总平台的完整「清俊 P01」上，依据用户提供的一张正面照片，建立肩部附近、偏中分、少量碎刘海、发尾内收的第一版大型。优先级是整体轮廓、分组连续性、从原生毛根到造型目标的路径，随后才是表现资产。照片未用于人物身份识别，也未改变人物面部或身体。

照片SHA256：`959b28381536f2b1fabb3683caaed71e8ccfbf8a994d2b7a344f1df0fecb2a91`，688×832，正面。原图不随公开页面或方案JSON分发。前视图可观察的分缝、轮廓与发尾作为造型依据；侧向深度、后脑、头顶与隐藏发际线明确保留为推定。所有毫米数是适配P01的工程造型值，非从照片恢复的真实尺寸。

## 实际结构

大型由本项目原创的平顺截面放样生成，包含封闭外表面、内表面、前缘和发尾连接面。九个发组为左/右发顶、左/右侧主发体、后脑、碎刘海，以及左/右/后的内收发尾层。整体和分组视图共用几何；切换着色、单独检查发组不会重新生成人物。

分组不是九块互不相干的外壳。相邻区域共享同一连续放样的边界与UV；发尾层继承其侧发体或后脑父组。后脑采用平顺椭圆截面连接两侧，保留统一发尾层，不凭单张正面照片发明背面的盘发、旋涡细节或额外卷束。

用户可调整整体分缝、长度、蓬松、内收，并分别调整左右宽度、后脑深度和碎刘海长度。左右、后脑参数在各自方向渐变到零，避免拼接处突然折断。肩颈附近使用同一P01原生三角面的静态支撑高度裁整发尾，保持放样行的顺序；没有改变肩部表面，也不把此裁整称为动态碰撞求解。

192条导向从原有精确原生根点出发，使用大型截面约束其走向，沿实际人物表面避让。少量刘海单独终止在额头附近；其余导向在造型发尾或当前肩部支撑处终止。3067个激活根点均保留，覆盖关系同时遵守原分区与分缝左右归属。修改分缝会重算覆盖，运动期间不会重新找最近点或跨分缝串组。

## 固定与允许活动

规则和实现见 `RULES.md`、`src/StyleRules.mjs`。毛根固定在人物表面；约前12 mm高保型，随后约20 mm渐变；中段和发梢逐渐允许偏离，但保留发尾弯曲记忆和发束联系。运动权重为无量纲工程初值，不冒充测量的质量、阻尼、杨氏模量或XPBD柔顺度。

当前可以查看活动权重、调整允许活动程度，并将逐点权重、段长、碰撞约定和造型目标一起导出。当前没有播放物理摆动，`stressFreeRest / gravityEquilibrium / runtime`仍未求解；绑定随人物转头不是动力学证明。

## 后续表现资产接口

`GuideGroom@3`导出同一人物参数档案、原生毛根与导向、分缝内覆盖、分组大型网格、UV、头部原生锚点及逐点保型规则。大型UV采用U环向/V发顶到发尾；独立发束UV采用U横向/V毛根到发梢。二者不可混同。`body / fringe`是稳定材质槽。

`hairF07.attachAppearance({body,fringe})`接受消费方的Three.js材质对象，在当前形体上替换材质，不改变人物网格与UV。传入材质由调用方管理，重建造型后需重新应用。未来提供的发卡或发丝资产仍需按导向、坐标、UV和分组适配；这不是“任意图片直接套用”的承诺。详见 `CONTRACT.md`。

## 人物与版本边界

完整P01固定来自人物总平台提交 `d413d108704af47cf531ee8c25d93f682c3176e3`，原HTML SHA256 `69da0a547349639d6a1245c46ff46c6420c9bdf45cb4b84bfba7fa549743664e`。原平台继续负责骨架、五官、皮肤、眉毛和人物生成。共同网格25,417顶点/50,624三角面，根签名`b0f64ef`；渲染仍保留原平台266,098表面顶点。

本版增加的素模是毛发形体，不是第二个头。F06与更早检查点保持不变；F07采用独立文档键`kaopu.hair.F07.design`和参考图库。可迁移F06方案设置；不把旧绑定面编号当作新目标。任意换身份、体型极值、复杂表情、剧烈动作以及动态发发接触尚未认证。

## 研究与知识

本轮查阅Disney的分层体积工作流、Hair Meshes的整体外形控制，以及Pixar的分层造型导向和保型约束原则。只采用研究思想，所有放样、分组和字段由本项目原创实现；没有导入第三方发型、材质或头部资产，没有宣称复现其完整算法。逐项来源、采用范围和未采用内容见 `knowledge/README.md`。

## 复现与交付

先运行`python build.py`，设置`NATIVE_PERSON_HTML`为同字节人物平台HTML，`ESBUILD`为esbuild程序。记录源码后以`GITHUB_SHA`写入源码提交；生成并记录分块payload，再设置`NATIVE_PAYLOAD_REF`固定payload提交生成预览。每块及解压后完整HTML均核对SHA256。

实际人物临时输入在忽略的`.build/native-input.json`，数值测试不会回退独立参考头：

```text
node tests/shape-core.mjs
node tests/shape-browser.mjs <本机地址> candidate
node tests/shape-browser.mjs <固定公网地址> public
```

候选浏览器使用已核对的本机人物资产缓存；公网测试使用原始固定HTTPS资源，不拦截请求。截图来自独立无界面Chrome的真实WebGL，不控制桌面鼠标，不使用图像生成。最终检查、源码与构建提交以`DELIVERY.json`为准；数值检查不能替代用户对形体的美术验收。

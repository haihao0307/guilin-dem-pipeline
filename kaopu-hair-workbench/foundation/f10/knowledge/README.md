# F10 · 三维发束构建、错误与检查依据

## 用户最终方向

原始照片和用户给出的发束分析示例为造型依据。用户否定助手的线稿表达和手绘分区，明确要求直接构建三维；这些助手图稿已从公开源码和生成输入移出，私有 QA 仅保留失败历史。当前以六个主要层组和 11 个原生头皮源区逐束长成宽度、厚度和独立收尾。

## 本轮实际失败

1. F07：先造全局外壳再按高度/方位给面分组，缺少源区到完整发束的关系；刘海与外壳的视觉关系被用户否定。
2. F08：虽然根绑定与整条路径连续，线和窄带仍不能表达用户要求的完整发束体量。技术检查通过不等于造型正确。
3. F10 手绘区域：没有严格贴合真实发纹，用户要求停用。它不是三维区域或数量的来源。
4. 第一轮三维：在源区边界重新调用分类，左侧分缝边界可能被分成右侧，刘海边界可能被分成长发，导致突兀外鼓和跨面拉伸。改为显式传递不可变 bundleId，并由其决定侧向。新增各组边界归属、最大横向范围和刘海最低高度检查，实际前后和双侧再审。
5. 只检验穿面无法发现绕目标盘圈；保留所有导向到达各自终点高度的检查。
6. 版本名的文本替换曾误碰到包含 f08 的原生索引散列。原生索引校验拒绝了该版本；恢复原始标识，并用实际 native 输入重新核验。以后改版本仅针对标识字段，不替换散列子串。

## 观察与推定

正面可观察偏分、斜刘海和少量碎束、贴脸层与外层的覆盖、肩部附近的内收。隐藏根区、后脑厚度、后颈内层和真实发丝数量不能从单图确认。P01 上的长度、宽厚和密度均为工程造型初值。

## 函数归属与数据权威

NativeSurface：固定 P01 公共表面、根绑定和源区映射。BundlePlan：固定工程根点与整束身份、内外层归属和导向配额。PortraitBob：按明确身份的贴头梳理、下落和发梢目标；边界不可重新分类。BundleVolumes：在头皮上裁分源区，核对实际三维面积，从该源区沿同束场生长体量，按源区面积计算预算和稳定采样。ShapeView：半透明三维体量和显示用 0.8mm 源区盖面抬高，不修改绑定。GuideExchange：原生重建、source cells/数量/体量交接与一致性检查。NativeApp：同一个 P01 场景、轻微原生转头和一次 placement。StyleRules：未标定的工程保型权重。

## 不把原则当效果证明

此前参考的 Disney Hair Pipeline、Tonic、Hair Meshes 和 Holding the Shape in Hair Simulation 仅作为造型、导向、模拟和表现分离的原则来源。本轮主要依据用户直接纠正的规则和给定发型，没有导入第三方头、发型或材质，也未声称复现研究的完整方法。

证据在 evidence/bundle-core.json 和 candidate/public 浏览器报告、当前真实 WebGL 图中。面积守恒、正确归属、数量可生成、绑定随动和形体美术验收是不同条件，不能互相替代。

# 电影毛发：从视觉目标到可复用的光学与动力学

2026-10-14 / 第一轮研究。以下明确区分公开来源事实、现有源码事实和本项目待验证方案。

## 1. 先修正目标中的隐含前提

《头号玩家》《阿凡达》《霍比特人》是视觉参照，不是一个可直接调用的统一“电影级着色器”，也不是可以按片名排列的客观质量等级。需要逐镜头区分数字角色、实拍头发、假发、数字替身与合成；未核实的具体镜头制作方法标记 UNKNOWN，不从电影名推断所有头发都是程序生成。

ILM 的官方项目页说明了《头号玩家》的数字角色和制作规模，但没有给出可直接复用的发丝光学/物理参数。[S1] Weta 的 Wig 页面描述的是梳理编辑，不应把其“直接艺术控制”误读为动态物理算法。[S2] Manuka 与《霍比特人：五军之战》的关联能确认，但不能据此断言片中每个头发镜头都使用同一种求解器。[S3]

本项目的目标拆为：有设计感且可编辑的发束；随视角和光照正确变化的丝状反射；内部透射/吸收与束间遮挡；自然重量和惯性；可靠接触；移动镜头时的稳定性。不能只靠增加发丝数量、降低透明度或加一个白色高光来宣称达标。

## 3. 当前代码审查

事实来源：固定 F03 提交 6b00c22d64f495bd515d031a80c61cd9f38ef81a 的 README、BUILD_MANIFEST 和 src/GuideKernel.mjs。

F02.1 默认生长域与耳前修剪已获用户通过；F03 有 192 条静态导向，引用面索引、重心坐标和稳定根 ID。3067 个激活诊断根点不是最终完整生物毛囊数。F03 通过原生三角面检查静态中心线，但没有密发光学、时间积分、扭转、自碰撞或连续碰撞检测；最近面法线符号不能当作开放半身网格的全局内外判定。

F03 的曲线是造型构建路径，不是已经测得的无应力物理形态。直接把它作为材料静止形态再施重力，可能产生二次下垂；应做静力平衡校准，或明确标记可调的美术形态恢复项，而不是把强制拉回路径冒充自然物理。

新研究分支不移动旧根、不扩张生长域、不修改区域长度和发际线。后续需要密发时，应在批准域内建立独立版本化、稳定播种的渲染根库；每根仍有自己的表面绑定，不能靠把少数导向的根整体散开制造假密度。发型/照片重建窗口与本质感物理窗口分工不变。

## 4. 建议的数据与求解分层

输入只读：ApprovedScalpRef、RootBinding、GroomRestRecipe、人物最终姿势和碰撞表面。单丝材料、物理状态、绘制设置各自版本化，不把它们塞回人体骨骼比例。

RootBinding：topologyRevision、faceId、barycentric、rootId、scalpLock、restTangentFrame。
GroomRestRecipe：分缝/发旋/区域方向、独立长度、静止曲率、分束层级、稳定 seed、参考来源和不可见区域推断标记。
FiberOptics：轴向/周向粗糙度、鳞片倾角、折射率、光谱或 RGB 吸收表示及其单位、自然色素/染色模式、沿丝稳定变化。
FiberMechanics：真实直径、密度、伸长与弯扭参数、阻尼、根部方向柔顺度、干湿状态、接触和摩擦属性。
Runtime：positions、velocities、materialFrames、constraintMultipliers、contactState、simulationRevision。
RenderBudget：投影尺寸、可见贡献、轮廓权重、接触重要性、显存/时间预算、时间连续调度状态。

每子步：采样头部/身体姿势 -> 更新根附着与碰撞体 -> 外力/相对风速 -> 伸长/弯曲/扭转 -> 接触与摩擦 -> 最终状态。随后从导向重建可见细丝，并再检验细丝的接触；只让导向不穿模不够。光学读取最终曲线切向和材料标架，而不是旧路径或固定世界方向。

## 5. 发丝质感的实现判断

采用专用纤维散射，而非把头发当作黑色塑料管或金属细线。表面反射、透射与带吸收的内部路径要有独立贡献，高阶内部反射与不同发丝之间的多重散射不是一回事。[S4][S5]

黑发、棕发、浅色发、灰白发以及染色需要不同吸收/散射组合，不能只换 baseColor。轴向粗糙度控制高光沿发丝的形态；周向粗糙度影响绕丝方向的展开。微观鳞片首先进入光学统计参数，不在普通镜头里为每片鳞片建立几何。

宏观发束 -> 小束 -> 独立细丝 -> 少量游离发，需要相关而非重复的变化。每丝的颜色、粗细、波曲、长度沿稳定种子关联；逐帧随机或所有丝同相正弦都会破坏自然感。造型遵循用户参考，材质实验不擅自替换发型。

浓密发束要有真实遮挡和透光深度。深度阴影/透射近似与可见性求解需专门验证；普通透明混合、简单加粗线宽、固定头皮黑贴片都不能替代这件事。轮廓采用亚像素覆盖与时间稳定处理，真实物理直径和屏幕抗锯齿补偿宽度分开。帧间稳定、反走样和曝光不是最后补的装饰。

实时绘制方案需要根据实际 WebGPU 能力实验决定：细丝曲线生成、阴影透射表示、透明排序或 OIT、时间历史校验分别计时。不能把离线路径追踪的源代码原样搬进 Three.js 就承诺同等画面和帧率。参考级单束渲染用于发现实时近似误差，不替代最终公网交互验收。

## 6. 发丝物理的实现判断

参考细杆模型，把发丝视为细长弹性体，而不是每个顶点同样晃动的绳链。[S6] 圆截面线性弹性基线：A=pi*r^2，I=pi*r^4/4，弯曲刚度 EI，线密度 rho*A，轴向柔顺度 L/(E*A)。这是简化模型，不包含毛发截面不规则、黏弹性、损伤或全部湿度效应。直径翻倍会让该模型的 EI 变成 16 倍，质量变成 4 倍；因此只改可见粗细却完全不改相关物理，含义必须明确。

稀疏导向代表一束丝时，质量和截面刚度的等效聚合要单独定义；不能把整个束的外半径当作单根实心杆半径，否则会错误地极度增硬。卷曲和辫子必须包含材料标架/方向与扭转约束，中心线位置本身不能完整表达这些自由度。

求解候选为带伸长、弯曲、扭转约束的 XPBD/Cosserat 式路线，再与高精度弹性杆小样对照。R01 只写了一个距离约束投影，不是上述完整路线。柔顺度按 dt^2 进入求解，乘子在同一时间步内累积；仍必须测试子步、迭代、网格分段和碰撞的收敛，不能宣称“用了 XPBD 就绝对与帧率无关”。[S7]

根位置固定绑定，不代表根上方很长一段必须僵硬。出根方向与根部弯曲柔顺度分开。真实惯性应来自根部运动和外力；停止转头后应回弹并耗散，不能立即吸回路径。方向性空气阻力使用相对速度；R01 仅验证正定线性阻力的耗散性，不等于 Weta 的非线性多孔介质耦合。[S8]

碰撞优先处理耳廓、脸、颈、肩和衣领；长发需要完整身体/衣物输入，当前截断头胸模型不够。必须检查有半径的整段与扫掠，而非只检查顶点。自碰撞、束间体积与滑动摩擦分开；不能用统一排斥力把毛发撑成气球。干湿状态可影响质量、阻力、束集、材料和光学，但变化参数要有来源或实验标注。湿发/水下耦合列为后续，第一轮不承诺完整流体求解。

## 7. 连续按需计算，而不是整件高低模切换

沿用按需、无固定距离分档的思路：同一根库、同一发型、同一物理语义。调度依据投影宽度/长度、遮挡、轮廓、运动和接触重要性，不仅是离相机距离。连续权重可从 w=importance/(importance+budgetPressure) 起步；本轮只验证这个响应函数，不宣称已实现预算控制器。

物理节点、绘制数量和 GPU 工作组仍是离散的。连续视觉效果应靠稳定抽样、受控过渡与累计误差控制实现，不能承诺“无限连续精度、零成本”。接触中的节点不得为省预算突然消失；远处要保住覆盖、轮廓和整体光学，不简单减少根数造成透皮。动态导向稠密化、GPU 驻留、局部邻域碰撞和缓冲复用优先，当前不做动作缓存。

纯算例：100000 根 * 32 节点 * 位置与速度两份 vec4 float32 = 97.65625 MiB；若双缓冲这两份数据则翻倍。尚不含静止态、方向、约束、碰撞、阴影和绘制缓存。这不是实际实现显存统计。全量展开/逐帧 CPU 重建会迅速扩大成本，必须先做缓冲账本。

目标硬件、浏览器、分辨率和单场景人物数量尚未确定。60fps 对应总帧时间约 16.67ms；头发不能独占人物、衣物和场景预算。本轮没有 GPU 或整头动态性能数据，不承诺手机、普通集显和离线大片效果能同时成立。

## 8. 可执行的下一阶段与失败门槛

R02 / 单束光学台：在可控统一灯光下比较同一几何的深色、棕色、浅色和灰白光学小样；对照正光、侧光、逆光及运动灯。检查高光是否随切向移动、暗部是否有层次、束内是否透光、轮廓是否闪。与人物光照接口对接时冻结曝光/色彩管理；可复用 EB1，但 R01 尚未接入，不能标已完成。A/B 使用同一相机和灯光，不以换灯掩盖材质缺陷。

R03 / 单束物理台：直、波曲、卷曲测试夹具；根平移/旋转/急停、重力、风、松手、贴耳/肩接触；记录长度误差、根漂移、接触深度、能量耗散和帧间结果。测试时长和子步/分段变化均记录。初始建议门槛为根漂移 <=0.1mm、正常拉伸误差 p99 <=0.5%，只是工程候选，需尺寸和镜头校准；不得把单次通过推广为所有参数空间通过。

R04 / 回装批准头皮：保留 F02.1 边界，读取同一人物和用户发型参考；验证发根覆盖、分缝、耳前、鬓角、后颈和完整背面。先呈现短发/中短发的真实密度与运动，再扩展长发；不重新开一套互相冲突的人体系统。照片不可见部分保留推断标记。

R05 / 复杂交互：衣领/帽子/长发、辫子、湿发及水下环境依赖完整碰撞输入和已通过单束求解，不在 R01 混入。

每轮用固定公开 HTTPS 的真实三维结果验收，记录版本、硬件、分辨率、CPU/GPU 时间、内存及手机验证范围。必须检查静帧之外的连续运动，不能只交漂亮截图。工程测试全绿不等于美术通过，更不等于达到某部电影。

## 9. 授权与结果诚实性

论文可阅读不表示电影资产、内部工具或数据可任意再发布。TressFX 和 Digital Salon 的代码许可与演示数据/头模/图片权利分别核对；本轮仅链接研究来源、实现少量独立数值探针，没有导入第三方实现或资产。后续移植必须记录版本、许可证、保留义务和来源，不因重写/改名声称原资产变成自有。

R01 的光能测试只覆盖标量路径预算；不含角分布归一化、BSDF 采样或束间多重散射。XPBD 测试只覆盖单个距离约束；不含时间积分、弯扭或接触。线性阻力测试只证明该简化函数在相对速度参考系耗散。根适配测试使用合成字段夹具，不是完整人物动画回归。四个冻结模块的哈希与 Git 差异检查只证明本分支未改批准域，不证明新头发自然。

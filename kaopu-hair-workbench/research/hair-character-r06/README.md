# R06 · 头发接触、动作与连续距离细节

本版继承 R05 的程序化发型与人物总平台，保留白背景、自然黑/栗棕和两款完整发型：偏分中长发、中分披肩长发。新增走、跑、跳，移动身体接触、外部碰撞物、蓬松压力测试，以及多人连续距离显示。所有新增头发由源码生成，没有短绒层、发片替代模型或导入发型资产。

## 打开与检查

本机入口 `preview-medium.html` / `preview-long.html`，公开压缩入口 `public-medium.html` / `public-long.html`。公开固定提交与链接见 `PUBLICATION.json`，实际公开浏览器检查见 `PUBLIC_VERIFICATION.json`。首次载入仍需要原人物平台资源与程序化梳理时间。

- 选择发型、发色、正侧背面和分缝；鼠标拖动旋转，滚轮缩放。
- “行走 / 跑步 / 跳跃”复用项目已有的捕捉动作与原生骨骼权重；“看全身 / 头肩近看”分别检查整体动作和头发。
- “距离渐进细节”默认启用。靠近时连续增加稳定编号的发丝、曲线采样和物理细节；远离时减少这些工作。使用同一套根、权重、曲线和材质，没有切换另一套简化发型。
- “同屏头部”可选择 12 / 24 / 48 个头部载体；“靠近人物”会移动到人群中的一个头部，最近对象恢复精细接触；“远处总览”返回压力场景。其他头部是来自原人物的基础几何载体，用于隔离头发开销，不代表 48 个独立完整人物与网络系统。
- “蓬松压力测试”提高长发丝的蓬松支撑和发尾展开，不生成短绒毛。“推球 / 挡板”提供匹配可见形状的椭球接触测试；“移开外物”恢复。

## 性能方案

同一发型的毛囊、四导向权重、几何属性与静止曲线缓存被所有头部共享。每个远处对象只保留四个独立低维运动坐标及速度。根据投影大小连续调整发丝前缀，以覆盖率补偿保持发量，并平滑显隐新增发丝。曲线采样也按屏幕大小调整，不截短头发。

远处通过共享 RGBA16F 缓存读取原始加权曲线，避免每个顶点重复求四条导向；当前一套发型的共享曲线缓存约 12.8 MB，不按人数重复。接近时平滑混合回当前导向、精确原生发根和逐丝细节。测试台最多同时启用 **1 个精细接触求解器**，分配给最近头部。其他对象有独立空间风响应；移动或受外物接触的远处重点对象使用 GPU 接触投影。静止后停止连续绘制，停风先衰减再休眠。

当前原型不能解释为任意人数、任意显卡都零消耗，也不能解释为所有近处人物均有独立完整物理。若接入多人项目，需要给各角色提交独立的头骨姿态、速度、加速度及外部碰撞体，再按设备预算管理多个精细求解器。实测方法、当前硬件结果与边界见 `docs/performance.md`。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/Groom.mjs` | 全头皮取根、连续侧后梳理场、自然分缝、蓬松度、四导向权重 |
| `src/NativeHeadBinding.mjs` | 原生三角形重心绑定、当前 morph/骨骼发根、物理根局部更新 |
| `src/GuideDynamics.mjs` | 120 Hz 重力、根惯性、弹性弯曲、段长与接触约束 |
| `src/CollisionProxies.mjs` | 原生头部表面、8 个移动身体包络、2 个外部椭球、相对速度/摩擦/扫掠 |
| `src/detail-dynamics.mjs` | 可见发丝的两个独立横向细节模态 |
| `src/NativeMotion.mjs` | 既有走跑跳捕捉数据、原生权重、头部惯性、眉毛附着 |
| `src/NativePoseCache.mjs` | 原生位置和完整法线/形变矩阵每可见姿态只计算一次 |
| `src/DistanceHair.mjs` | 连续距离预算、低维运动、人群压力测试、最近对象细节分配 |
| `src/RestFiberCache.mjs` | 原加权静止曲线共享缓存 |
| `src/HairRenderer.mjs` | 发丝、覆盖率补偿、介电体光泽和显示接触 |
| `src/HairPassCache.mjs` | 所有可见头发合计一次透过率缓存，复用于原平台三个阶段 |

外部碰撞适配：`HAIR_CHARACTER.setCollider(slot, matrixWorld16, radii3)` 接受 0 / 1 两个椭球槽位，自动吸收矩阵缩放。矩阵为实际场景世界坐标；调用者随外物运动更新。`setProp('off')` 清除外物。此处头发响应指定碰撞物运动，不向外物或人体反向施加完整刚体冲量。

## 复现与证据

`node tools/build.cjs` 构建 HTML 与摘要；`node tools/serve.cjs` 在 8770 端口启动本机缓存服务器。工具中的构建器、浏览器和原人物缓存路径是当前机器配置，交付网页不依赖这些本机路径。

`python -X utf8 tools/run-final-checks.py` 检查数值内核、完整发型/人物绑定、动作接触和多人性能。`node tools/test-cache-quality.cjs` 检查缓存曲线误差、距离下的同一几何、共享透过率绘制和远处停风衰减。`tools/capture-motion.cjs` / `tools/make-motion-gif.py` 保存真实 WebGL 动作帧与预览。报告中的 `sourceHashes` 对应 `BUILD_MANIFEST.json`，早期诊断文件不作为最终交付依据。

## 来源与实现边界

原人物固定源 `guilin-dem-pipeline@ab499da18b1da1e256cd66e35ec1212183c58028`，头发基线 `6c116f8122d934e1d7b9e8e2abee7daba3830688`。冻结的 `references/character-platform-frozen.html` 保留原快照字节；当前目录收到的另一套肤质更新保留在 `references/character-platform.html`，不混入本轮头发性能对比。构建时只增加一个 GPU 存储兼容修正：原人物在毛孔纹理尾部附加原有 17 行表数据前释放旧显存，避免把 512×111 上传进 512×94 的存储；不改原像素、皮肤着色器或几何。记录见 `HOST_COMPATIBILITY.json`。

动作复用本项目既有重定向器与原生权重，没有截掉小权重。原始数据署名 Carnegie Mellon University Graphics Lab Motion Capture Database，来源、帧率、摘要保留在 `references/motion/*-SOURCE.json` 与 `references/MOTION-SOURCES.md`。

身体接触仍是按骨骼移动的包络近似，不是完整身体网格 SDF。没有逐丝自碰撞、湿发粘附、全体积空气或双向刚体耦合。发量支撑和有效束刚度是作者配置，材质没有真人测量标定。头发接收人物阴影；没有深度透明投影。数值通过与真实截图不等于用户美术验收。

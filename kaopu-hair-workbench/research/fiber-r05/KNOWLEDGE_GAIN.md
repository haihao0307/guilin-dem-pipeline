# R05 / 从毛梢摆动到分段弯曲：本轮学到并验证的内容

用户明确否决 R04 的效果。本轮不能把“接入完成”和“画面测试通过”继续解释为自然感或美术验收通过。R04 保留供对照，R05 仍为单束候选。

## 1. 可借用运动架构，但不能忽略形变自由度

自有毛领 FUR R02 的少量导向、固定步长、阻尼和 GPU 驱动显示毛发值得复用。原 R04 对每个导向只有一个毛梢偏移，再乘 t²：整根只能采取一类位移轮廓。长发的中段和末段不能分别弯曲，单纯增加风力不会补出缺失自由度。

R05 在同一 85 个空间导向上采用三个独立弯曲模式。各模式使用根部位移和连续数学导数为零的基函数，分别保存广义位移与速度。风与鼠标外力投影到模式上，释放后继续进行惯性和阻尼积分；不是逐帧播放固定曲线。GPU 将模式场插值到同一根库的 10000 根显示发丝。

前三个悬臂根值为 beta=1.8751040687、4.6940911330、7.8547574382，刚度比例采用 beta 的四次方。数值积分在每个 1/120 秒步内对恒定外力使用阻尼振子解析更新。交互反馈、力变化和位移限幅仍使完整系统存在离散化与非线性误差，不能称作绝对无条件精确。

这是围绕既有静止曲线的降阶弯曲近似，不是测得真人物性，也不是完整弹性杆。中心线未强制不可伸长，没有扭转材料标架、自碰撞和人体/衣物接触。连续基函数根部导数为零，不表示有限折线的第一段方向没有离散误差。大幅拨动和复杂长发仍需要下一阶段约束。

## 2. 抓取应该表达位置，而不是把鼠标速度永久当作力

R04 鼠标移动形成外力，保持按下时可能继续向同一方向推。R05 在导向投影附近选取弧长位置，建立面向相机的交互平面，将鼠标当前位置变成局部目标。这样中段抓取和末段抓取产生不同的形变，松手后才释放。拾取仍是导向近似，不是准确逐根发丝或真实手指接触。目标范围与总位移有限，不能把限幅当作碰撞处理。

## 3. 性能先清除重复工作，而不是先牺牲质感

恢复并固定每根 81 个光学采样节点，移除默认 21 点稀疏插值。10,000 根、80 段几何、物理丝径、原色素、粗糙度、三灯与 R/TT/TRT 表达保留。视角与材质相关的共有计算移出三灯循环，避免重复求值。

原阴影每灯的两个半图分别绘制同一几何，R05 改成双输出再按像素打包，深度采样值不减少。原头发的透明双面材质默认还会分别提交前后面，而自有毛领已启用 forceSinglePass。对当前单层细丝窄带的加法累计通道，取消这项重复提交不需要把发丝改成单面、不透明或更粗。原分离通道保留作同机对照；是否保持画面由回归验证决定，不凭设置名称推断。

八层合成仍是八层。八输出 MRT 的单次绘制是能力分支；本轮实际验证设备只支持四输出，运行的是两组四层。不得把存在于源码中的八输出路径写成已经实测通过。

## 4. 可重复的证据，而不是错误的性能数字

最终候选的同机交替测试使用相同 81 节点光学、发束、分辨率和确定的运动状态。原分离通道两帧 17424.3 / 17478.6 ms，合并与单次双面通道 13123.3 / 13068.9 ms，平均完整帧耗下降约 24.96%。这是 SwiftShader 软件验证的 GPU 完成栅栏计时，不是用户显卡 FPS。秒级绝对帧耗仍不能称为实时达标。

实际提交的细丝三角形遍历从每完整帧约 2720 万降至 960 万；这减少的是多通道对同一几何的重复提交，发丝数量与真实几何没有减少。阴影打包等全屏三角形需要单独记账，嵌套 profiler 项不得相加两遍。

阶段 wallMS 记录即使调用了 gl.finish，在该浏览器上仍主要反映命令提交，不能标为可靠 GPU 阶段执行时间。完整帧必须等待 fence 完成。后续需要可靠的 GPU timer query 或其他独立通道测量，不能用阶段零点几毫秒解释整帧秒级瓶颈。

原图回归使用固定 R04 原精度 PNG；本轮静态前景 sRGB MAE 8.324059810450747e-7，99 分位差异为零，最大差一个 8-bit 色阶。该数字支持受测状态下原外观基本保留，不证明所有参数、光线、设备、运动都已经美术通过。原发束的造型和宽带状高光观感也不会因为保留原图而自动改善。

## 5. 复用接口与后续门槛

运动核、着色实现、交互桥接和原参数配方分开保存。未来读取同一人物最终姿势与批准头皮，不用运动写回比例、骨架或毛根生长域。旧版本和教师毛领源码均只读。

下一步首先根据实际连续运动评审分清：发束造型、高光层次、运动自由度还是帧耗仍不合格。接触与不可伸长性尚未完成时，不向整头、帽子和衣领自动推广；不把局部单束数值测试推广成整个角色的电影级质量认证。

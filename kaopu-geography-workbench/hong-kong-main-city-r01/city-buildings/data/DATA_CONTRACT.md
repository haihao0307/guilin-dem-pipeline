# Hong Kong corridor KAOPU measured-recipe adapter

This is a research adapter, not a frozen global KAOPU format. The source glTF and BIN files remain byte-for-byte preserved in the separate source archive. These payloads contain measured plane/boundary recipes, reconstructed by a shared generator. They do not rename raw meshes as a new format.

## Integration

- `manifest.json`: all 113 downloaded source tiles and all 23,413 usable source models. One additional official corrupt source model is explicitly excluded, with its ID/hash and reason. Pending extraction is not ready coverage.
- Each tile has source tile bounds and actual model-union bounds in EPSG:2326 East/North/metres above Hong Kong Principal Datum (mPD), exact model counts, source triangle budget, and `chunks` for verified available recipes.
- Tile `index.url`: gzip JSON with every model ID, category, source hashes, geographic anchor, transformed source accessor bounds, provenance, dates, and unchanged original dimensions.
- Chunk `url`: gzip JSON (`kaopu.hk.tile-score-bundle/0.1`) with `models:[score,...]`. The URL is relative to the asset root. Gzip is the transport encoding, not a special geometry representation. Decompress explicitly when the server does not send Content-Encoding.
- `runtime/reconstruct.mjs` exports `reconstructBuffers(score, THREE)` and returns Float32 `positions`, Float32 `normals`, null indices, material groups, and patches. Three is used only for CPU Earcut triangulation; no additional renderer is required.
- Reconstruction output is local X east, Y up, Z south. Position the object at [E-834000, H, 827000-N] using `georeference.originEastingNorthingHeight`. Keep original sizes; all edit scales remain 1.
- **Vertical alignment is a separate explicit transform:** source models are mPD while the current map has an EGM2008-model datum chain. Do not assume they match, invent a constant, or snap model bases to terrain. Use the verified external datum controls and mark any unsupported object `datum_pending`.
- No DEM, terrain photo, windows, or doors are generated by this exporter. The uniform material is intentional. Only the separately researched 33 La Salle textured sample has texture evidence; these complete-corridor payloads are non-textured.

## Progressive rendering and correctness

Load visible/near chunks under an explicit memory/triangle budget, unload distant buffers, and show available/loading/failed/pending counts. The whole source contains 16,458,270 triangles; 17 railway models include a few extremely large objects. Do not allocate all decoded data at startup. A pending or exceptional object must never be counted as loaded.

The original 0.1 generator is retained. Any explicit residual extension will use a separately versioned wrapper and separate count; raw exception triangles are not described as successfully learned parametric rules. Original defects, extraction exceptions, and runtime loading failures are different states.

Each ready chunk was reconstructed using the shared generator and checked for every patch's area, oriented face normal and bounds against its source patch, finite coordinates, and deterministic repeated buffers. The validation receipt states this method; it is not a strict global Hausdorff proof. Source survey accuracy is not upgraded by numerical agreement.

## Time is not one interchangeable date

Each object separates source tile revision, geometry acquisition, occupation permits, construction, current exterior-form date, photo capture, and authored game time. Unknown remains unknown. A 2026 dataset revision is not a 2026 building. An occupation-permit date is not proof of current geometry at that date. Missing links in the incomplete age join remain `relationship_query_pending`, not confirmed undated. Positive existing permit evidence is reused; no new historical appearance is invented. The 1997-01-01 cutoff has not deleted or altered any original geometry.

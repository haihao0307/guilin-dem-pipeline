# R06 · 原创函数场建筑试验（候选版）

入口：[r06.html](../r06.html)。这是独立于旧版网格链路的直接函数求值实现，不是把 Three.js 的 Mesh 改名为“函数场”，也不是完整 BIM、建筑实测复原或安全认证模型。R01–R05 与相邻三个原案例应保留不动。

**当前状态：已实现三案源轮廓约束设计及同场候选，GPU 尚未验收，未生产发布。** 原始外形、早期独立关系图和新的源绑定设计是分开的表示，均不能称为真实室内复原。候选 7 的远端 265 项 CPU 测试通过，但浏览器运行在低层案例失去 WebGL context；没有已接受的新图。候选 8 正准备三阶段求交 / 着色与精确描述数据纹理，测试、GPU 结果及性能改善尚未确立。

## 1. 外形、关系与设计，不能混成同一个事实

### A. 三个实测外表面的无符号场

[cases.mjs](./cases.mjs) 读取既有 measured-plane-boundary 配方。每个 wallStrip、wallProfile、roofPlane、undersidePlane 都转为自己的解析平面、正交局部坐标和有限多边形域，保留原面 ID、所有边界及洞。没有三角化、对象顶点缓冲、对象索引缓冲、体素化或 marching cubes。

点查询的定义是：点先投影到面；投影在外环内且不在洞内时，用到平面的垂距；否则用垂距与到最近有限边界线段距离的平方和开方。所有面的最小值就是有限源表面并集的精确无符号距离（浮点误差另计）。BVH 只用包围盒距离下界排除不可能更近的面，不改变源形状。完整遍历版本保留为比较基线。

直接射线路径对同一组平面作 ray/plane 求交，再以外环/洞谓词检验有限域；BVH 用射线与包围盒的相交区间剪枝。它是解析平面与边界函数的求交，不是向 GPU 提交多边形来光栅化。有限边界坐标是函数定义数据，不是渲染顶点；没有因此声称“无坐标”“无限压缩”或“没有任何离散数据”。

此场的 inside 始终未定义。零厚度外皮不自动成为闭合实体，塔楼底面也不补假封口。不能用它断言室内占用、墙厚、房间、楼板、基础、可行走区域或碰撞安全。它保留的是既有数据派生形状，并非重新现场测量。

### B. KCC 宿主内的两层有符号设计场

[field.mjs](./field.mjs) 是另外一套原创、有符号的设计函数：沿已知凹轮廓挤出的两块楼板、两跑阶梯轮廓、平台、连续扶手管、墙体减去门洞。min / max 进行并集与差集；物体 ID、材质角色和米制局部坐标随查询一起返回。

- 楼梯不是一摞互相遮盖的箱子：闭合台阶剖面包含踏面、立面和连续斜底，再沿梯宽挤出。默认每跑 10 级高差、9 个独立踏面，最后一级由相连平台或楼板闭合。
- 扶手由精确直线和有限圆弧组成一条母线，距离到母线减管半径得到管场。rounded 模式在坡段、平台和转角作解析圆弧切线衔接（G1，不冒充曲率 G2 连续）；angular 模式故意保留 C0 硬折点，不是降低网格细分。
- 墙开洞是同一有符号场内的布尔差，不是贴一张“门”图片。这里只有通道开口，没有据此宣称已做门扇、五金或防火门。
- 此场有有符号占用定义，但 min / max 组合后并非任意内部位置都给出精确欧氏距离。源码承诺是 1-Lipschitz 保守距离界；场值命中容差不等于所有 CSG 角点都具备同等欧氏精度证明。

[host.mjs](./host.mjs) 保留源身份、世界坐标、刚性变换和关系图，不依赖渲染器生成几何。楼层、楼板、核心筒分组、跨层楼梯、墙和洞口有独立拥有关系。这里的“设计核心筒”与公开平面里的真实核心筒关系记录不是同一对象，不能因为名称相似就合并。

默认层间距 3.2 m、梯宽 1.2 m、平台深 1.2 m、踏深 0.28 m、板厚 0.2 m、扶手高 0.9 m、管半径 0.035 m、转弯半径 0.22 m、门洞 0.9 × 2.1 m，均为可改创作参数，不是 KCC 实测尺寸或规范合规承诺。两层使用 floor-001 / floor-002 设计 ID，不对应公开图里的某两层。宿主中原有 2 × 2 m 服务预留体同样是创作预留，不是发现了一口真实电梯井。

### C. 保留的早期独立关系装配

[assemblies.mjs](./assemblies.mjs) 中保留的 deriveEvidenceAssembly 不只是文字关系图：楼板、墙、楼梯和入口都由有限多边形挤出场组成，渲染器实际求交。多边形的空域定义真实门洞，房间内部为空，不是实心盒子或贴上的门图。每个实体函数都绑定语义节点、物体 ID、材质角色和关系装配局部坐标系。原始外形视图与关系装配视图分别选择、分别显示；关系装配没有塞入或缩放原外壳。

- 喇沙利道 33 號：两块有厚度的设计楼板、上层楼梯洞、一组连接两层的设计双跑梯；31–33 共用街门与 No.33 住宅入口各有自己的宿主、开口和示意连接。两层标签有来源，但层高、梯位、门位、门宽和接近路径均为创作。共用场地不被错误归为 No.33 独有；未生成电梯不意味着已证实实楼没有电梯。
- KCC：一张代表层关系装配，A–F 六个具有空室内和实际门洞的单位，通过公共通路连接共享梯厅；三部电梯接口归属同一核心筒，而非某一楼层独有。另以相向梯段表达公开平面关系，未声称复原真实剪刀梯互锁、防火分隔或停靠表。六户和三梯符号来自已注明范围的公开图，但矩形房间、核心筒尺寸、门位、通道宽度与相对坐标都是设计，裙房没有被并入塔楼生成。
- 仓库：开放仓储场域、分开的宽车辆入口和窄人员入口、各自接近路径与装卸带，再连接一个货运功能接口。这个接口是功能占位，不表示真实货梯只有一部，也没有把经纪所称九部货梯变成已核实布局。没有住宅分户或推定柱网；入口、装卸区和接口尺寸与位置都是设计。

所有未知尺寸都带 authored / diagram 证据标记，actualPosition / actualElevation 不因生成了设计坐标而变成已知实测值。界面允许编辑相应板厚、墙厚、层高、入口宽、通道宽及接口宽，验证后重建函数；超出有界试验域的请求拒绝，不改变已存在的源外形。

#### 有对齐链，不等于已完成配准

关系图具有 `diagram-local-frame → measured_source_local_east_up_south → EPSG:2326 / mPD` 变换链。alignmentTransform 仅接受米制平移和绕竖轴旋转，拒绝缩放/剪切；`assemblyLocalToSource`、`sourceToAssemblyLocal`、`assemblyLocalToSurvey` 和反向查询把同一个设计点映射到源/测量坐标，并保留材质局部米制坐标。

这里描述的是旧独立关系图的刚性对齐接口：其 registrationStatus 为 unverified_editable_design，placementMode 为 separate_relation_diagram，sourceTransformApplied 为 false。它仍可单独查看，新源绑定层见下节。默认零平移/零旋转也不是位置测量证据。尚未用校准图纸、现场尺寸或可靠控制点核实实楼配准，不能把查询坐标链当作实际门位、核心筒或楼板落位的证明。

模块还可在选定高度对原始有限源面作水平截交，保留来源面 ID；开放、分支、退化或与水平源面重合的截线会拒绝，不以外包矩形补成楼板。选定截面不证明实际楼层，当前也不替代独立关系装配的设计轮廓。

## 2. 求交与显示路径

[renderer.mjs](./renderer.mjs) 使用 WebGL2 片元程序直接查询函数。每个 pass 的一个全屏三角形只负责触发屏幕像素，是光栅化基础设施，不是建筑三角面；多 pass 不能被表述成整帧只有一次三角形绘制。空 VAO 不承载模型顶点；浮点纹理可以承载逐像素查询结果或解析描述数据，不是体素模型。没有 WebGL2 时明确报错，不偷偷切回对象网格。

已有函数与候选 8 的管线边界：

1. 实测外壳：源平面 / 有限域 / BVH 直接求交。
2. 三案关系装配：逐个有限挤出体的端面 / 边界平面候选，检验该面的有限域，再排除埋在并集内部的接触面；不是把另一个临近面的距离误当作此面的命中。
3. 两层设计内核：保守 primary 先求交；未决 / 掠射 / 非边界候选进入解析 rescue，检验有限结构域、占用变化及扶手。内部接触面不应变成可见外面，平面方程列表不是面片三角化。
4. rescue 中的扶手只在其包围域内保守步进，以结构命中限制范围；不加可能跨过薄部件的正最小步长。预算耗尽保持 unresolved，不得算作普通 miss。primary 与 rescue 的预算及计数按实际版本报告。
5. 命中后的物体身份、法线与局部米制坐标交给材质函数。微表面高度只改变着色法线，不秘密修改轮廓。

候选 8 正将 primary、rescue、shade 拆成三个 pass，用不同浮点渲染目标传递每像素状态，避免采样和写入同一目标；是否正确及是否减少耗时尚待测试。另将原始面、正交基、有限边界和 BVH 打包为二维浮点描述纹理，由 texelFetch 读取同一套解析数据。它不是按空间采样的 SDF / 占用栅格，不是体素，也不含对象绘制网格。“精确描述”指保留函数及边界语义，不声称 Float32 无损保存原 Float64 数值；BVH 外包界需保守向外舍入并验证 CPU / GPU 精度。

当前可见表面法线取解析命中：实测面使用源平面法线，关系装配使用胜出面的解析法线，两层结构使用边界平面法线，扶手使用管面点与解析最近母线点的方向。离面查询的法线探针仍可能使用有限差分，不能把“显示采用解析法线”扩成所有查询均无需差分。

探针程序现按查询种类延迟编译，只有请求材质探针时才加入完整材质闭包；编译与链接耗时单独记录。可选 AO 默认关闭，开启后才增加局部遮蔽查询。这些是代码路径变化，不是已经测得的提速结论。

混合路径仍需按最终渲染器版本完成验证。诊断里的“步数”分别可能是实测外壳 BVH 节点访问、关系装配有限面测试、扶手场评估或旧版全场步进次数，不能混成同一性能指标。8-bit 诊断步数超过 255 会饱和，不能由读回颜色直接声称完整测试量。所有循环上限、容差及诊断编码以本次实际运行代码和结果为准，不在本文伪装成已经测得的性能。

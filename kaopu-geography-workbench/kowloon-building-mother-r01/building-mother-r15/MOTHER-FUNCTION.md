# 建筑母函数：当前真实执行关系（R15）

实际入口：growBuilding(seed, parameters) → { model, recipe, validation }
文件：building-mother.mjs。不是另一个不会运行的概念函数。

seed 包含 caseId、source（原建筑有限源面与尺度）、model（原有生成器的保留种子）、openingEvidence（观察证据）。parameters 是明确的检查假设；它不能覆盖实楼层数、层高或整体高度。

## 真实调用次序

1. 原 source / 官方外形约束 → 原 controller.derive → 原立面接口和电梯可见部件。这一步仍在母函数之前，是保留的原有代码，不冒称已全部重写。
2. growBuilding：±0坐标基准 → 基础/地下状态 → 横向柱梁及空间规则 → 原楼层表纵向展开 → 走廊/楼梯/核心拓扑 → 宿主墙洞及源面构件 → 保留屋顶。
3. growBuilding 返回完整本次 model。低楼的整层、柱梁、内墙洞和观察窗确实由它生成；龍總窗位配准和仓库可见构件现在也在这个入口内部发射，不再是主页面偷偷追加的旁路。
4. prepareBuildingLifts / attachBuildingLifts 消费生成结果，驱动既有电梯状态；composeBuildingScene 只平移三个实例，不修改尺度。渲染和构件分色只是结果的显示消费者。

## 三栋覆盖边界

- 喇沙利道33号：两层和源屋顶不变。deriveFloorMother 的柱点、梁跨、房间/走廊、共享墙、洞口，经 integrateCompleteFloorSystem 展开到楼层。墙厚同时传到墙体、洞口和框深。室内布局与支承是设计验证，不是取得了实楼全部图纸。
- 龍總：原壳、原层序、原核心/电梯保持。5–17和18–26层分两套已观察平面，6层平台例外。主塔楼176个部分窗位置候选经两套轮廓拟合接真实源面；R0/R180尚未独立校准。此处不是全楼窗数，窗高/窗台和窗型仍是检查参数。整个首层到住宅的真实通达未完成核准。
- 仓库：原壳、楼层与货运设计保留，实际全楼层数/停层不冒认。母函数 envelope 读取p012观察记录，生成3组分格、12个被照片截断的机组前部。没有把格栅当玻璃，也没有新增穿墙洞。

## 最少变量与真实消费点

- source 外轮廓/高度：只读证据，所有源面与宿主位置共同约束；不接受随意变成三层。
- model.levels：保留本栋层表；低楼整层发射、柱墙竖向端点、楼板及楼梯连接消费它。真实室内标高状态独立于官方外形高度。
- dimensions.wallThickness：低楼0.12/0.14/0.18米检查选项；传入deriveFloorMother、墙域、洞口与框深。
- dimensions.windowGlassThickness：低楼0.006/0.009米检查选项；仅玻璃厚度，不改洞宽。
- frameGrid.points / spans：共享柱点和梁跨；支承图和低楼结构发射共同消费。现不开放修改实楼外轮廓。
- facade.candidateId：龍總R0/R180，改变所有观察窗的宿主面/局部位置，不改变楼高。
- facade.detail / mirror：仓库明细开关与水平映射候选；按同一p012局部坐标生成，关后回退灰片/重新生成无残留。
- facade.projectionDepth：仓库格栅检查深度0.12米；机组前部0.28米明确为设计假设。
- time：目前只在电梯控制器的运行状态里，不是母函数已有“自动历史老化”。不可声称已经实现建筑年代演化。

## 关系而不是后贴编号

楼 → 层 / 核心 → 墙；墙 → 洞口 → 框/玻璃或未来门系统接口。
构件有ownedBy、voids/fills；低楼支承生成图有dependsOn/supports；通达是入口→走廊→房间及楼梯跨层，不是每个房间直通电梯。
基础与地下室分别未知，不把未观察到基础当没有基础。没有真实基础证据时不会制造实测尺寸。支承关系验证不等于结构承载、消防或无障碍合规认证。

## 检查与回退

母函数测试实际改变墙厚/柱点并检查输出几何变化、回退同种子输出完全相同；拒绝改真实层数，保留全部源面。仓库测试两种映射、构件宿主、边界、裁片下缘、无玻璃/穿墙洞。构件分色只换显示色，不新增几何。旧R14保留。

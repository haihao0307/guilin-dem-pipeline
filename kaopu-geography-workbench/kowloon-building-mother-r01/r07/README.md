# R07 bounded hosted function components — work in progress

This source checkpoint is not a tested or published preview. R03/R04/R05/R06 are frozen. R06's known one-pixel underside grazing failure and failed full-acceptance report remain unchanged.

## Bounded continuation of the same three cases

- No.33 La Salle Road: proposed operable residential window on actual vertical measured patch p120/object1120. Its exact window placement, wall thickness, frame depth and hardware are design assumptions, not photo-registered measurements.
- K.C.C. Building: a hosted door on the existing representative-floor unit-A partition/object2003, preserving the six-unit/three-lift-interface relationship. Not all 24 tower storeys or a verified actual stair/lobby reconstruction.
- China Travel Hip Kee Godown No.2: vehicle/person frames on the existing separately inferred official-footprint podium perimeter/object2002 and freight interface/object2003. The elevated original upper source is not converted into a street-level entrance. Unknown vehicle shutter/lift mechanisms are not invented.

## Function authority

The same host-local function descriptors govern wall aperture, fixed frame, moving sash/door, and finite-thickness glass. Rounded and straight frames are field domains, not generated object meshes. Baseline source mode retains every original patch and roof. Proposed source apertures may affect only the stable selected host patch, never opposite walls. Existing authored portal edits must rebuild that host's real aperture.

A simplified hinge or slider is not a real friction-linkage simulation. Door frames have no unannounced full-height threshold bar. Optional security grilles are not included unless their fixed-host attachment and motion clearance are actually validated.

Glass work is planned as bounded real-pane ray transport with Fresnel/refraction/absorption and a disclosed environment-reflection approximation, not an opacity-painted rectangle. This is not a claim of full product optics or structural certification.

## Verification still required

CPU/GPU point, normal, identity, thin-edge and ray parity; parameter/host rotation/reset/disable checks; sampled motion clearance labelled as sampled, not continuous proof; actual open/closed/edge views in all three cases; small-resolution cost gate before large renders; unchanged old versions and exact public hashes after any authorized publication.

The runtime launches rays with fullscreen raster triangles, but generates no object vertex/index buffers, model meshes, Marching Cubes or voxel model. On-demand adaptive pixel resolution changes ray count, not geometry.

# KAOPU 海岸 · 从原片重新观察 R23

## 直接打开

打开根目录 `KAOPU_SHORE_RESTART_R23.html`。它包含新三维代码、8/24/40 秒参考图，以及完整 75.93 秒老师视频的压缩预览。运行时不需要联网，也不加载任何 R00–R22 场景代码。文件是 HTML 工作台，不是视频冒充的三维。

默认先看同一张 08.00 秒原片；“原图测量线”显示本次人工重新描取的边界。“重建顶视”展示右侧三维的正交顶面，不是从老师取得的真实深度图。拖动和滚轮是真正旋转、缩放三维。

“水纹预览”只演示解析水纹；本版没有流体求解器。泡沫覆盖是根据 08 秒画面分布建立的观察场，不是已验证的输运/守恒算法。默认停下观察，不能用动画掩盖错误。

## 真正重新做了什么

本次没有读取旧版的地形、相机、岩脊或泡沫代码。只读取老师原 MP4、从原片重新抽取的关键帧，以及小马的知识文档。

1. 从原视频重新抽取 0.5、2、4、8、12、16、24、40 秒画面，检查相机确实在环绕，不把不同镜头的截图当作同一个相机。
2. 以 08 秒帧为本轮标定对象，人工描取 14 个水—沙交界点、20 个草地边缘点、岩体上缘与接地边两条不同曲线，并逐个标记角色、散石。
3. 拟合一个能够解释该帧投影的三维相机和地表参数。平面尺寸、陆角高程、隐藏海床均属于假设；相机重投影吻合不等于已经恢复唯一真实几何。
4. 用新曲线形成海湾、白沙和草地；以岩体实际轮廓构建高低起伏的有限岩体，而不是圆管、杆或五个重复块。
5. 将橙色角色的可见高度和位置作为投影约束，而不是每版随意乘一个缩小系数。
6. 从一开始分开：原片里直接看到的像素、推断的三维、待验证的运动。没有把“参数值没变”称为老师复刻通过。

## 校准的诚实边界

`source/observations.json` 保存原图像素点、推断相机和假设。图像点人工描取的不确定性约 ±4 px；这是操作估计，不是统计标定置信区间。

相机自由度和推断地表参数可以使这些拟合点的重投影残差非常小。这只是坐标计算自洽检查，不是独立测试，更不代表全图 100% 或真实深度正确。尚未通过第二视角的独立三维验证。

本次采用 32 重建米的横向尺度和约 52.4 重建米的纵向尺度来拟合展示块；不能据此断言老师整个展示地形的真实物理长宽。视频的 256² 局部模拟网格也不能自动等同于整块显示地形。

岩体的可见前沿用于约束位置；为避免反投影高度任意波动，将峰线深度作了平滑/平面约束。此约束也是推断，不是地质测量结果。

## 实际浏览器检查

详见 `qa/QA_REPORT.json`。在桌面 Chromium + SwiftShader 下真实运行了 HTML、WebGL2 shader、几何、按钮、正交顶视、重置、视频解码和窄屏布局。PNG 是这些运行结果的截图。

当前容器限制 file:// 和 localhost 导航，因此测试通过 Playwright setContent 将同一 HTML 载入浏览器；未声称进行了公网 HTTP 部署验收。没有实际 iPhone GPU 签收；软件 GPU 通过不能代表所有设备性能。

## 源码与生成

- `source/app.part*.js`：全新 WebGL2 场景与观察工具，运行 `source/assemble_app.py` 生成 `app.js`。
- `source/observations.json`：图像标注、推断参数及证据分层。
- `source/template.html`：新的左右同画幅工作台。
- `source/build.py`：把数据、参考帧、老师预览片和代码装成一个 HTML（需要 Python/Pillow）。
- `evidence`：本次使用的图像与老师预览片；GitHub 文本快照用指针管理二进制证据。
- `qa`：实际测试报告与截图；GitHub 文本快照保存 QA 报告，完整包保存 PNG。

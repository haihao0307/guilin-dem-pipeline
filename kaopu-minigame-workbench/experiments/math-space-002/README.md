## 试玩内容

从回廊中央出发，沿地面的细导光找到并点亮 A、B、C 三盏灯。拖动转头、WASD 行走；手机按住方向键。灯的触发半径为真实内蕴距离 0.48 单位，不是屏幕像素距离。

“从起点引导试玩”先恢复起点，再沿测地线自动行走，靠近每座灯后换向，三灯全部到达后结束。方向输入随时接管。暂停后再次开始引导，会从起点重走；意外受阻会停止并提示，不会无限假装前进。重置可重复整个过程。

两种空间都把三灯放在距中心 3.60 单位、出发方向彼此相差 120° 的位置：

| 模式 | 三边长度 | 每个内角 | 内角和 |
| --- | ---: | ---: | ---: |
| 欧氏，κ = 0 | 6.235382907 | 60° | 180° |
| 双曲，κ = −0.09 | 6.460494048 | 38.741777931° | 116.225333792° |

控制台显示的是同一几何内核算出的三灯中心连线的角度，不是画面上人工摆出来的角度，也不是把玩家任意行走的轨迹当成三角形。引导会在灯前约 0.35 单位停下，避免走穿基座，因此累计试玩路程不等于三角形周长。

切换曲率会明确清空位置、路程与点灯进度，保证每次对照从同样的构造起点开始。

## 数学实现

负曲率写作 κ = −k²，本实验 k = 0.3。点使用双曲面坐标 p = (x,z,t)，满足：

    B(p,p) = t² − x² − z² = 1，t > 0
    d(p,q) = acosh(B(p,q)) / k

沿单位切向量 v 前进真实距离 s：

    p(s) = cosh(ks) p + sinh(ks) v

相机方向随运动做平行移动。转头是切平面里的旋转；移动不是圆盘投影里的欧氏平移。小地图使用庞加莱投影，显示坐标不参与距离计算。

三角形角度使用双曲余弦定理。κ = 0 分支直接使用欧氏距离、直线插值与欧氏余弦定理，没有把除零附近的近似冒充零曲率。

渲染采用 H² × R 产品空间：水平位置遵循双曲几何，竖直方向采用普通高度。光线沿该产品空间的测地线步进，几何距离用于场景查询。它不是所有二维截面都有相同负曲率的 H³ 空间。

## 视觉和技术边界

- 自有解析圆柱、圆弧门框、暗石色、暖铜色、细导光，没有方块地形、原游戏花纹、噪点粒子堆或外部贴图。
- 光照、材质、雾和发光是实时美术近似，不是经过标定的物理光照。
- 没有接入 Houdini，也没有实现流体模拟；这里首先检验“一个明确的几何规律是否能成为可读的行走体验”。
- 行走有外壁、立柱、门柱和灯座碰撞；这些是本实验的简化碰撞体，并非完整人体动力学。
- 灯台触发、距离、测地线、角度使用真实数学；图像着色与性能尚待浏览器验证。
- 有限回廊，未实现 HyperRogue 的无限网格或大型世界生成。
- 内部渲染像素数上限约 22 万。没有实际帧率结论；应先看真实截图和交互，再决定清晰度/性能档位。

## 文件与测试

最小试玩文件只有 `index.html`，下载后用支持 WebGL 的浏览器打开即可。没有外部运行时请求。参考链接仅在主动点击时联网。

`geometry.js` 是内联数学内核的可读副本；运行页面不需要它。测试直接从最终 HTML 提取内核与应用代码，以避免只验证了一个未实际交付的模块。

无需额外包的测试：

    node tests/math.cjs
    node tests/application.cjs

真实浏览器验收（需要可启动的 Chromium 环境）：

    npm install
    npx playwright install chromium
    npm run test:browser

已有 Chromium 可用 CHROMIUM_PATH 指定。`tests/browser.cjs` 成功后会保存 7 张真实截图及 `tests/browser-results.json`，涵盖两种空间（直接读取 canvas 像素比较，排除 UI 文字影响并检查非黑屏）、点灯路线、重置、真实键盘输入、手机触摸与参数切换。截图仍须人工查看，机器检查不能代替美术验收。

浏览器脚本为生成可重复场景而使用确定性模拟时钟推进引导路线；不据此报告实时帧率。键盘与手机触摸检查使用真实浏览器输入。

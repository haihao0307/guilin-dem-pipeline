# 峡谷来信：落石前的四拍

一个可实际操作、失败、撤回与重试的有限救援策略实验。三台相同绞盘、四个可控回合，救出四个人。不是实时反应测验，不强迫真实秒表。

## 运行

在此目录运行 `python3 -m http.server 8765`，打开 localhost:8765。无运行时框架、网络资源、模型或CDN依赖。`npm test` 执行有限规则验证。`npm install`、`npx playwright install chromium` 后执行 `node tests/browser.cjs` 进行真实浏览器交互。测试版本锁定 Playwright 1.55.0。

## 操作

将控制栏的任一绞盘绳端拖到现场挂点，或点选一项行动。三项以下也可以推进一拍。点已安排的行动可取消；撤回可恢复前一拍的完整状态。第一拍开始远端接力，可以使用备用材料直达；先救修理师则可以开启预装旁路，用平台接回伤员并保住材料。游戏不保存在远程账号。

## 三题的真实边界

- 028：有限高斯素数锚点 A=(1,2), B=(2,3), C=(1,4), D=(2,5)，范数依次5/13/17/29。段长上限1.5，相邻段√2，隔一个锚点为2。画面投影 x=50a+185b−170，y=35a−140b+825；判定使用原始欧氏坐标，不能拿屏幕像素距离当真实绳长。近人挂点是预装救援装置，不新增高斯素数点。关卡边界不可越界，此有限实例不能证明无限护城河结论。
- 089：独立平面道路层 K2,3。六条旧边容量1，四类固定需求XY/YZ/ZX/UV各1，抽象供给可拆分，人物不拆分、不模拟真实液压。基础最优共同率3/4，单旧边UX扩1最优7/8，额外UV外面旁路容量1达到1。flowWitness 给出精确有理可行路径；每个割的容量需求比下界1与真实共同率.75不同。用户不需输入公式，补给决定平台能否启动。
- 124：每项标准动作一拍，任一绞盘可执行。所有前置条件只在拍初读取，每动作后安全锁止并释放机器，无转接旅行时间。同屏可轮流安排但不宣称联网合作。冻结路线之后的依赖图关联三机单位排程；人物期限、备用材料与动态路线选择是额外游戏规则。

四拍先结算行动，再判断落石期限。四类设备供给不随救下人物而消失，也不跨拍蓄存。阀门旁路预装，只需修理师开阀，不耗备用材料；直接搭接C-D耗1，旧边扩容也耗1。

## 保守研究来源

关联 OpenAI/math 的028、089、124问题结构：[028](https://github.com/openai/math/blob/main/lean/docs/028.md)、[089](https://github.com/openai/math/blob/main/lean/docs/089.md)、[124](https://github.com/openai/math/blob/main/lean/docs/124.md)。这些是仓库发布的研究材料，不等同独立证明验收或数学界共识。本实验没有执行Lean、没有复现研究算法、没有证明完整定理；引用只用于明确关联的模型，不将本关成功包装成解决开放难题。

## 美术与实现来源

场景、角色、设备、山体与UI为本次原创Canvas 2D路径与CSS，构成2.5D插画式游戏。没有复制原游戏素材，没有用生成图片伪装交互，没有依赖尚不存在的老师模型。没有CommonPerson扫描模型，也不是完整3D游戏。人物牵引、平台运动、绳路和落石进度均由实际游戏状态驱动；不模拟绳张力/弹性/碰撞。

图形不是用户已批准的最终风格；独立实验仅作为可试玩候选。保留旧math-space案例与其他工作台，不替换旧版本。

## 质量门

必须实际测试两条成功路线、错误扩容、依赖误选、双击取消、失败重试、终局撤回、重置、空拍确认、390px移动与1280px桌面尺寸。CI截图来自真实Chromium渲染，不是设计稿；CI耗时不能当用户设备FPS。核心测试另穷举有限任务状态，确认不存在3拍内救4人的解。

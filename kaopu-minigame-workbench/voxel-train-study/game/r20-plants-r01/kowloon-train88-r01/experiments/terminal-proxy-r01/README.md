# One terminal-group far proxy, isolated stencil experiment

Motivation: 449c043a/run38319298337 measured original g0 at51–60% of four fixed representative warm query configurations. The initial alternate configuration enqueued only6 candidates, yet g0 still took38.29ms. This establishes a target, not a causal claim about a private array. Existing capacity1 is not repeated or adopted.

The light shader keeps byte-extracted original host-ray, box and compact merge functions. Known far points use the exact original id0/raw1 proxy. Near points, nonfinite values and unknown controls discard into stencil0, then the unchanged original g0 shader executes there. It does not truncate materials or replace a surface. The other11 groups remain in original order. Strict min/tie, raw counts, flags and canonical defaults are preserved.

One additional g0 render target owns its depth/stencil attachment. All requested stencil clears, classification, original heavy draw and narrow state restoration are inside g0's timer. Original buffers/parity resume from group1. Asymmetric or unsupported GL state falls back to the original g0. No CPU texture readback chooses geometry. The experiment preserves actual GL/Three state-cache consistency rather than issuing a blanket renderer reset.

Exactly three warm rounds alternate original/proxy AB, BA, AB in one resident controller. Both fixed original terminal and original initialized ray inputs run full and alternate queries. Every group's actual compact prefix is compared; original4MRT projections and frozen complete terminal metadata are retained. Boundary/unknown probes use all three ages outside timing. Actual ANY_SAMPLES_PASSED results are checked against light-program discard masks; timing decides whether stencil execution actually helps this software backend. Stencil API semantics alone do not promise early shader execution or performance.

No images, host adoption, public publication, full-frame performance or hardware extrapolation. Same600s process deadline and120s no-progress bound as the previous QA. One false toggle returns to original shader execution.

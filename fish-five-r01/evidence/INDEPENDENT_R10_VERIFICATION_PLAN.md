# R10 compact product independent verification plan

Prepared 2026-10-03 against baseline `259168f309f75c88c470b5e52b0a8a4a36ce36a9`.
Status: READ_ONLY_RESEARCH_COMPLETE / CANDIDATE_NOT_YET_FROZEN.
This plan does not accept a candidate, grant a license, or claim visual fidelity.

The latest user authorizes removing full source data from runtime after adopting it into a lightweight product. Earlier exact-topology and exact-original-pixel storage rules therefore need a scoped task override. Source references remain offline for verification; no generic geometry substitution is authorized.

## Required numerical gates

1. Bind candidate bytes and actual changed production owners to a frozen SHA/hash. Parse the emitted product independently, checking block bounds, overlap, schema, cardinality, finite values, indices, and image metadata. Do not let the production decoder certify its own product.
2. Runtime product must not include full source reconstruction fields (`base`, `paramAddress`, `residual`), original GLB/FBX, or a concealed original fallback. A source SHA/author/license record is provenance, not a forbidden geometry payload.
3. Report rest-position error in source canonical units and BL, silhouette/envelope error, normal angular error, UV error, and material-channel fidelity. Source-specific tolerances must be frozen before acceptance; thresholds chosen after seeing a failure are not valid proof.
4. Quantization/reordering or decimation must preserve discrete fin labels and continuous fin weight/gradient fields. The five-specimen oral-runtime sparse binding indices must remain valid or be remapped and baked into the product. Legacy attributes are positions, oct normals, UV, 12-channel weights, partInfo, and partRoot; omission of any required field is a failure.
5. No new dynamic splits at coincident vertices/UV seams. Test fin roots and whole-body transport in rest, hover, cruise, burst, turn and maximum legal automatic transition amplitude, including source thin-fin/double-sided/alpha material semantics. Do not fill original mouth seams or source-open boundaries.
6. Preserve shader Jacobian/cofactor normal behavior; reducing mesh data must not silently revert to flat/incorrect normals. Test transformed positions, finite unit normals, deformation residual and triangle strain across a full motion period.

## Required actual runtime gates

1. Headless only; do not take the user's mouse. Root controls GPU scheduling. No browser has been launched for this plan.
2. Offline `file://` standalone: first frame, six switches, single/group, existing modes/automatic cycle, skeleton/head views, eyes, mouths where confirmed, and zero core HTTP requests / console errors.
3. Online mirror: selected compact product only; no legacy/source requests, no eager six-source download, no original-package fallback, HTTP 200 and asset hashes matching frozen build. Desktop and mobile startup and interaction remain mandatory.
4. 30 fish share rest geometry and textures. Record runtime creation/decode counts and single-to-group allocation changes. No per-fish full geometry/material copy, no rest-geometry generation in the frame loop.
5. Compare same-state actual source and candidate single-fish images at side, front/head and oblique views, at rest and high legal deformation. Examine visible silhouette, texture sharpness, eye attachment and fin continuity; pixel metrics supplement visual review. This comparison is internal QA and does not imply user visual acceptance.
6. Record per-product encoded bytes, numeric bytes and explicit allocated GPU geometry/texture bytes; startup, renderer JS heap/backing storage and frame costs separately. Driver/worker/native/process/GPU residency must not be confused with JS heap.
7. Successful local QA is not public delivery. A fresh public proof with shareAllowed=true is required before a new URL is sent; visualAcceptance, productionReady and scientificCalibration remain false unless separately authorized evidence exists.

## Existing baseline facts

Selected barracuda binary is 24,282,063 bytes, carrying approximately 497,701 vertices and 964,285 triangles. Five source binary files total 51,751,353 bytes; all six runtime binaries total 76,033,416 bytes. Yellow-label tuna alone carries 46,219,248 encoded image bytes, with six 4096-square source images. These are baseline storage facts, not measured candidate improvements.

## 本轮实际完成

本轮没有覆盖旧版 `wm-r11-cloud-base-optics-v001.html`，而是在独立实验目录建立单文件 WebGL2 工作台。

云对象固定为 `cloudId=WM-CU-001`，世界尺度声明为 `1 unit = 1 km`，云底 1.15 km，候选云顶 4.55 km。相机只负责观察，当前时间冻结；没有把噪声相位动画冒充风场输运。

云结构按以下职责分开：

- `CloudEnvelope`：稳定包络、平底、独立对流塔、受保护空区和下切区。
- `CloudState`：粗密度代理及用于光学的粗状态。
- `CloudDetail`：Yohei Nishitsuji 方法启发的 log2 半径、方向坐标、嵌套余弦频带与独立三角干涉。
- `CloudOptics`：消光、透射、方向相位近似、太阳光、天空光和粗自阴影。
- `CloudTransport`：本轮明确未实现；任何画面变化都不标记为真实输运。

## 对 Yohei 方法的准确迁移

本轮吸收的是可验证的坐标与多尺度组织机制，不把 Yohei 的艺术着色器错误称为通用云物理求解器。

1. 使用 `log2(radius)` 将乘法尺度转成平移坐标。
2. 使用方向坐标与嵌套余弦形成相关频带，不采用互不相关的白噪声层。
3. 每一频带保持固定幅度，新增频带不重新归一化、不改写旧低频前缀。
4. 原始嵌套余弦场具有明显正偏，本实现用固定中心和固定增益改成有正有负的细节场；否则它只会把云越加越厚，不能形成空腔。
5. 把程序化场预计算为确定性 3D 缓存：七个独立频带、一个干涉通道、一份云包络/粗状态缓存。浏览器渲染时读取缓存，不在每个光程样本里重复运行大量三角函数。

默认缓存为 `64 × 40 × 64`，三份 RGBA8 三维场总计约 1,920 KiB。它们由单文件 JavaScript 在启动时重建，不依赖外部贴图或二进制资产。

## 交互与诊断

- `A=0`：关闭细节，精确回到稳定粗状态。
- `候选`：启用受包络门控的 Yohei 多尺度细节。
- `A/B`：同一相机、同一光照、同一粗状态下左右对照。
- `包络 / 粗态 / 细节 / 密度`：分别查看各层，避免只靠最终调色判断。
- 拖动旋转、滚轮缩放；拖动期间自动降低光程步数，松开后恢复正式步数。

## 当前明确不足

这仍是第一团云的结构候选，不是最终 3A 成品。当前主要不足是：多重散射只是近似；云型统计、湿度、凝结、蒸发、浮力和降水尚未进入状态；没有真实风输运；复杂地形边界尚未接入；目标设备的帧时间与显存尚未测量。

下一轮只应在用户视觉意见基础上继续修改这团云的大形、内部空腔、光学层次和近景表现，不能同时把整片天气系统、降雨和动力学全部塞进来。

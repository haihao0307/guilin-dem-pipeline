# 05 · 重开后的下一步

不要重新发明第四套云。直接以 R27 固定候选为当前开发对象，以 R26 为安全回退。

## 第一轮：验证统一对象是否真的成立

- 固定 cloudSeed、detailSeed、时间和世界位置。
- 在观云与飞行模式查询相同位置的密度，输出必须一致。
- 镜头切换不能改 Cloud DNA。
- 同一 cloudSeed 更换 detailSeed，只允许高频和边缘变化，大尺度轮廓必须保持。

## 第二轮：把银边彻底变成 optics

- 固定云身份，只旋转太阳与观察者。
- 验证银边连续移动，密度诊断不变。
- 删除任何把 silver 当 genus 或另一个密度场的遗留路径。

## 第三轮：逐类检查十云属

顺序建议：积云 → 层积云 → 层云 → 高积云 → 高层云 → 雨层云 → 卷云 → 卷积云 → 卷层云 → 积雨云。

每类必须检查：远景、云缘、云内、穿出、种子变化、太阳变化、移动端帧率。未通过的一类挂起，不得污染已经通过的云属。

## 第四轮：真实性能与渐进启动

记录真实 iPhone Safari 的：

- 首个可见云帧；
- 可交互时间；
- 稳定 30/60 秒帧率；
- 内部渲染尺寸；
- 设备温升/降频迹象；
- context loss 与恢复；
- 切换十云属后的内存和卡顿。

先显示低频主体，再逐步开放高频、光照缓存和历史收敛。不能为了启动质量让用户先面对空屏。

## 第五轮：飞机遮挡

保留 R25 的 fail-open 光学衰减作为最低层。更精细逐像素遮挡必须经过能力检测，禁止直接恢复曾导致手机空屏的旧 depth FBO 路径。

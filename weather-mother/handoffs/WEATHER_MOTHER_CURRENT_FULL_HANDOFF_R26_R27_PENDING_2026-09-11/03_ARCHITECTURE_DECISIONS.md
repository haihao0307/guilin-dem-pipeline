# 03 · 已批准的架构决策

## 一个云对象，多种观察者

观云、地面观察、飞机远看、云缘、云内和穿云后，必须读取同一份 Cloud Object / Cloud State / Density / Optics。镜头只改变位置、光程和可见频带，不能因为进入飞行模式就换另一套云。

## 银边不是独立云种

银边是同一密度场、湿润低密度肩部、太阳方向、前向散射和光学厚度共同产生的成像结果。太阳和观察方向变化时，银边应沿同一朵云移动。正式云类型中不再保留独立 silver cloud genus。

## YOHEI 只继承方法

可以保留相关三角频带、频率递增、振幅递减、稳定低频前缀、log-spherical/domain transform 和按观察距离展开频带的方法。

不能继续保留可识别的原作者构图、固定常数组合、默认颜色和太阳角，也不能把 YOHEI 场直接当气象真值或云身份。最终画面必须由 Weather Mother 的 envelope、Cloud DNA、种子、气象状态和 optics 决定。

## 两级确定性种子

- `cloudSeed`：决定大形身份、云瓣、空洞、塔体、层断口和不对称。
- `detailSeed`：决定局部侵蚀、湿边、丝状和高频褶皱。

两者都必须是可复现整数，不随帧或镜头变化。更换 detailSeed 时不能破坏 cloudSeed 对应的大形。界面应提供输入、上一颗、下一颗和随机生成，并把最终整数写回。

## 观察带宽

近距读取完整频带，过渡距离连续减弱高频，远距只读稳定低频前缀。不能重新归一化、换种子、重置身份，也不能用另一朵低模云替换当前对象。

## 渐进启动

先显示天空和低频云，再逐步启用完整体积路径、3D noise、light cache 和 history。用户应能先移动，再后台提高质量。任何高级路径失败时都必须保留 cloud-first 可见结果，不能退回纯色背景。

## 性能判断

十云属低帧率不是十种云同时在算，而是单帧全屏 ray marching、复杂密度函数、多频带、太阳二次积分和高 DPR 共同造成。优先使用空区跳跃、低透射早停、光照缓存、动态分辨率、移动时低采样、静止后收敛和观察带宽。216×144 的软件 QA 不能代表真实手机性能。

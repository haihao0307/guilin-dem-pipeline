# Anny 身体工作台：可复用的技术结论

审阅日期：2026-10-06。源码固定为 [Anny v0.6.1](https://github.com/naver/anny/tree/v0.6.1)，提交 `d6fc027ced5c17b6b0775dee944096ade7a9ef80`，模型缓存数据版本 `12`。本页记录源码审阅与实现约束；数值通过情况以工作台实际测试报告为准。

## 1. 真正值得提取的能力

Anny 的核心是一个可解释的身体形变器：语义参数 → 多维分段插值系数 → 身体表面与骨架 → 姿态传播 → 蒙皮。它不需要在每次拖动滑杆时运行照片重建网络，也不需要加载其他人体模型的全部权重。

六个默认形态参数是 `gender / age / muscle / weight / height / proportions`，默认值均为 `0.5`。年龄、体重、肌肉等并非各自独立的单个缩放器；其插值系数相乘，选择适合组合条件的形状基。例如，同样的身高参数，婴儿和成人使用的形状基不同。[系数实现](https://github.com/naver/anny/blob/v0.6.1/src/anny/models/phenotype.py)

形体与姿态应分别保存：改变年龄或体型后仍可复用动作；恢复姿态不能意外重置身体身份。运行时只依赖已导出的几何和骨架数据。将来接照片拟合时，拟合器负责产生这套参数，身体运行时负责稳定执行它们，两者通过有版本的参数契约连接。

## 2. 年龄滑杆到底改变什么

- 原生年龄锚点为 `-1/3、0、1/3、2/3、1`，依次对应 `newborn / baby / child / young / old`
- `age=0.5` 是 child 与 young 的中间形态，并非“50岁”；若显示岁数，应另外使用官方形态年龄映射及其校准数据
- 年龄改变表面顶点、骨骼起点以及适应形体的静止骨架方向，不能用整体等比缩放代替
- 新生儿端有明确的近似：在婴儿形状基础上使用 `[0.922, 0.922, 0.75]` 的非等比缩放及模板补偿。它并非独立采集的真实新生儿扫描
- `gender=0` 与 `1` 对应上游名为 male 与 female 的形态端点；这些是作者设定的形状控制，不是身份判定或医学测量
- 其他默认轴使用 `[0,1]`。局部修改通常为 `[-1,1]`，零为关闭；上游默认局部集合有254项，排除两项 nipple 控制。界面可选少量实用入口，但应说明保留的参数范围

来源：[锚点及参数范围](https://github.com/naver/anny/blob/v0.6.1/src/anny/models/phenotype.py)、[新生儿构造](https://github.com/naver/anny/blob/v0.6.1/src/anny/models/full_model.py)、[年龄映射](https://github.com/naver/anny/blob/v0.6.1/src/anny/shape_distribution.py)。[论文](https://arxiv.org/abs/2511.03589)也明确提醒：语义形状基包含艺术家的预设，不能把参数当成真实身份属性。

## 3. 浏览器端必须保留的计算顺序

1. 为每个语义轴计算相邻锚点权重。每个形状基的系数是其关联轴权重的乘积；局部正、负修改分别使用 `max(x,0)` 与 `max(-x,0)`
2. 从模板加权累加表面顶点、骨骼起点，以及每根骨骼的3×3协方差矩阵
3. 将协方差矩阵投影为行列式 `+1` 的旋转，得到随形体变化的静止骨架方向。默认 anny 骨架已离线烘焙所需数据，浏览器不需要重做原始拟合
4. 根据参考骨架方向，把 `local-ref` 姿态转换到骨骼空间；按父子关系做正向运动学
5. 每根骨骼的蒙皮矩阵为“当前骨骼姿态 × 静止骨骼姿态的逆”。保留每个顶点的全部非零影响权重，做线性混合蒙皮
6. 模型保持“米、Z向上”。Three.js 的Y向上展示可在整个显示组上施加 X轴 `-90°` 旋转，不能只旋转皮肤而漏掉骨架，也不能在导出时重复旋转

注意：默认 `local-ref` 的单位姿态会执行根骨定位和参考方向处理，因此最终 `vertices` 不能简单假定等于 `rest_vertices`。必须与相同配置的官方前向输出比较。

主要实现：[rest model / forward](https://github.com/naver/anny/blob/v0.6.1/src/anny/models/rigged_model.py)、[FK](https://github.com/naver/anny/blob/v0.6.1/src/anny/utils/kinematics.py)、[蒙皮](https://github.com/naver/anny/blob/v0.6.1/src/anny/skinning/skinning.py)、[缓存骨架](https://github.com/naver/anny/blob/v0.6.1/src/anny/models/model_transforms.py)。

## 4. 开发资产与最小运行时分开

官方 v0.6.1 的 `src/anny/data/` 共1,559个文件、107,825,068字节，约102.83 MiB。这是 Git 树中源文件尺寸之和，不是浏览器下载量、解压内存或模型缓存大小。里面含多套骨架、替代拓扑、关键点、统计分布和可选表情素材，不能全算成某一个身体实例的必要负担。

构建端保留官方源资产与校验环境。浏览器运行时只需：模板、面索引、所选形状基与标签/掩码、骨骼层级与标签、起点和方向的基数据、参考方向、蒙皮索引与权重、以及有版本的元数据。无贴图展示不必带UV；没有表情入口不必带52项 facial actions；不用SOMA、SMPL或SMPL-X就不带对应拓扑和映射。

但 v0.6.1 的原始 `load_data()` 会先读取完整形状源，再筛选配置：`facial_actions="none"` 代表最终模型不含表情，不代表首次源码构建可以直接删除表情源目录。已导出的浏览器运行包不受这一构建期需求约束。

轻量化顺序：无损零项稀疏化 → 合并固定参数轴的贡献 → 按功能拆分延迟加载 → 有误差报告的量化/降模。合并固定轴必须同时处理顶点、骨骼起点和方向协方差，保留开放轴之间的交互；不能只保存几个截图式预设网格冒充连续参数模型。

同一份数组不要复制到每个角色实例。共享不可变的身体定义，每个角色只保存参数、动态顶点和姿态缓存。换姿态只重算FK与蒙皮；换形体才重算静止身体和骨架。

## 5. 版本、顺序与缓存都是接口

- 新默认 `rig="anny"` 是104骨、`local-ref`；旧工厂保留163骨MakeHuman与 `local-bone`。姿态矩阵不能直接混用
- 过滤面、移除未引用顶点、重排骨骼、换拓扑都会改变索引契约。保留 `base_mesh_vertex_indices`、精确面索引及骨骼标签顺序；不要让网格库自动合并、排序顶点
- 默认拓扑的三角化应在构建时固定；不要因形体变化重新挑选四边形对角线
- 上游缓存键为构建函数参数的规范化JSON哈希，加数据版本目录；它不会自动哈希全部源资产内容。修改本地源资产或导出器时，必须另外更新构建指纹/内容哈希，避免旧缓存被当成新结果
- 浏览器 manifest 应记录：上游提交、数据版本、完整配置、坐标约定、数组形状/类型、资产字节数、校验哈希，以及自身导出格式版本。参数预设也应绑定该契约
- 若以后启用SOMA，v0.6.1 固定 `py-soma-x==0.1.0`，对应资产 revision `6db1b4e8d737db240e680ca5358ae2897f2d9427`；不要无条件拉取最新资产

来源：[数据与缓存](https://github.com/naver/anny/blob/v0.6.1/src/anny/models/model_data.py)、[更新记录](https://github.com/naver/anny/blob/v0.6.1/CHANGELOG.md)、[SOMA固定版本](https://github.com/naver/anny/blob/v0.6.1/src/anny/models/soma.py)。

## 6. 黄金对照与验收

以官方CPU float32、同一提交和完整配置生成参考输出，比较所有顶点，不只几个采样点：

- 默认六轴均0.5；年龄全部五个锚点及0.5；年龄与两端体型组合；其他轴0、0.5、1；至少一组非锚点混合参数
- 每个开放局部控制的正负方向；多个局部控制叠加；修改后复位，并反复切换预设以检查残留状态
- 肩、肘、髋、膝、手腕及根骨平移的姿态；先改形体再摆姿态；清空姿态后返回同一形体的官方中性输出
- 比较 `rest_vertices / rest_bone_poses / vertices / bone_poses`，分别报告最大绝对误差和RMS。建议 float32 浏览器顶点目标：最大误差≤`1e-5 m`、RMS≤`1e-6 m`，这是验收目标而非尚未实测的保证
- 核对顶点/面/骨骼数量与顺序、索引不越界、父子树可遍历、权重非负且和为1、旋转正交且行列式为+1、所有输出有限
- 上游对照仅允许忽略“没有蒙皮权重且没有子骨”的叶骨方向差异；不能借此忽略有权重骨骼或父骨错误
- 浏览器另外测试首次下载、加载失败后重试、快速连续滑动、重置、导出、重进页面及视图旋转。参数导出应能重新产生同一个身体

来源：[官方回归测试](https://github.com/naver/anny/blob/v0.6.1/test/test_regression_vs_fixtures.py)。本工作台的测试记录应单独区分：已通过、失败、未运行。

## 第一层：共同理解与边界

必读原交接 MOTHER_STARTUP.md、REVIEW_DISPOSITION.md、RECIPIENTS.md，以及导师 00_小妈先读.md。随后按任务展开 details/01_REVIEW.md、02_HANDOFF_AND_ROADMAP.md、05_CONTRACTS.md。原研究地图仅作为索引，不能当作当前代码审计。

每个执行者提交 R1-A 回答：

1. 本轮具体要解决哪个已存在的错误？当前版本与最后人工接受版本分别是什么？
2. 指出至少两处本轮实际读取的文件、提交和小节，并解释对自己工作的影响。仅列标题不算答卷。
3. 用自己的项目举例，分别说明资料已读、方法已实现、结果已验证、用户已接受四种状态需要什么证据。
4. 指出三个自己不能改动的边界。遇到导师建议与当前有效规则冲突时，如何处理？
5. 从证据缺失、证据未召回、尺度/相机不一致、理解错误、表示不足、导出/运行偏差中提出两个竞争解释，设计一个能区分它们的检查。

## 第二层：软件方法转成技能

所有 Mother 先读 [技能总目录](SKILL_INDEX.md) 的四类概览；按自己责任深入相应 SKILL.md 和对应官方英文原文。无需每个 Mother 全读四套软件手册，也不能用目录阅读冒充全文掌握。

每项技能保留三层：来源中的原名、版本和章节；独立于产品的输入输出、因果关系与适用条件；本 Mother 的实现位置、测试及边界。共用原理可以共享，领域参数和生产许可分别核对。

每个执行者交回 R1-B：一张本线技能卡，写清来源、输入、输出、单位、坐标/属性域、假设、步骤或伪代码、依赖、失效条件、成本和计划验证。至少回答一个改变前提的追问，不能只复制本轮样卡。

## 第三层：理解核验与同学复述

小妈收到原始答卷后逐项复核，并提出针对答卷的新追问。先检查证据可访问性和分支身份，再检查推理与边界。单独的“已读”“理解了”“全部掌握”只记收到回应。

每人回答 ASSIGNMENTS.md 中本线问题，再选一个不适用场景。合格答卷应能预测一个参数改变后的影响，并指出何时应拒绝套用方法。没有读到原文、依据冲突、缺少实测时明确说明。

同学互学按实际收到的技能卡安排：Tiles 与 House 互查接触/支承；Brick 与 Weather 互查材料响应；Landscape 与 Ocean/Coast 互查岸线和坐标语义；Human 与 Animal 在入口确认后互查状态连续性；Historical World 与 DEM 互查时间、空间和真值来源。互审是第二份可追溯答卷，不代替小妈复核，也不代替用户验收。未真正发生的互审保持 not_run。

## 第四层：有限试验与采用决定

通过理解核验后，由用户按本线情况决定新技能的下一步。试验固定来源、版本、相机、尺度和种子，明确修改范围，保留旧版本与恢复路径。结构问题检查实际接触/穿透；动态问题检查完整状态变化；发布继续执行已有在线三维门禁。

技能先在一个已知问题上验证。需要宣称可迁移时，再验证未参与调参的对象或参数。一个样本改善可以记录，但不可自动升级为全类掌握。

本轮学习不覆盖全部软件能力，不更新模型权重，不意味着软件已经安装或实际运行。启动其他聊天、Codex 实例和定时工作需要真实执行通道；仓库留言本身不构成启动证明。

## 回复方式

在收到通知的 Issue 中逐个回复，开头写 MOTHER_LEARNING_R1_REPLY，并带 mother_id、轮次、执行会话标识、实际分支/HEAD和本次读取提交。正文使用 [REPLY_TEMPLATE.json](REPLY_TEMPLATE.json) 的字段，也可使用等价 Markdown。不要复制模板空值后宣称完成。允许先交 R1-A，随后交 R1-B；受阻也必须写原因和已能继续的部分。

同一账号可能承载多个执行会话，用户名相同不能证明来自同一 Mother，也不能证明独立性。需结合会话自报、实际分支、答卷差异、来源和实验记录核验。小妈发出的题目、样卡和汇总一律排除在 Mother 回执之外。

状态分列：通知发布、执行者回应、阅读证据、理解复核、技能试验、跨对象复用、用户采用决定。通知已发布不能自动提升后面任一项。遇到新回复，核验后更新状态并保留旧记录。本轮未设定后台轮询或定时调度。

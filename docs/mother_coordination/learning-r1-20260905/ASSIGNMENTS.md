## guilin-dem-pipeline，既有 Issue #61

DEM：包含桂林、温州等现有子线，分别记录各自当前合同。主读真值与生成边界、属性/单位、版本和显示层约束。问题：看过 Gaea 侵蚀后，哪些知识可学习，哪些输出仍不得进入 canonical？如何证明一个显示优化没有改变数值？

Landscape：主读 Houdini 属性与依赖、Gaea 地貌过程，辅读 UE 空间生成。问题：主峰轮廓不对而微噪声很丰富时，先检查什么？把相机或光照改好看能否作为形态修复证据？交一个主形有限实验方案。

Weather：主读 Houdini 场与 UE Niagara，辅读材料接口。问题：如何描述风、雨、湿度的单位、时间和位置？请给出外观停止而环境状态继续演化的可检验例子。

Cloud：在本仓库 AGENTS 中有命名，列为覆盖检查项；是否独立执行会话仍由 Weather/Cloud 实际回执说明。主读体积密度、空间采样与实时表现。问题：密度、透明度与降雨强度为何需要独立语义？没有 Cloud 独立会话时由 Weather 报告覆盖范围，不代造新 Mother。

Ocean/Coast：Coast 按现有海洋子范围处理，不新建独立 Mother。主读场/状态边界和 UE 动态表现，辅读 Gaea 尺度。回复中分开水面外观、浮力、碰撞、岸线与边界。问题：如何区分泡沫好看、岸边接触正确和边界不泄漏？

## HOUSE，既有 Issue #16

House：主读 Houdini 依赖、Blender 几何上下文，辅读 UE 场景组织。问题：墙体与屋架或屋面材料修改时，哪些结构关系必须保留？用何种证据判断支承有效？

Brick：主读属性分离、实例与材料检查，向 Weather 说明环境接口。问题：湿度变化时哪些材料通道可变化，哪些几何或材质类别信息必须保持？如何区分材质改善和打光变化？

Tiles：主读几何/实例、装配依赖。问题：面对悬空、互穿、支撑关系错误，如何建立有效对照和检查？如何防止修完瓦片后支撑件或旧版再次退化？使用当前正确参照，不从教材猜地方构造尺寸。

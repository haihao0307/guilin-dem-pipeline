# 实时世界状态与表现技能卡

R1 初始样卡。主要来源：Epic PCG Overview、Niagara Overview；补充阅读入口为 PCG Generation Modes、Control Rig。正文查读范围见 SKILL_INDEX.md。UE 实际运行、网页移植和跨系统联调均 not_run。

## 来源核心

PCG 使用空间数据和带属性的点组织生成，点包含变换、密度、种子等数据。Niagara 区分系统、发射器、模块和参数，并组织产生、更新和显示等阶段。Control Rig 提供控制器、骨骼与求解工具，接入仍需匹配实际项目约束。

## 本轮提炼的方法

对空间筛选、环境输入、动力学状态和显示输出建立不同合同。外观可以使用物理状态，也可以是近似表现；必须标明两者关系。跨 Mother 交换前确认单位、时间、空间采样位置、更新时间与责任方。

输入：时间、坐标/单位、空间候选及属性、环境字段、场景限制、版本与种子。输出：被选择的实例/对象、动态状态、显示参数、独立的碰撞或接触检查。

有限步骤：选一个已有任务；记录输入语义；固定参照与相机；改变一个环境参数；分别记录显示与物理输出；检查时间连续性和边界；在既有运行时验证，不强制迁移整个项目。

## 理解题

水面出现泡沫能证明浮力和碰撞已经正确吗？一项输入叫 wind 时，如何区分速度、方向、强度乘数和纯视觉噪声？屏幕上的雨停了，粒子状态、湿度与材料响应是否必须同时归零？你如何验证自己的具体解释？

## 试验设计

提供一个允许区与禁止区的空间筛选正反对照；固定种子检查生成可复现程度。动态试验先写明实际 dt、初态与终止条件，记录启动、停止、恢复过程，检查边界泄漏或对象消失。单位变换和时间步变化单独检查，容差按任务先约定。

对 Human/Animal，求解表现必须遵守已有骨骼、finalPose 与低层执行边界；Brain/Jarvis 只产生高层意图和任务状态。对历史世界，现代地理字段不自动证明历史物体存在。

## 采用条件

来源理解通过、接口语义明确、试验有真实结果后再讨论接入。UE 模块的存在不等于 Three.js/WebGPU 已具备同样功能。结构正确、动态正确、浏览器通过、用户视觉接受分别记录。

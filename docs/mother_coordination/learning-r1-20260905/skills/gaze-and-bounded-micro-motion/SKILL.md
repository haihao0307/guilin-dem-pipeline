## 蒸馏结论：四个职责分开

目标层决定看哪个世界点或对象，输出targetId、worldPoint、时间戳、有效期、置信度及任务版本。眼球控制层根据头部参考系、眼球中心、前向轴和允许角度形成朝向意图。节奏层安排转向、停留、跟随和目标失效后的过渡。有界微动层只贡献明确幅度与频率的次级变化。此四层是本项目的候选职责划分，尚未接入人物运行时。

Brain/Jarvis继续负责既有高层意图和注意决策；目标坐标与时间经明确定义的接口传递。Human既有运动执行者负责眼球朝向求解及与头部、眼睑的配合。显示层只读最终结果，不绕过姿势权威写骨骼，不接管另一创作者的身体部位。

漂浮眼球群的空间移动与头部内双眼的受控朝向分别使用。进入人物时，先保留现有眼球枢轴和身体定位。没有本线明确允许和验证的平移自由度时，不把截图的空间漂移叠到眼球中心上。眼睑接触、角膜穿插、瞳孔变化及生理性眼动参数都需各自证据，不能由一个艺术动画推定已成立。

## 坐标、双眼与有界朝向

最小合同：稳定eyeId；模型前向轴和up轴；bind参考姿态；当前头部/眼球父变换；左右眼各自的中心；世界目标；模拟时间t、dt；角度和角速度上限；当前模式、任务版本与微动参数。单位分别为m、s、rad、rad/s；屏幕像素必须经过实际相机投影映射，不能直接当作世界距离。

在刚性、单位缩放的头部参考框架中，可先计算d_world=normalize(target_world-eye_origin_world)，再用头部/绑定参考旋转的逆旋转得到d_local。眼球网格实际前向轴与统一前向轴的校准单独保存。不要假设全部眼球模型都沿+Z，也不要硬编码原作品的转轴补偿到另一模型。父层含非均匀缩放时，停止套用这个纯旋转推导，先建立合法的控制参考框架。

左右眼共享同一目标点，各自由自身中心计算方向。直接复制相同Euler角会忽略两眼中心差异。近目标、远目标、目标穿过视野边缘、头部旋转以及目标与眼球中心重合均须分别测试。重合目标返回明确的保持/无效状态，避免零向量归一化。

候选角度约束可在声明的局部前向轴下使用yaw/pitch范围或椭圆预算，再产生目标四元数。范围属于待标定参数。四元数插值解决旋转表示问题，不能自动保证眼球角度、角速度和角加速度均合法；加上微动之后还需检查最终预算。

固定目标时，角步长可取omega_max*dt；使用最短弧插值避免Euler跨越正负180度时绕远路。移动目标的追踪误差、头眼协调和角加速度仍待实测。采用平滑追踪时，可研究alpha=1-exp(-dt/tau)，其分步一致性只在固定目标的一阶模型下成立，不能推广成任意动态目标完全相同。

## 噪声微动与既有函数体系

截图中的机制可表达为p(t)=p_reference+A*N(reference_coordinates,time,identity)。A控制长度幅度，空间取样尺度控制相关长度，时间缩放控制变化速率。小的空间noiseScale并不单独保证时间上更慢。相位/通道偏移用稳定ID与种子生成并保留；每次重建重新Math.random会改变对象行为身份。

截图用noise3D(nx,ny,t)、noise3D(ny,nz,t)、noise3D(nz,nx,t)生成三个分量。它们分别丢弃一个空间坐标，并可能高度相关；当nx=ny=nz时，三个输入完全相同。需要完整空间连续性时可研究noise4D(x,y,z,t)与明确的通道变换；需要共享微动时有意保留相关性。通道偏移只提供去重策略，不证明统计独立。

对眼球朝向，建议把有界微动表示为小角度旋转deltaQ，在声明的局部顺序下与主朝向组合，再做最终限制。A=0时deltaQ必须严格为单位旋转，主朝向保持。直接把rotation.x或rotation.z赋成噪声值会覆盖既有基准分量，不能当作通用叠加。

参考态查询不累加上一次偏移，避免逐帧积分漂走。同一ID、版本、参数和t应可重复查询且只读。输入幅度归零只能关闭这一微动分量；已有状态机、追踪历史或目标选择不会自动倒退，严格对照仍要恢复相同快照和事件序列。

Simplex Noise只负责相关变化，不证明真实注视、警觉、注意、微眼跳或生理震颤。艺术微动与真实人类眼动要分别命名、标定和验收。本轮没有做眼动生理研究或人体参数标定。

## 状态、生命周期与物理权威

目标切换采用一个显式任务版本或epoch。旧回调即使晚到，也不能重新启动上一条转向任务。对象销毁、页面重置、切换角色及停止指令必须清理自己的回调/计时器/动画引用；不能清除别的身体作者正在使用的全局动画。学习消息要求执行者检查真实停止和旧任务失效，不新增无法验证的后台循环。

随机事件按共同模拟时间定义。每显示帧固定概率会随刷新率改变每秒发生率。以每帧0.01为例，独立试验下1秒内至少一次事件的概率在30帧约0.2603，在120帧约0.7006。候选可使用p(dt)=1-exp(-lambda*dt)，或在事件发生时抽样并保存下一模拟时间。最终事件序列还需稳定随机流和可恢复状态。

对于确实需要漂浮碰撞的独立道具，控制层给力、速度目标或明确的运动学目标，物理步负责最终位置；显示随后读取。把显示位置再加任意噪声可能重新产生互穿。固定步长、最大子步、暂停与追赶政策须明确，不能仅截断帧间隔后宣称真实时间一致。这里没有要求给人体眼球增设自由漂浮刚体。

本轮由S1与S6组合发现一个需防误抄的细节：把自定义forceMomentum对象直接赋给body.force后，物理步的clearForces会原地清零同一个对象。这种别名会让所谓独立平滑状态一起归零。独立CPU反例已验证引用清零的语义；没有运行完整原作品。需要持久控制状态时应独立保存，并复制数值到物理受力槽，单位与响应模型重新明确，不根据变量名认定它就是物理动量。

形状发生变化时，包围范围、AABB、质量和惯性依赖按所用引擎约定更新。S6官方文档分别列有相应更新方法。没有据此宣称原作品发生了特定碰撞故障；完整场景需另测。旧版本示例和现行官方文档的接口差异也不能自动忽略。

日期：2026年9月7日

## 决定

长期知识蒸馏以 GitHub 为主存储。当前目录位于 `haihao0307/guilin-dem-pipeline` 的协调分支 `handoff/xiaoma-mentor-v1.1-20260905`。这里保存知识、推导、来源、反例、试验设计和采用状态，不作为任何生产线的代码基线，也不整支合入生产分支。

## Make 当前状态

Make 平台本身可以连接，能够读取环境、创建场景、设置周期和保存配置。实际人工智能研究步骤目前没有稳定运行成功。

已经观察到的失败包括：

1. Make AI Toolkit 的 Ask 模块缺少可用连接 ID。
2. Make AI Agent 模块在实际运行时出现参数校验失败。
3. 一次加入代码触发模块的方案受到当前套餐限制。
4. 后续调整还遇到临时请求频率限制。

故障场景 `6177373` 已关闭，避免继续按计划产生失败运行。此前测试场景也保持关闭。当前不能把 Make 记为可用的长期研究执行器。

## 选择 GitHub 的原因

这套知识以 Markdown、JSON 和少量检查脚本为主。单条概念通常只有数 KB，完整技能卡通常也只在数 KB 到数十 KB。即使长期积累数百条，文本总体仍然很小。GitHub 可以直接提供版本、差异、来源回溯、分支隔离、Issue 收件箱和恢复点。

图片、视频、模型和大型网页不进入本知识目录。它们只保存链接、文件名、尺寸、哈希和读取范围。这样可以让知识库长期保持轻量。

## 工作流程

### 一，收件

用户提供的新资料先进入总账 Issue。每条记录写清来源、主题、目标 Mother 和当前任务关系。

### 二，研究草稿

草稿保存观察、竞争解释、公式、未知项和下一问。草稿必须标出来源事实、团队推导和待验证假设。

### 三，稳定蒸馏

经过复核的内容进入主题技能卡。每张卡至少包含输入、输出、单位、坐标、时间、状态、适用对象、拒绝范围、反例和最小试验。

### 四，生产适配

Weather、Cloud、Ocean、Coast、Landscape、材料和 B24 等生产线各自读取一张适配卡。共同函数可以共享，各对象的参数、状态和物理语义继续分开。

### 五，证据分级

状态固定分为：

1. source_logged，来源已登记。
2. source_read，原文已读。
3. derived，完成推导。
4. probe_passed，有限小试验通过。
5. product_evidence，真实产品提交证据。
6. visualAcceptance，用户视觉认可。
7. productionReady，生产条件满足。

任何前一级都不能自动提升后一级。

## 长期更新方式

小妈在实际对话和研究会话中读取资料、推导、试验并提交 GitHub。GitHub 负责保存和组织，不自行产生新的科学结论。将来确有需要时，可以只用 GitHub Actions 做 JSON、链接、哈希和目录完整性检查。自动调用外部模型需要单独的密钥、成本和安全决定，在取得明确授权前不启用。

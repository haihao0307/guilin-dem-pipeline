# 小妈世界知识实验室 V1

日期：2026年9月7日

## 决定

长期知识蒸馏以 GitHub 为主存储。当前目录位于 `haihao0307/guilin-dem-pipeline` 的协调分支 `handoff/xiaoma-mentor-v1.1-20260905`。这里保存知识、推导、来源、反例、试验设计和采用状态，不作为任何生产线的代码基线，也不整支合入生产分支。

## Make 当前状态

Make 平台已经能够执行有界研究草稿循环。正式场景为：

`6177373`

`小妈 | 世界生成长期蒸馏 V2 | 6小时有界 | Weather-Ocean`

当前结构使用一个基础触发器、持久循环编号和 GPT-5 nano 文本模块，每六小时生成一份候选研究备忘。已核实两个成功执行，具体执行 ID、失败历史和当前配置见 `STATUS.json`。

初期曾出现连接 ID 缺失、AI Agent 参数校验失败、代码模块套餐限制和临时请求频率限制。经过字段核对，当前文本模块使用有效的 `textPrompt` 输入，循环已经成功运行。

Make 只负责扩大问题空间和形成候选草稿。它没有生产访问、GitHub 写入、网页读取、图形运行或视觉验收能力。自动输出可能混用表面、体积、自由表面和材料语义，因此每一轮都要由小妈人工复核。只有通过复核的关系才能进入 GitHub 稳定知识。

## 选择 GitHub 的原因

这套知识以 Markdown、JSON 和少量检查脚本为主。单条概念通常只有数 KB，完整技能卡通常也只在数 KB 到数十 KB。即使长期积累数百条，文本总体仍然很小。GitHub 可以直接提供版本、差异、来源回溯、分支隔离、Issue 收件箱和恢复点。

图片、视频、模型和大型网页不进入本知识目录。它们只保存链接、文件名、尺寸、哈希和读取范围。这样可以让知识库长期保持轻量。

## 工作流程

### 一，收件

用户提供的新资料先进入总账 Issue #63。每条记录写清来源、主题、目标 Mother 和当前任务关系。

### 二，研究草稿

草稿来自实际对话中的研究，也可以来自 Make 的有界循环。草稿保存观察、竞争解释、公式、未知项和下一问。草稿必须标出来源事实、团队推导和待验证假设。

Make 原始输出保留在执行历史。自动草稿不会直接写进稳定知识目录。

### 三，人工复核

小妈逐条检查对象类型、单位、坐标、时间、状态、物质属性和证据边界。错误的跨域映射要明确退回，例如把云烟体积密度直接复制进 PBR 表面通道，或让云密度直接改变海面法线。

复核记录进入 `reviews/`，同时保存采用关系、退回关系和下一项单变量试验。

### 四，稳定蒸馏

经过复核的内容进入主题技能卡。每张卡至少包含输入、输出、单位、坐标、时间、状态、适用对象、拒绝范围、反例和最小试验。

### 五，生产适配

Weather、Cloud、Ocean、Coast、Landscape、材料和 B24 等生产线各自读取一张适配卡。共同函数和只读环境接口可以共享，各对象的参数、状态和物理语义继续分开。

### 六，证据分级

状态固定分为：

1. `source_logged`，来源已登记。
2. `source_read`，原文已读。
3. `derived`，完成推导。
4. `probe_passed`，有限小试验通过。
5. `product_evidence`，真实产品提交证据。
6. `visualAcceptance`，用户视觉认可。
7. `productionReady`，生产条件满足。

任何前一级都不能自动提升后一级。Make 草稿生成成功只记为候选产生，不属于上述产品证据。

## 当前重点

近期知识池包括 Houdini 的场与体积、Adobe Substance 3D Designer 的 PBR、Unreal Engine Lumen、Yohei Nishitsuji 的多尺度生成与审美、Multiscale MIP Fluid、Boids、眼球有界微动、共同时间、稳定身份和显式状态推进。

下一轮优先把这些知识分别适配到 Weather Mother 和 Ocean Mother。Cloud 重点处理包络、非负密度、输运和体积光学。Ocean 与 Coast 重点处理海面世界查询、水的光学、连续浓烟、岸体边界和资源预算。

第一条已经完成复核的跨线候选，是 Weather 与 Ocean 的只读光照接口。Cloud 通过光学厚度给出世界点到太阳的透射率，Ocean 只把它当作入射光输入，继续保护自己的波面几何、法线、粗糙度和水位查询。详见：

`reviews/2026-09-07-weather-ocean-light-interface-r1.md`

## 长期更新方式

Make 按六小时周期形成有限草稿。小妈在实际对话中读取执行结果、纠正错误、补足来源和推导，再将稳定部分提交到 GitHub。GitHub 负责保存、版本、恢复和 Mother 之间的固定知识交接。

GitHub Actions 将来只用于 JSON、链接、哈希、目录和小型公式检查。它不自行产生科学结论，也不改生产分支。任何自动模型直接写入稳定知识或生产代码，都需要另行授权和安全设计。

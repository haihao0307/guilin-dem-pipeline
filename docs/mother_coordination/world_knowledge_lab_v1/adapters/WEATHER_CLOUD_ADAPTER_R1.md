# Weather 与 Cloud 生产适配卡 R1

日期：2026年9月7日

## 目的

把近期学习的 Houdini 场与体积、Multiscale MIP Fluid、西辻陽平的多尺度生成、Substance/OpenPBR 的物质分层，以及运行时光照反馈思想，整理成 Weather Mother 和 Cloud 可以逐步实现的接口。

本卡是生产前的候选设计。它不修改当前 Weather 或 Cloud 内核，也不代表真实云物理、浏览器性能或视觉效果已经通过。

## 一，先把云分成五个职责

### 1. CloudEnvelope

负责大尺度云团在哪里、整体厚度、云底和云顶、哪些区域必须为空。

最小输入：

`cloudId`

世界空间包围范围

基准高度与厚度

大尺度形态参数

稳定种子与版本

输出 `B(x,t)`，范围零到一。它只描述云的存在范围和大形门控。

西辻陽平作品中清晰的大轮廓、负空间和尺度节奏主要进入这一层。包络先成立，细节才有依附对象。

### 2. CloudState

负责随时间推进的云状态。第一阶段可以保存粗分辨率的非负密度 `rho_sim(x,t)` 和速度 `u(x,t)`。温度、湿度、浮力、生成与消散只有在实际模型需要时再逐项加入。

状态必须有：

世界坐标或明确的局部体积坐标

模拟时间 `t`，单位秒

步长 `dt`，单位秒

速度 `u`，优先使用米每秒

检查点与版本

源项和消散项

`rho_sim` 如果尚未标定为真实质量密度，应明确写成归一化介质浓度代理，不能擅自标记为千克每立方米。

### 3. CloudDetail

负责中尺度团块、薄边、卷曲和细丝。它可以使用对数尺度、多尺度三角场、连续坐标扭曲或其他已经验证的公共函数。

第一阶段建议把细节作为由状态决定的渲染细化：

`rho_render = max(0, B * (rho_sim + A * M * D(q)))`

其中：

`A` 是唯一细节强度。

`M` 是作用门控，避免在明确空区和受保护大形外生成云。

`D` 是有界、稳定、多尺度细节。

`q` 是声明过的参考坐标或由速度场回溯得到的采样坐标。

A 等于零时，`rho_render` 必须严格回到 `B * rho_sim`。第一阶段细节只进入光学，不回写流体状态，也不改 Weather 的风场。

细节函数要保持粗层前缀。新增高频层不能重新归一化并暗改已有大尺度结构。

### 4. CloudTransport

负责云状态怎样被风带走。最小形式需要明确：

`rho_next = Advect(rho_sim, u, dt) + source - sink`

直接让 `D(x,t)` 随时间改变只能形成程序化形态变化，不能证明密度被速度场输运。

轻量路线可以先用有限体积区域、较粗状态场和较低更新频率，再让渲染细节读取同一速度或回溯坐标。需要分别检查总量、峰值、质心、边缘清晰度和成本。总量近似保持时，峰值仍可能被数值平滑抹低。

### 5. CloudOptics

负责云如何吸收、散射和遮挡光。最小关系为：

`sigma_t(x,t) = k_t * rho_render(x,t)`

`T = exp(-integral sigma_t ds)`

如果 `rho_render` 是无量纲代理，`k_t` 需要承担每米的消光尺度，并通过实际云尺寸和画面对照标定。

第一阶段至少区分：

消光

散射比例

相位方向

太阳光

天空光

观察射线

白色颜色加透明度不能承担这些职责。Substance PBR 的表面粗糙度、金属度和法线也不能替代云体积光学。

## 二，Weather 对外只读接口

Weather 与 Cloud 可向其他 Mother 提供：

`sunDirection(t)`

`sunRadiance(t)`

`skyRadiance(x,omega,t)`

`sunTransmittance(x,t)`

`windVelocity(x,t)`

`precipitationState(x,t)`，后续需要时再启用

接口必须只读。Ocean、Landscape、House 和 B24 无权通过查询反向修改 Weather 内部状态。

共同接口只传递世界环境。云的密度、消光、相位、源项、消散和内部网格继续属于 Cloud。

## 三，诊断视图

Weather/Cloud 工作台至少保留以下独立诊断：

包络 `B`

粗密度 `rho_sim`

渲染密度 `rho_render`

速度场方向与大小

源项与消散项

沿太阳方向的光学厚度

观察射线透射率

最终光照

主形诊断使用克制的灰阶或单色。最终配色后再检查日光、晚霞和阴天，避免颜色掩盖密度问题。

## 四，第一项单变量实验

对象：现有工作台中的一团云。

区域：云体内部一个固定局部范围。

固定：包络、粗密度、速度、太阳、相机、曝光、颜色、种子和时间。

唯一参数：细节强度 `A`。

状态：

A 等于零，显示 `B * rho_sim`。

A 取一个低值，只增加受门控的多尺度密度细节。

检查：

云的大片轮廓与空区是否逐值保持。

中尺度团块和薄边是否只在云体中出现。

相机移动时细节是否固定于世界或声明的云坐标。

关闭颜色强化以后，厚区、薄区和负空间是否仍然清楚。

光学积分步长变化时，总体透射是否近似稳定。

A 恢复为零以后，画面和状态是否回到同一基线。

这个实验不同时开启风、生成、消散、太阳移动或新的调色。

## 五，第二项实验的进入条件

第一项通过后，固定 A，只改变太阳方向。云的密度和轮廓保持，亮边、内部暗部和阴影随光路变化。

第二项通过后，才开启一个均匀风场。给密度团设置可追踪质心或标记，检查它是否按速度和时间移动。直接改变噪声相位、质心不移动的结果只能记作形态动画。

## 六，性能路线

优先限制计算域，只在实际云区保存状态。

粗状态场承担主运动，细节函数承担确定性的渲染细化。

空区跳过射线采样，透射足够低时允许有误差记录的提前终止。

状态更新频率、光学更新频率和画面刷新率分别记录。

禁止逐帧把完整三维场搬回 CPU。

每轴分辨率翻倍会让体素数增加八倍。任何高分辨率方案都要报告字段数量、双缓冲、临时缓冲和实际显存。

## 七，拒绝范围

拒绝用粒子球或面片堆出本轮目标云。

拒绝把程序化时间变化写成真实输运。

拒绝把云密度复制进表面 PBR 通道。

拒绝用 Lumen 或泛光掩盖密度与轮廓错误。

拒绝通过移动相机制造尺度进步。

拒绝在当前 Landscape、Ocean、B24 或其他 Mother 内核中暗改 Weather 状态。

## 八，视觉目标

画面先形成大片包络、清楚空区、厚实核心和薄边。中尺度团块与微小丝状结构共享同一坐标关系。光从薄处穿出，从厚处被遮挡，颜色服从日照和天空环境。复杂细节集中在需要解释结构的位置，画面保留安静区域。

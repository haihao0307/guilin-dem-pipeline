## 2. 核心原则

长期学习不依赖模型在后台静默改变自身权重。当前阶段采用可审计的知识积累方式：

1. 每轮从固定提交、固定问题和固定规则开始。
2. 多个 OpenAI 模型或多个隔离上下文分别探索。
3. 每个输出都形成持久 Artifact。
4. Critic 负责寻找漏洞、重复和共享偏差。
5. 小妈负责 Judgment、停止条件和资源调整。
6. Verifier 检查机器可验证约束。
7. 所有新结论先进入 Candidate Capsule。
8. 经过人工和机器审查后，才有资格进入稳定知识。
9. 冻结点永久可寻址，后续只能追加新版本。

因此系统的学习发生在证据图、问题树、知识胶囊、验证器、技能和冻结版本的持续积累中。

## 3. OpenAI 自有运行层

### 3.1 ChatGPT Project 或 Work

用于保存长期目标、讨论上下文、冻结点、用户判断和复盘。这里承担小妈的总控、知识提纯和跨领域迁移。

### 3.2 ChatGPT Scheduled Tasks

用于周期性启动有界研究、监测公开资料变化、回到固定聊天提交审查结果。任务只生成待复核草稿，不自动修改稳定知识。

### 3.3 Codex Scheduled Tasks

用于需要读取仓库、运行脚本、生成测试数据和检查差异的任务。每次优先运行在独立 Git worktree，保护本地工作区和生产分支。

### 3.4 Skills 与 AGENTS.md

Skills 保存稳定方法，AGENTS.md 保存项目级规则。定时任务只负责触发，方法本身由版本化 Skill 定义。每次修改 Skill 都要有版本、测试和回滚点。

### 3.5 GitHub 固定提交

继续承担持久证据、冻结输入、实验 Artifact、Candidate Capsule 和 verifier 结果。GitHub 属于持久存储和协作证据层，不承担 Judgment。

### 3.6 ChatGPT Memory

只保存用户长期偏好、角色关系和少量高层原则。技术真值、证明、测试结果和格式定义继续以固定 Artifact 为准，避免把难以审计的记忆当成权威来源。

## 4. 第一阶段内部训练结构

先采用少量 OpenAI AGO，控制在六个角色以内：

1. Explorer A，寻找第一性结构与最小语义。
2. Explorer B，寻找替代表示、反例和不同路线。
3. Standards AGO，检查可继承的人类标准和互操作性。
4. Evidence AGO，检查历史资料、来源依赖和污染风险。
5. Critic AGO，专门攻击方案。
6. Verifier AGO，只检查约束，不参与创意。

小妈位于这些角色之上，承担 Judgment。各角色开始阶段保持上下文隔离，完成后再进行交叉比较。

## 5. 单轮学习协议

每一轮必须包含：

1. 固定 Problem Contract。
2. 固定输入提交和来源清单。
3. 明确不能修改的冻结点。
4. 两个以上隔离探索路线。
5. 至少一个攻击型 Critic。
6. 一次 Judgment。
7. 一个最小可执行案例。
8. 一个独立 Verifier。
9. 一份 Candidate Capsule。
10. 一份暂缓项和失败记录。

任何一项缺失，该轮只能标记为 incomplete。

## 6. 推荐调度节奏

正式定时以前，先人工运行三轮。

第一轮继续使用 synthetic fixture，验证流程。

第二轮使用一栋真实云南历史建筑的小型资料集。

第三轮更换对象和资料类型，检验方案是否过拟合第一个案例。

三轮通过以后，再建立 OpenAI Scheduled Task。初始频率建议每七天一轮。每轮限制问题数量、模型调用数量、仓库写入范围和最大运行时间。

## 7. 晋级门槛

内部体系达到以下条件以后，才考虑扩大 AGO 数量或与外部模型对练：

1. 连续三个真实案例通过同一组核心 Verifier。
2. 同源复制不会增加独立证据数量。
3. 共享标定、共享假设和系统误差可以被识别。
4. Unknown、Not Observed 和 Observed Absent 在实际资料中保持区分。
5. Builder 与 Verifier 保持独立。
6. 小妈能够停止重复路线并重新分配任务。
7. 所有实验可以完整回滚到冻结输入。
8. Candidate Capsule 能够无损说明来源、假设、结果和失败边界。
9. 连续三轮没有污染生产分支或稳定知识。
10. 用户能够通过短报告理解该轮为什么晋级或暂缓。

## 8. 与外部模型对练的未来条件

Anthropic、Claude Code 和其他外部模型暂时不进入生产与长期学习主链。

未来达到内部晋级门槛后，可以建立单独的对练实验室。外部模型只获得公开或明确授权的固定输入，输出进入隔离分支，不能直接写稳定知识。对练重点是寻找我方盲点、比较推理结构和攻击验证器。

外部结果仍需经过同一套 Claim、Evidence、Provenance、Critic、Verifier 和 Judgment 流程。

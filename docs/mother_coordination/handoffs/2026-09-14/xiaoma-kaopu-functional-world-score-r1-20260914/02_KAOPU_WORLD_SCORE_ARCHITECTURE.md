# 02｜靠谱 World Score 分层架构

## A. Observation Root｜观测根

保存真实获得的数据及其边界：DEM、照片、扫描、量测、文献、历史地图、传感数据。每条观测必须带：

- 来源和许可；
- 时间与坐标系；
- 空间/时间分辨率；
- 误差和置信度；
- 覆盖范围；
- 是否可以被后续生成值替换。

原则：生成层只能补充空白，不得伪装成观测层。

## B. Object DNA｜对象身份

保存对象是谁，而不只是长什么样：

- 类型、实例和部件；
- 绝对位置与局部关系；
- 材料域与内部结构；
- 锚点、接触面和保护区；
- 能力、状态、寿命与维护；
- 与其他对象的依赖。

## C. Domain / Coordinates｜坐标与域

函数在哪个空间计算，与函数本身同等重要。候选域包括：

- 世界坐标；
- 对象局部坐标；
- 材料坐标；
- 表面切线/法线坐标；
- 沿坡、等高线和水流方向坐标；
- 对数径向/角度坐标；
- 距离场和骨架坐标；
- 随时间随形变稳定运输的材料域坐标。

域必须绑定对象身份和局部位置，不能绑定帧号或随机镜头。

## D. Function Grammar｜函数语法

由原语和组合器构成：

- 距离、SDF、波、ridge、valley、cell、crack；
- min/max/smooth-min、布尔、混合、重复、扭曲；
- 梯度、曲率、散度、拉普拉斯；
- 流动、输运、扩散、侵蚀、沉积；
- 生长、竞争、分裂、合并和停止；
- 状态转移、事件与记忆。

## E. Fields｜环境与价值场

空间中每一点可拥有多个场：

- 重力、水势、风、日照、湿度；
- 土壤深度、岩性、承载、风险；
- 可达性、地价、劳力、人口；
- 文化、产权、保护等级；
- 观察尺度和算力预算。

对象函数由这些场调制，而不是全空间均匀生效。

## F. Constraints｜约束

约束不是事后碰撞修补，而是生成过程的一部分：

- 拓扑和结构；
- 不穿透、接地、承载；
- 水力连续与质量守恒；
- 锚点和边界保护；
- 历史遗存不可随意覆盖；
- 观测真值锁定；
- 每尺度的位移预算。

## G. Interaction Graph｜交互关系图

对象对之间的关系应显式记录：

- repel：排斥/避让；
- attract：吸引/依附；
- block：阻断；
- occupy：占据；
- consume：消耗资源；
- share：共享通道或边界；
- transform：使对方改变；
- inherit：继承既有结构；
- repair：修缮；
- compete/cooperate：竞争或协作。

## H. Process / Event / History｜过程、事件和历史

世界必须同时保存：

- 连续变化；
- 突发事件；
- 人工维护和修复；
- 废弃和再利用；
- 路径依赖；
- 能解释当前痕迹的历史摘要。

## I. Scale Spectrum｜尺度谱

每个对象都有明确的尺度职责和幅度预算：

- 低频：身份和主体；
- 中频：结构和形成过程；
- 高频：材料、风化和局部状态；
- 超高频：只在观察和性能允许时展开。

高频必须服从低频，不得推翻已验证的主体。

## J. Evaluator / Compiler｜求值器与编译器

根据观察位置、用途和设备，把乐谱编译为：

- 几何或隐式表面；
- PBR 与颜色；
- 碰撞和导航；
- 动画与行为；
- 声音；
- LOD、缓存和流式数据。

同一乐谱可以有多个演奏器，但对象身份和状态必须一致。

# TLO DNA 核心定义 R0.1

状态：候选。尚未冻结二进制编码、文件扩展名、序列化方式和最终 schema。

## 1. 三个核心字母

`T = Time`

`L = Location`

`O = Object`

时间是第一坐标。Location 描述对象处在世界的哪里。Object 描述“是谁/是什么”以及对象 DNA、状态和关系。

## 2. 为什么称为 4D 文件

用户给出的核心分类是：

- TXT 可以视作一维顺序信息的典型文件；
- PNG 是二维图像；
- OBJ 是三维几何；
- TLO DNA 要把时间作为第一等坐标，与三维空间共同组成四维世界描述。

因此候选基本空间为：

`(t, x, y, z)`

对象 `O` 在这个四维世界中拥有持续身份、状态和关系。

这里的“四维”首先是世界描述维度，不代表必须把所有数据展开成稠密 4D 体素，也不代表 Object 是第五维。

## 3. 文件的本体不是“画出来的结果”

TLO DNA 不以最终网格、像素、贴图或某个软件工程文件作为世界本体。

它应当优先保存：

- 时间和时间语义；
- 地理/空间位置和参考系；
- 对象稳定身份；
- 对象所需的最小状态；
- 真实来源和约束；
- 对象之间的关系；
- 能够重新生成可观察结果的函数或规则；
- 适用精度和证据等级。

渲染网格、GPU buffer、图片、3GS、OBJ、GLB 等都可以成为输入、缓存或编译产物，但不是 TLO DNA 必须长期保存的唯一真相。

## 4. 时间必须进入对象生命周期

同一个对象要能够回答：

`O(t, L)`

或更具体：

`query(objectId, t, location, precision, context)`

对象可以随时间移动、成长、老化、维护、损伤、修复、改变状态，但稳定身份不能因为相机、分辨率或渲染方法变化而漂移。

## 5. Location 不是只保存一个 XYZ

L 至少要说明：

- 世界参考系/CRS 或局部参考系；
- 当前或有效空间位置；
- 方向/姿态（对象需要时）；
- 所属容器、区域或空间关系；
- 位置的不确定性和来源（需要时）。

对于固定地理对象，L 可以与 canonical truth 绑定。
对于动物、飞机、水体状态等动态对象，L 可以是随 T 推进的状态。

## 6. Object 是身份与可重建能力

O 不等同于一个 mesh。

O 至少可以关联：

- `objectId`
- `objectType`
- `objectDNA`
- `state`
- `constraints`
- `relations`
- `history/events`
- `evidence`
- `functions`

对象内部可以继续拥有部件 DNA；当部件具有独立历史、替换、行为或关系意义时，可以升级为独立 Object。

## 7. 当前设计目标

TLO DNA 首先解决的不是“怎样比某个 3D 格式多装几个字段”，而是：

**怎样让人和机器把一个世界事实用最少、最清楚、可验证、可继续计算的关系传下去。**

目标是降低：

- 对话上下文丢失；
- 跨窗口遗忘；
- 多 Mother/多执行器之间的语义漂移；
- 重复解释；
- 把渲染结果错当世界真值。

## 8. 与 World Kernel 的关系

TLO 更接近 World Kernel 的交换/存储语言候选。

World Kernel 已有顺序：

`Time -> Identity -> Truth/State -> Strategy -> Precision -> Query -> Function -> Evidence`

TLO 将其中最根本的世界索引压缩成：

`Time + Location + Object`

然后 Object DNA 再承载对象内部的真值、状态、结构、材料、行为、函数和证据。

## 9. 当前不要冻结的部分

以下还在讨论，不能冒充已经定稿：

- 最终文件扩展名；
- 文本/二进制/混合容器；
- chunk/index 结构；
- 事件与连续状态怎样编码；
- Location 的全球统一坐标合同；
- Object relations 的最小关系集合；
- 压缩、随机访问和流式传输方式；
- 与 WebGPU runtime 的编译合同。

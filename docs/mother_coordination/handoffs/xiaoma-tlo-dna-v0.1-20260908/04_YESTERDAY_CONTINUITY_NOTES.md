# 2026-09-07 至 2026-09-08 连续性笔记

本文件只记录已确认的核心方向，供新 Codex 窗口恢复上下文。

## A. 世界计算哲学

用户反复强调“省力”是系统设计核心。人脑以很低功耗选择性处理重要信息，工程系统不应把所有地点、所有尺度、所有对象同时算到最高精度。

目标不是让世界少存在，而是让世界只保存身份、因果和重建所需的最小状态；观察、交互、物理、叙事等请求决定当前展开深度。

成熟经验最终写成函数。新问题第一次可以重研究；验证后形成函数；以后直接调用；只有超出有效范围才重新高成本思考。

## B. 工具蒸馏

3GS、Blender、Houdini、Substance、Unreal、WebGPU 都是阶段性工具和知识来源。长期系统只吸收它们的坐标、状态、依赖、函数、材质、体积、测量、误差和计算调度思想，不把任何一套软件格式当世界终点。

## C. Object DNA

对象不应该永久保存全部表象。对象保存足以维持身份、结构、状态、关系、材料、行为、证据和重建能力的最小关系。

Aircraft AN/M2 方法被用作第一批真实蒸馏案例：来源网格是证据，不是产品本体；测量工具可替换；长期留下语义约束、可读配方和证据。

Farmland Object DNA 已建立启动框架；细知识由其专业执行者继续自查和学习。

## D. Weather / Ocean / DEM

Weather/Cloud 与 Ocean/Coast 已分别建立知识包。Cloud 需要把 Envelope、State、Detail、Transport、Optics 分层。Ocean 把海床真值和时间相关海面状态分开。

温州 DEM 新方向：清理旧 Weather/旧 Ocean 表面等活动运行时残渣；保留真实陆地 DEM、海底、水文、海岸、潮汐来源与 QA；未来 DEM 内核只负责 canonical truth、约束、多尺度重构和查询。

## E. 感知带宽

世界不应以“预先做多套 LOD 资产”作为本体。更接近的概念是观察/感知带宽：同一对象根据当前屏幕足迹、注意、交互和物理需求逐渐展开不同频带。高频细节应集中在有意义的地方，画面要有视觉休息区。

## F. TLO 新议题

2026-09-08 对话转向自有文件格式：

- T = Time
- L = Location
- O = Object
- TLO DNA 被用户定义为四维文件；
- 与 TXT/PNG/OBJ 的比较只是说明它的世界维度定位；
- 核心目标是人机交流高效、准确，中间信息不要流失；
- 对话必须定期 markdown checkpoint 并重读，避免十几分钟后上下文断裂。

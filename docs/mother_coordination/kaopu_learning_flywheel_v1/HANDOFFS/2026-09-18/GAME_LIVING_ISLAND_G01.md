## 3. 第一项 Game 实作：有行为的彩色鱼群，保留既有捕鱼事务

先在现有湾内做一个能观察、靠近、惊散、再聚集的接续增量，再扩充分布。延续用户“20 组”目标：20 组可辨认的配色/大小/栖息区组合，共享少量已验证行为模板；不是为了数量宣称 20 个真实物种，也不是复制 20 套模拟器。

| 游戏行为模板 | 运动/交互设计 | 说明 |
|---|---|---|
| 小型成群鱼 | 较强邻域聚合/对齐，保持间距；接近时局部受惊向群体传播；危险过去后逐步回群 | 转向/速度按模板调，不把所有小鱼都规定成高速鱼 |
| 中型礁栖鱼 | 小群或短距离游走，绕礁、停留、觅食样动作，记住活动区 | 是有边界的设计行为，不凭噪声轨迹宣称觅食生态已验证 |
| 大型巡游鱼 | 更大身体净空/转弯半径，较疏的队形、长游程，游速有加减速 | 大鱼不等于捕食者；只有明确标记捕食角色的模板才追逐小鱼 |
| 鸟 | 海面上方群飞、盘旋、滑翔/振翅交替；树冠鸟另用停栖/短飞状态 | 共用邻域方法，不能把鱼的水下运动直接复制到天空 |

占位鱼也应有可辨认的头尾、鳍和三维体量；颜色按背/腹/侧纹/鳍组织，并允许同群个体变化。尾摆与游速、转向连续相连。先用程序形态，不等待写实物种资产。金刚鹦鹉/天堂鸟式色彩可作原创岛屿设计候选，不自动记为帕劳原生动物。

必要接续条件：

1. 沿用稳定 fishId/groupId、worldTime 和坐标框架；位置/速度/行为/随机状态须可保存或确定性恢复。鱼捕获后沿原事务移入背包，同一 fishId 不再运动/渲染/领奖。现有刺捕不能变成完好放生奖励；未来垂钓与放生另设可核查动作。
2. 使用共同海面/海床/岩体查询。当前 host.water 主要提供 eta，不能由海面高度自行猜出已验证三维海流。没有可靠流速时显式用自主游动候选，不伪造流场物理耦合。
3. 大鱼需要身体净空，不只检测中心点。水面与海床间隙不足时区域不适宜生成/通行，不能用互相冲突的 min/max 强夹 y 值掩盖。现有高度场不表达悬洞；对真实拱洞/礁洞要有相应三维几何与接触查询，不能把贴黑或保守盒说成精确洞穴。
4. steering 避障不保证不穿透。候选下一位置需校核运动路径、净空和允许步长，失败时退回可行状态并记录原因。对未知/不支持的洞穴通行先限制在已支持区域，不能另造一套不可见海床。
5. 第一版优先简单可核查的邻域实现。空间桶按物理邻域查询、精确距离筛选；仅当桶边长不小于最大查询半径时，3D 的 27 个相邻桶才充分。密集桶仍可能退化到平方开销。小场景和全对全参考比较邻居集合，再测实际规模。
6. 保留用户已禁用 LOD/远近粗细替换的要求，不换名恢复。可用实例化、共享缓冲、固定时间步、正确空间索引和有完整依赖的缓存节约开销；相机距离不能改变对象身份、可捕获状态、世界事实或鱼群规则。不能把增鱼目标降成“远处贴一片鱼”。
7. 画面丰富来自群的分布、层次、大小、节奏与礁区关系；不是盲目铺满每一立方米。高密度区域和留白共同安排。数量上限由实际目标设备测试决定，不凭 GitHub 演示人数承诺手机性能。

本增量需返回：当前继承 SHA/改动路径、固定候选入口、群体受惊与重聚的实际运行记录、连续运动中的水/礁碰撞检查、已有鱼叉与同鱼重复捕获保护、读档/过夜/暂停恢复结果。性能报告区分桌面、手机视口与真实手机；视觉接受仍由用户判断。测试和普通入口保持同一表示，不做 QA 专用降质。

## 5. 珊瑚与植物：分清部件，不增加相互竞争的世界

## 6. 半年生存与无线电：让回家成为长期推进线

保留现有“损坏装置属于筏上物品”的事实；故事设计候选：

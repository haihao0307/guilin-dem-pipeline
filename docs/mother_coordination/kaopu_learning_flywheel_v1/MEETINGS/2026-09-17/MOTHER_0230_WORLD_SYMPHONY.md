## “总谱—声部—乐器”最小共同语言

本次不冻结新大格式，只保留五个可检查术语：

1. **表达总谱（Intent Score）**：主题、历史、情绪、生活重点、观察节奏与允许的艺术取舍。它决定要表达什么，不能篡改Canonical Truth或冒充观测事实。
2. **共同状态（Shared State）**：带时间、地点、对象身份、单位、版本和来源的可续接事实/候选状态，例如地形、降雨、渠水位、田块水深、土壤含水与劳作阶段。
3. **声部职责（Part Ownership）**：每个Mother明确读取什么、拥有并更新什么、只观察什么。共享变量不等于多方同时改写。
4. **形成过程（Process Relation）**：水流、侵蚀、沉积、耕作、修缮、踩踏、生长等带方向与时间的因果候选；函数/噪声只是表达或求值工具，不能凭相似外形宣布真实成因。
5. **演奏器（Evaluator/Instrument）**：Microscope、Shader、网格、缓存和LOD把状态编译成形态、材质、行为和显示；它们有预算与误差，但不是新的世界真值。

证据等级、Mother实现、浏览器/设备运行和用户视觉接受继续与上述五项分开。

## 有限例：“农田—田埂—水—土壤—人的生活”

一个可工作的候选依赖链是：

`Weather降雨/蒸发 → Landscape地形、集水与流向 → Farmland水源/渠/单田控制体 → 田埂水位差与进排水口 → 土壤含水/踩踏/维护历史 → Microscope真实微形态 + Shader光学响应 → 人与水牛的可行路径及生活场景`

职责限定：
- Landscape提供冻结地形真值上的坡向、集水、谷/脊和承载表面；不凭视觉噪声改写DEM真值。
- Weather提供有单位和时段的环境输入；一张湿润颜色不能充当降雨量。
- Farmland拥有田块、共享田埂、水口、渠网、单田水量/容量及劳作关系；R042的连通图是候选基础。
- Microscope在已声明的材料/过程状态上生成宏—中—微形态；不能决定田块拓扑或把随机凹凸称为侵蚀历史。
- Shader读取材料、湿度、粗糙度、光照与观察条件生成视觉响应；深色外观不等于水质量，漂亮画面不等于水路正确。
- 人与水牛的行为读取可通行田埂、任务与水状态；数量与动画不证明生活关系已经成立。

共享的最小状态应先限于：`terrainRef, fieldId, bundId, waterNode/edgeId, time, waterLevel/depth, soilMoistureCandidate, cropStage, accessState, provenance/version`。具体单位、守恒式、更新责任与误差仍需在下一题核对，不能把字段列表当成已经完成的接口。

## 真实分歧与决定

1. **情绪是否直接写入物理状态？**
决定：不直接写入。情绪/叙事属于表达总谱，可选择季节、镜头、节奏、声音和强调层级；若要改变水量、地形或历史事件，必须成为显式、可追溯的设计事件，不能暗改真值。

2. **所有声部是否共享同一个巨大状态表？**
决定：只共享身份、单位、时间、来源和必要接口；各Mother保留自己的详细状态与版本。一个万能表会混淆所有权，也会使未知值被默认补造。

3. **多尺度噪声能否统一解决形态与材质？**
决定：它可作为共同乐器和空间组织方法，但拓扑、守恒、材料成因与历史顺序必须由对象关系和过程状态提供。Landscape Y04说明安全求值本身还可能消掉绝大多数形态能量。

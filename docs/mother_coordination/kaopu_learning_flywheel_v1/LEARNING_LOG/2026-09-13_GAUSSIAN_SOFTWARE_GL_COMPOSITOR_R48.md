# R48 bounded learning cycle — Gaussian software-GL compositor

## Question

Does an actual raster/blend backend preserve the R47 two-splat result, and is either continuous CPU arithmetic or naive per-draw `RGBA8` rounding an exact pixel oracle?

## Evidence status

- **Observation:** pinned Three.js r186 supplies the Gaussian cutoff, kernel/alpha, color and normal non-premultiplied blending semantics already locked in R47. This is the same source lineage, not a new independent Observation Root.
- **Candidate executable evidence:** the R48 probe created an EGL 1.5 surfaceless context, executed an independent desktop OpenGL shader plus fixed-function blending on Mesa llvmpipe 25.2.8, read back a `33×33 RGBA8` framebuffer, and compared it with continuous and per-draw-quantized CPU oracles. Two runs were byte-identical; result SHA-256 is `6ea09fcb611c8b37d9ff1ad9c5623c8e900ad25ed31f1f808e6ad9669b7d0264`.
- **Unknown:** direct Three.js TSL-generated shader execution, WebGL/WebGPU backend behavior, hardware GPU behavior, browser output transforms, Safari/iPhone limits, learned assets, real photos and human acceptance.

## New or corrected knowledge

1. The llvmpipe framebuffer preserved a material combined difference: maximum channel difference `0.0823529` (`21/255`) versus R47 continuous CPU `0.0851303`. Their reported maxima differ by `0.00277734`; the synthetic CPU value is not an exact framebuffer value.
2. Backend-versus-continuous maximum absolute error was `0.00497459` for the reference and `0.00537919` for the candidate. Respectively 14 and 11 channels exceeded one `RGBA8` code relative to the continuous oracle.
3. A naive CPU oracle that rounded after each draw matched the reference within one code, but the candidate still reached a two-code difference across 85 channels. This is a concrete counterexample to assuming that one generic UNORM8 rounding model exactly reproduces fixed-function blending and shader float behavior.
4. Center pixels remained diagnostically different: reference `[97,9,9,183]`, candidate `[76,9,9,183]`. Equal quantized alpha at that pixel does not prove equal continuous alpha or equal images.

## Counterexamples and boundaries

- **Rejected:** “R47 continuous linear pixels are exact `RGBA8` backend predictions.”
- **Rejected:** “rounding every CPU blend result to `RGBA8` guarantees one-code equivalence on this backend.”
- **Preserved:** R47's qualitative conclusion that combined DC/order/ellipse behavior can be material and non-additive.
- The shader independently re-expresses the fixed equations; it was not generated by Three.js TSL. llvmpipe is a software renderer, not evidence about a hardware GPU or target device. The two-code envelope is fixture-specific, not a perceptual or production threshold.

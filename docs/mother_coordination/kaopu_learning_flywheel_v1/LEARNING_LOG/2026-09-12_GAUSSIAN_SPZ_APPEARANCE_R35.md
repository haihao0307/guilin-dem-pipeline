## Observation

### O-R35-1 — opacity byte handoff is exact, but source opacity remains quantized

The pinned Niantic encoder realized every requested opacity byte, and Three r186 exposed all 256 alpha bytes with maximum byte error `0`. This proves the narrow packed-byte handoff for the synthetic matrix.

It does not prove source-logit or appearance fidelity. SPZ maps the source logit through sigmoid and an 8-bit quantizer; sufficiently extreme logits become byte endpoint 0 or 255. The candidate gate reports those endpoints for later error budgeting.

### O-R35-2 — Three r186 clamps 120 of the 256 valid SPZ DC bytes

The pinned SPZ source uses `colorScale = 0.15`, deliberately smaller than SH C0, so DC values can represent colors outside `[0,1]` that higher spherical-harmonic terms may bring back into range. The pinned Three loader converts that DC coefficient to linear RGB and writes it into `Uint8ClampedArray` storage.

The exhaustive fixture measured:

- packed bytes `0..59`: converted DC is below zero and becomes byte `0`;
- packed bytes `60..195`: no r186 DC clamp;
- packed bytes `196..255`: converted DC is above one and becomes byte `255`;
- clipped domain: `120/256` possible SPZ DC bytes;
- non-clipped domain: `136/256` bytes;
- maximum linear base-color clamp error at the endpoints: `0.44031597257959376`.

The r186 LUT itself matched the source-defined calculation with maximum output-byte error `0`; the incompatibility is the representable domain, not an unexplained arithmetic mismatch.

### O-R35-3 — r186 float PLY loading is not an appearance-fidelity bypass

The actual r186 PLY loader was executed with float `f_dc` coefficients `-3` and `+3`. It also produced color bytes `0` and `255`. Retaining float PLY remains necessary as the reconstruction checkpoint, but viewing that PLY through this r186 loader does not preserve out-of-range DC for later SH compensation.

### O-R35-4 — early DC clamp and post-SH clamp are not equivalent

Pinned `GaussianSplat.js` unpacks the already-clamped base color, then adds higher-order SH and clamps the final RGB. A CPU arithmetic counterexample produced:

- DC `-0.2`, SH contribution `+0.3`: source-order result `0.1`; early-clamp result `0.3`;
- DC `1.2`, SH contribution `-0.3`: source-order result `0.9`; early-clamp result `0.7`.

This proves non-equivalence of the operation order. It is not a GPU, perceptual or real-reconstruction measurement.

## Candidate

### C-R35-1 — appearance compatibility gate

Add `ADAPTERS/gaussian_spz_appearance_gate_r35.mjs` before labeling an SPZ/r186 derivative appearance-preserving. It:

- rejects non-finite or mismatched DC/opacity arrays;
- reports DC coefficients that the SPZ packer would saturate;
- reports source DC values whose quantized SPZ byte lies outside the Three-safe range `60..195`;
- reports opacity values that quantize to endpoint bytes.

For a future real reconstruction, record a DC-byte histogram and all gate counts. A source outside the safe domain may still be evaluated as an explicitly lossy presentation derivative, but it cannot be called numerically preserved without a separately accepted fixed-view error budget.

## Current Best View

# GAEA Study R01 — 2026-09-09

Question: Which GAEA 2.3 workflow mechanisms can improve KAOPU continuous learning and world generation without contaminating Canonical Truth?

Status: Candidate. Primary-source-backed where noted. Older GAEA documentation is retained as historical/behavioral evidence and requires current 2.3 verification before promotion.

## Primary-source observations

- Current Production Ready download is GAEA 2.3.0.1, released 2026-05-13. GAEA 2.3 adds Macros, advanced automation, improved Regions, and large-scale-world workflow support.
- QuadSpinner explicitly separates Production Ready from Bleeding Edge and promotes experimental work only after it matures. This is directly compatible with KAOPU Candidate vs Frozen governance.
- Official tiled/distributed build documentation states that buckets are processed independently and therefore do not naturally interact with neighbors. Blending is used to hide or reconcile edge differences, and higher blending increases memory/build cost.
- TileGate workflow marks operations that are not safe for tiled evaluation. This is a strong analogue for KAOPU operator capability declarations: local/tile-safe vs global/context-dependent.
- Official Erosion documentation exposes a Deterministic mode that trades parallel throughput for repeatability. The general transferable principle is that deterministic verification and high-throughput production are distinct operating modes.
- Selective Processing changes causal drivers such as precipitation, erosion strength, or rock softness rather than merely masking the final shape. This suggests a KAOPU rule: where possible, modulate typed operators/forcing before output composition rather than cosmetically clipping the result.
- Multipass erosion separates stages with different purposes. This supports KAOPU's multiscale structure: stable low-frequency form plus staged/local higher-frequency processes instead of one monolithic procedural function.

## Candidate transfers to KAOPU

1. Operator capability metadata
   - Every world-generation operator should declare whether it is local/tile-safe, neighborhood-dependent, global, deterministic, stochastic, time-dependent, or residual-bearing.
   - A conductor must not schedule a global/non-tile-safe operator as though it were independently evaluable per page.

2. Verification mode vs production mode
   - Keep an exact/reproducible mode for evidence and regression.
   - Permit faster parallel/stochastic modes only when their allowed variation is measured and declared.

3. Cause-space modulation
   - Prefer changing precipitation/forcing/material susceptibility/domain parameters before simulation.
   - Avoid post-hoc masks that make a visually plausible result while breaking process meaning.

4. Shared-edge is semantic, not cosmetic
   - GAEA tiled-build caveats reinforce that edge handling is part of the computation contract.
   - KAOPU must not accept seam blending as proof of shared truth continuity.

5. Reusable subgraphs
   - GAEA 2.3 Macros suggest a useful packaging model for validated KAOPU operator subgraphs, but each macro-like unit needs source, version, parameters, invariants, test fixtures, and failure boundaries.

## Do not promote yet

- Exact behavior of older Erosion/TileGate documentation under GAEA 2.3 must be rechecked before treating implementation details as current.
- GAEA's artistic goals are not equivalent to Canonical Truth reconstruction. A mechanism can be useful while its output is unsuitable as evidence.
- Blending/hiding seams is not acceptable as a replacement for KAOPU shared-edge truth.

## Routing recommendation

- Wenzhou/Terrain Mother: operator tile-safety declaration, deterministic verification mode, shared-edge gate.
- Landscape Mother: cause-space modulation and staged/multipass field construction.
- Weather/Ocean: investigate whether forcing-field modulation can replace cosmetic output masks in selected processes.
- All procedural Mothers: consider reusable validated subgraphs only after provenance and invariant registration exist.

## 关键纠偏

1. 不把视频里的“累积距离”擅自解释为沿河里程、汇流面积或累计流量。作者相关记录说的是不同生成层级的距离组合，具体集合、权重、节点实现仍不明。本轮自己的两级累计集合试验是说明信息差异，不是还原作者公式。
2. 不因画面像河谷就声称地形侵蚀、水流或地质正确。几何位置不包含流向、进出水、守恒或河口边界条件。
3. 不因有真实位移就声称获得完整独立树木、房屋或可耕作田块。真位移能改变表面，但单值高度表面没有同时表达地面和上方树冠底面的能力。森林能否走入、房屋是否有内部空间、碰撞和物体身份必须另验。
4. Voronoi颜色区与实际田块拓扑不同。视觉边界不自动产生相邻田块、可行走田埂、渠口或灌排路径；季节材质滑块也不是种植过程模拟。
5. 视频中的抽象河网先生成地形可作设计型场景试验，不能用于覆盖本项目已认可的12.5m DEM或手工补造真实河流。真实地形线只能从已许可资料读关系，缺失就保留Unknown；试验副本和合成CPU例子必须与真值分开。

## 与Y01/Microscope的关系：候选架构，不冒充作者共同体系

本轮补充的是“哪些地方该出现哪类结构”的关系层。Y01讨论的多尺度函数需要读取关系层，而不是在整座山上均匀加同一种粗糙度。

建议的有限组合：冻结/合法基底 -> 明确身份和来源的关系数据 -> 主河/支沟/坡面/田块等分区和方向 -> 材料专属的中小尺度场 -> 实际表面或对象表示 -> 观察层采样与着色。

输入至少区分到几何的欧氏距离、分支层级、沿图距离和真实水文量；各有单位与语义，缺哪项不可用另一项偷偷替代。地形分类可以使用明确标为基底的坡度/法线，最后着色使用最终表面法线；不能把两种尺度的坡度混成一个字段。

几何、材质和对象分布读取同一稳定空间映射及区域身份。域扭曲若只在着色器内做，画出的田边可能与田埂、碰撞或路径不同。只有warp可逆、区域无自交、边界/锚点满足约束并有稳定ID，才可由视觉细胞进一步研究真实田块；本轮未完成这些几何验证。

远景可以使用有界代理表示，但必须对应相同世界对象/区域，近景不能重新撒随机种子创造另一片田。相机只改变观察近似，不改变河网、田块身份或已冻结地形。

## 实际做过的三个CPU例子

见 `../PROBES/terrain_relation_probe_t01.py` 及结果JSON。已在本轮实际执行，3/3通过；都是自构代数/关系反例，不是三个独立地质观测或项目验收。

A：主河点和支河点到整个河网的最近距离同为0。明确选定的两级平均距离却分别为0和1.5m，说明单一最近距离丢失层级信息。这个构造没有证明沿河纵坡正确。
B：把同一河网的所有边方向反转，采样的最近距离变化为0；源点能否沿有向边到出口却从True变为False。因此单有距离场无法恢复有向连接，更谈不上真实流量。
C：对两个简单田块标签施加可逆剪切域变换。让几何读取变换后的坐标、材质读取变换前坐标，会在测试点得到相反田块标签；两者读同一域则一致。这个例子只验证域错配，不验证一般田块分割。

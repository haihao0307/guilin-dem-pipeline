## Current observations

### O1 — Erosion2 determinism is current, but it is not a claim of cross-resolution identity

Current Erosion2 documentation explicitly states that Erosion2 delivers deterministic results. However, GAEA's current Non-Determinism documentation separately explains that procedural output may change when resolution changes, and that this can remain unavoidable even when algorithms reduce the difference.

Therefore the safe interpretation is:

- deterministic at a fixed evaluation contract is a supported current behavior;
- deterministic does not mean invariant across resolution, grid, or evaluation context;
- a bare `deterministic: true` flag is semantically insufficient for KAOPU.

### O2 — Current tiled-build documentation confirms the underlying TileGate problem without confirming the old TileGate implementation

Current Tiled Builds documentation gives explicit failure classes for isolated tile evaluation:

- frame/screen-dependent generators or transforms;
- large-scale filters whose support extends outside the tile;
- per-region normalization, auto-leveling, or equalization;
- any operation that needs context beyond the current chunk.

The documented remedy is to bake tile-unfriendly world-stage work into a stable base, or evaluate with a larger Hybrid bucket/context, and reserve tile-friendly high-frequency work for the local detail stage.

Current node pages also explicitly mark some nodes as requiring baking in Hybrid/Tiled builds. This verifies the *concept* of locality/context capability in current GAEA.

A current official `TileGate` reference page or current exact legacy TileGate semantics was not found in this bounded round. Therefore the old node/name-specific claim remains Unknown and must not be promoted.

### O3 — Regions preserve graph identity across resolution windows

Current Regions documentation says the overall landscape and an isolated high-resolution Region are developed through the same procedural graph, so graph changes keep the versions synchronized.

For KAOPU, the transferable idea is not GAEA's artistic upscaling itself. It is the identity rule: a high-resolution region should normally be a different evaluation/view of the same world process and score, not a new truth object or independent Observation Root.

### O4 — Official migration advice implies a version-change evidence gate

GAEA 2.3 release notes say 2.2 production projects should generally move to 2.3, but still strongly recommend testing one or two projects to ensure the pipeline holds.

Transferable rule: vendor compatibility statements are not sufficient for Frozen promotion. Tool/operator version changes require regression fixtures against locked inputs and declared tolerances.

## Candidate KAOPU transfer R02

### 1. Replace node-name dependence with an operator context signature

Every typed-wave or process operator should declare at minimum:

- `contextScope`: local | neighborhood | global
- `contextRadius` or required halo where meaningful
- `normalizationScope`: none | local | page | region | global
- `seedScope`: sample | tile/page | region | world
- `boundaryPolicy`
- `determinismContract`: version + resolution/grid + seed + context + execution mode
- `timeDependency`
- `residualRequired`

A scheduler may independently evaluate a page/tile only when the declared context is actually available. Otherwise it must evaluate/bake the upstream global stage or supply sufficient halo/context.

### 2. Determinism must be scoped, not boolean

KAOPU should reject unqualified statements such as `deterministic=true`. Reproducibility claims must name the evaluation contract. Cross-resolution equivalence is a separate property and requires its own evidence.

### 3. Separate world stage from detail stage

Use a world-consistent stage for global structure, global normalization, and context-heavy operators. Use a local/detail stage only for operators proven safe under the declared halo/context. Presentation blending can hide seams but cannot prove truth continuity.

### 4. Region views should preserve world identity

A focused high-resolution region is a view/evaluation window of the same world score unless independent evidence creates a new claim. Resolution change alone never creates a new Observation Root.

### 5. Version migration is a regression event

Any change in GAEA/Houdini/Substance/UE/Blender/3ds Max or an internal operator implementation that can alter outputs must trigger a fixture-based regression check before Frozen knowledge or a production contract is updated.

## Epistemic disposition

- Observation / current-primary-backed: GAEA 2.3.0.1 current release identity; current Erosion2 deterministic claim; current tiled-build context failure classes; current Regions same-graph synchronization; official migration-testing recommendation.
- Candidate: KAOPU operator context-signature schema and world-stage/detail-stage scheduler rule.
- Unknown: exact current behavior/existence of the older `TileGate` implementation as previously described.
- Rejected: interpreting `deterministic` as resolution-invariant; treating seam blending as proof of shared truth; treating a high-resolution region as an independent evidence root merely because its resolution differs.

## Question

Which modern procedural-noise and field-composition practices are measurably better than the current KAOPU typed-wave primitives for multiscale natural structure?

## Logical correction before adoption

The phrase “better noise” is underspecified. A newer or more complex noise basis is not automatically better. Current mature tools expose several bases and several octave-composition laws precisely because suitability depends on the downstream task: derivative quality, tiling, bump/normal use, morphology, runtime cost, temporal stability, and sampling footprint. Therefore this cycle does not rank Perlin, Simplex, Worley, wavelet, fBM, ridged, or hybrid methods with one global score.

The more defensible question is: which missing evaluation contracts or composition semantics make a procedural field measurably more stable, reproducible, and task-appropriate?

## Primary-source observations

### O-NOISE-R01-EPIC — evaluation footprint and cost are explicit

Official Unreal Engine 5.8 Utility Material Expressions documentation exposes a `FilterWidth` input on the Noise expression and describes it as controlling blur applied to the noise. The same documentation separates multiple noise functions by direct-use quality, bump suitability, tiling behavior, texture lookups/instruction cost, and octave count; Levels multiply computational cost. Vector Noise includes Perlin Gradient and Perlin Curl, and Epic recommends baking expensive vector noise after the look is developed.

Source: https://dev.epicgames.com/documentation/unreal-engine/utility-material-expressions-in-unreal-engine

Transferable point: sampling footprint / filtering policy and evaluation cost belong in the operator contract. “Noise(position)” alone is not a sufficient runtime interface for a multiscale field used across camera distances or page resolutions.

### O-NOISE-R01-SIDEFX — derivatives and field semantics are first-class

Current SideFX VEX documentation lists `gxnoised` and `xnoised` as Simplex-noise derivative evaluations, and describes Simplex noise as reducing grid artifacts and using a higher-order B-spline for better derivatives. It also exposes curl-noise families for divergence-free fields and flow/periodic variants.

Source: https://www.sidefx.com/docs/houdini/vex/functions/

Current SideFX Curl Noise documentation treats curl as a vector-field semantic, not merely a visual scalar texture; the operator can account for intervening geometry via surface-distance and normal information.

Source: https://www.sidefx.com/docs/houdini/nodes/vop/curlnoise.html

Transferable point: value, gradient/derivative, curl/vector semantics, periodicity, and required geometry/boundary context should be explicit capabilities of a typed operator. Derivatives should not be silently reconstructed downstream when the basis can provide them directly.

### O-NOISE-R01-BLENDER — basis and octave composition are separate choices

Current Blender 5.2 LTS Noise Texture documentation distinguishes fBM, Multifractal, Hybrid Multifractal, Ridged Multifractal, and Hetero Terrain as different ways to combine octaves. fBM adds octave values; Multifractal multiplies them; Hybrid uses both addition and multiplication; Ridged applies an absolute-value/inversion construction; Hetero Terrain has a different heterogeneous composition. It separately exposes Detail, Roughness, Lacunarity, Offset, Gain, Distortion, dimensionality, and normalization.

Source: https://docs.blender.org/manual/en/latest/compositing/types/texture/noise.html

Transferable point: the base noise basis and the octave/spectral composition law are distinct operator properties. A KAOPU record that stores only basis + frequency + amplitude + octave count loses meaningful behavior if it does not also preserve how octaves are coupled.

### O-NOISE-R01-PIXAR — band limiting is a correctness issue, not cosmetic blur

Cook and DeRose’s Wavelet Noise paper analyzes aliasing and detail loss in classic procedural noise and proposes an almost band-limited wavelet-noise construction. The paper is older than the current DCC documents, but it remains primary research evidence for the underlying sampling problem. Its importance here is not “replace KAOPU with wavelet noise”; it independently supports the need for a sampling/filter contract.

Source: https://graphics.pixar.com/people/derose/publications/WaveletNoise/paper.pdf

### O-NOISE-R01-NVIDIA-2023 — stochastic evaluation is scope-limited

Fajardo and Pharr (2023) show that procedural-noise weighted sums can sometimes be estimated stochastically at lower cost in Monte Carlo rendering. This is relevant to path-traced shading, but does not establish that stochastic evaluation is appropriate for canonical world state, deterministic simulation, collision, hydrology, or other stateful Mother logic.

Source: https://research.nvidia.com/labs/rtr/publication/fajardo2023noise/

Disposition: Parked as a renderer-specific candidate, not routed as a general KAOPU world-generation rule.

## Comparison against current KAOPU typed-wave primitives

The current KAOPU “造波” vocabulary already includes basis wave/noise, phase, frequency, amplitude, direction, rotation, scale, domain transforms, modulation, coupling, seed, time evolution, boundary conditions, and required residual. That vocabulary should not be replaced wholesale.

This cycle identifies four missing or under-explicit contracts that are more important than adding another fashionable basis:

1. **Evaluation Footprint / Filter Policy** — declare the spatial/temporal footprint at which a field is being evaluated and the policy for suppressing frequencies that cannot be represented at that footprint. This separates world structure from sampling artifacts.
2. **Differential Capability** — declare whether the operator natively provides gradient, Jacobian, curl, divergence-related construction, or only scalar/vector values; record derivative continuity/quality expectations.
3. **Spectral Composition Law** — distinguish additive fBM from multiplicative/hybrid/ridged/heterogeneous octave coupling. Octave count alone is insufficient.
4. **Evaluation Mode / Cost Boundary** — distinguish exploratory procedural evaluation, runtime evaluation, cached/baked evaluation, and truth identity. Baking may be a reproducible cache of a locked graph; it must never silently become a new Observation Root or erase provenance.

## Executable evidence status

A prior repository skill (`learning-r1-20260905/skills/procedural-noise-audit`) already contains executed mathematical counterexamples for curl normalization, potential modulation, Worley boundary distance, periodic field versus periodic trajectory, ridged-value-range assumptions, and domain-warp invertibility. Those results remain applicable and are not duplicated here.

For the new footprint-filtering claim, this cycle adds a standard-library probe that uses the current KAOPU-compatible sinusoidal typed-wave basis. For each plane-wave component, a box-footprint average has an analytic sinc attenuation. The probe compares raw point evaluation with footprint-aware evaluation against exact cell averages. This is deliberately a sampling-contract probe, not evidence that sinusoidal sums are a universal natural-world basis.

## Unknowns / blockers

1. No current KAOPU production field has yet been benchmarked with footprint-aware filtering versus current evaluation; production benefit remains unverified.
2. A normalization layer can make different algorithms easier to interchange but may erase meaningful amplitude/energy semantics. Normalization must therefore be explicit and typed, never silent.
3. Native derivatives may improve quality/cost relative to finite differences, but the actual benefit depends on target hardware and operator basis; this needs executable comparison.
4. “Wavelet noise is better” is rejected as a global claim. The paper establishes a strong anti-aliasing property for its target problem, not universal superiority for terrain, clouds, ocean, materials, or simulation.
5. Stochastic procedural-noise evaluation remains renderer-specific until a Mother demonstrates an unbiased, stable, task-appropriate use case.

## Routing recommendation

- KAOPU core candidate: evaluation footprint/filter policy, differential capability, spectral composition law, explicit normalization/evaluation mode.
- Landscape/Terrain: test cross-resolution morphology and shared-edge stability; do not replace Canonical DEM truth.
- Weather/Ocean: test derivative/curl-capable field operators only where the field semantics match forcing/transport; do not infer fluid correctness from noise appearance.
- Material Mothers: test composition-law control and footprint filtering for stable multi-distance appearance; retain material causality and measured properties separately.
- Realtime rendering Mothers: evaluate bake/cache boundaries and runtime budgets; baked fields remain derived artifacts with graph/version provenance.

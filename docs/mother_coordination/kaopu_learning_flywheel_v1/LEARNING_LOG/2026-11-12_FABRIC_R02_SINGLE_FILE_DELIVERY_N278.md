## One bounded question

Does the newly published Fabric R02 page satisfy the current primary-delivery contract: one self-contained HTML that opens by double-click / `file://` with zero required external files or network requests?

## Current facts

The exact `gh-pages` commit adds four files under `fab-fabric-material-lab-r02/`:

- `README.md`
- `index.html`
- `app.js`
- `shader.wgsl`

The implementation is not a fake screenshot. It contains a native WebGPU indexed render pipeline, a 128 × 88 cell mesh, depth testing, eight procedural material presets, editable WGSL and JSON parameter import/export. The public URL resolves and renders its interface.

However, the primary page is not self-contained:

- `index.html` loads `./app.js`;
- `app.js` executes `fetch('./shader.wgsl')`;
- therefore local double-click delivery requires at least two sibling files and a successful file-origin fetch policy;
- no single-file artifact, `fileProtocolTested=true` receipt, `requiredNetworkRequests=0` receipt, exact standalone digest or independent double-click run was found.

The cloud browser reached the public page, but its environment returned `错误：没有可用 WebGPU 适配器`. This proves only that the page and controls are publicly served and that this browser environment cannot run the WebGPU path. It does not prove failure on the user's device, nor a production browser/device pass.

## Claim boundary

R02 truthfully describes itself as a material lab and says its geometric drape folds are procedural. The mesh is static geometry generated by trigonometric functions; there is no time integration, gravity, collision, sewing, body contact or garment-on-character subject. Therefore:

- material-lookdev source delta: `VERIFIED`;

- single-file primary delivery: `FAILED`;
- local `file://` run: `NOT_RUN / UNPROVEN`;
- cloth physics or garment-on-character delivery: `NOT_CLAIMED / NOT_IMPLEMENTED`;
- device/runtime acceptance: `UNKNOWN`;
- user acceptance: `false`.

## Decision

`HOLD_PUBLIC_MULTI_FILE_NOT_SINGLE_FILE_PRIMARY_ARTIFACT`

Do not reject the material study itself. Do not promote it as a valid primary delivery until the exact same result is packaged into one self-contained HTML and independently exercised from `file://` with the required receipt fields.

## De-duplication

Institutional result: `NO_NOVELTY`.

The current root AGENTS / single-file delivery authority already requires one self-contained HTML, double-click / `file://`, no required sibling files, no CDN and zero required network requests. Existing expected-artifact, freshness and public-delivery semantics already distinguish source/publication from usable delivery. No new regression case is created.

Applicable existing cases were reviewed:

- `WHOLE-MACHINE-NOT-PARTIAL-DELIVERY-001`: useful analogy for evidence layer separation, but its scope is complete machines and it should not be broadened silently.
- `FREE-ASSET-LICENSE-NOT-REDISTRIBUTION-001`: R02 does not redistribute the referenced Fab texture pixels; exact acquisition/license remains relevant only if future work incorporates those assets.
- `CANDIDATE_USER_VISIBLE_PROVENANCE_NOT_HIDDEN_001`: R02 visibly links its Fab references, so the observed failure is packaging, not hidden provenance.

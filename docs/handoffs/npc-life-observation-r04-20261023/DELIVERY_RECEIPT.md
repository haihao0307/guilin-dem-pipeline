## 4. 仍然成立的边界和下一重点

1. `Workbench.mjs` 的 `station()` 增加 sceneEpoch 并调用 `world.reset()`；`enterMode()` 在拿放／窗边模式改变时调用它。因此工位切换是测试场景重设，不是角色步行，也不构成保持物品历史的“整理→走到窗边→开窗”连续生活任务。下一结构迭代优先分离明确的测试重置与正常技能／工位转换，并验证瓶子、窗扇、任务和占用状态在转换中保留，再接导航与触达。
2. 仍是固定工位、有限力辅助握持；没有手指摩擦动力学、完整全身运动动力学、整房间导航、跨设备权威状态中心或通用 AI 规划器。
3. 没有增加更自然的全身动作。本轮控制和数据修复不能证明腕、肘、躯干协调已达到生活化质量。
4. 66,621,065-byte 独立 HTML 仍有明显启动负担。后续需要受控拆分资源、缓存和按需计算，不能把软件 GPU 测试通过等同于大量 NPC 或手机性能合格。
5. 390×844 是 Chromium 视口测试，不是实体手机验证。
6. `visualAcceptance=false`、`productionReady=false` 保留。本文确认的是当前观察版的明确功能及程序验收，不是整个虚拟人系统完成。

# 服装穿插的工序诊断与接触学习

本轮把 R02 的一个真实失败样例追到具体裁片和工序，形成可重复运行的诊断工具。**当前执行链能检查布面相交，但没有启用运行时布料自碰撞响应；下一项有效改进应覆盖缝合与整理过程中的接触。** 单纯增加聊天入口、提高迭代次数或开启旧开关，都不能由现有证据保证修复。

这是独立研究成果，未修改 R02 网页或原求解器。原网页仍在 [固定 R02 地址](https://haihao0307.github.io/guilin-dem-pipeline/kaopu-tailor-workbench/clo-learning/r02-c5c99dd6e7fb/)；该地址没有本轮新增的诊断界面。

## 已执行的实验

研究输入为已归档的公网 Chromium 原始 paper/done 消息，源应用提交 `c5c99dd6e7fb2124435653843c618bc6a4e4c47b`，参数为裙长 +100 mm、原三角开口深度 −40 mm。直接复用浏览器实际生成的纸样与材料网格，不按参数重新生成。

**最早被记录到相交的端点是腰部缝合完成。** 端点取样没有捕获精确首次碰撞时刻，也不能证明腰部某条约束是唯一原因。release 后的 535 对不能直接归因为重力；该工序同时释放临时支撑并继续原求解。本次 63.146 秒包含审查、状态摘要与导出开销，不用作求解速度比较。

## 最终 14 对相交发生在哪里

独立 Python 脚本用 NumPy longdouble 线段与三角形计算，复核原公网终态的全部 14 对。每对都有落在边内部、目标三角形内部的交点；最小重心分量为正。它是独立的高精度算术佐证，不是通用精确谓词证明。

| 相交双方 | 对数 | 几何定位 |
| --- | ---: | --- |
| 后裙片与后腰头 | 1 | 后腰接缝 s15 附近 |
| 前裙片与前腰头 | 9 | 8 对在 s13 区域，1 对在 s14 与前省道附近 |
| 前腰头内部 | 4 | s13 所在前腰区域 |

这批终态相交位于腰部区域，没有定位在后下摆开口。接缝关联表示二维材料距离及实际交点位置，不是因果归责。相交对数量也不等于独立缺陷数量：按共享同一三角面的图关系，这 14 对构成 5 个分量。

其中 4 对共享缝合求解顶点，2 对还共享原材料顶点，却在共享点外仍有约 4.05、4.14、7.86、13.34 mm 的相交区间。因此，不能把“共享缝合顶点”作为整对三角面免检的理由。普通共享边接触与超出共享边界的穿透必须区分。

完整面片身份、原始顶点、重心参数、交点、缝合组和距离见 `evidence/local/CONTACT_AUDIT.json`。`evidence/local/DIAGNOSIS.json` 将这些事实组织成未来工作台可以消费的事件记录；其中首次观察工序仅表示被保存的检查点，根因仍标为未确定。

## 为什么旧开关不能视作修复

冻结来源 `c84b16a0ae022dda9fe22c09df758fcb8095bc07` 的 `native-adapter.mjs` 确实含有旧 SelfContact 类，但实际初始化显式设置 `selfCollisionEnabled=false`；公网结果也记录 `runtimeSelfContact=false`。

旧类使用离散点面距离和侧向变化启发式，没有完整边边响应。对保留终态做候选覆盖分析时，4 对相交的相关点面候选全部被其邻接条件排除；其余 10 对仅 2 对存在小于 0.6 mm 的合格点面近距候选。这不是“只能修好 2 对”的预测，因为没有用旧子步状态执行其 crossing 分支，也没有实际开启响应。

执行结构也不同：`GarmentLab2.step` 在打开该开关时转入 `super.step`，改变原 WASM 求解路径；`seam-relax / refine / seam-finish / joint` 又直接调用 kernel。只改一个布尔值，既改变求解条件，又没有覆盖全部坐标修改工序。

## 本轮吸收的知识

| 知识 | 对我们系统的直接要求 |
| --- | --- |
| 检测、响应、连续检测、解缠分别表达 | 禁止用一个 `collision:true` 同时代表四种能力 |
| 每次坐标修改都可能引入接触问题 | 缝合整理、应变投影和全局优化也应进入接触处理范围 |
| 无相交初态的预防与已穿插状态的恢复不同 | 先检查起点；已有穿插不能自动交给只保证可行起点的算法 |
| 缝合邻接不等于几何安全 | 保留共享边界以外的真实穿插检查 |
| 算法对照必须固定实际输入 | 比较材料哈希、人体和实际网格，不只比较滑块参数 |
| 诊断须保留证据和不确定性 | 输出裁片、接缝关联、工序、交点与来源，未确定的根因保持未知 |
| 人体整合首先对接最终表面 | 对齐身体与碰撞的版本、坐标和时刻，骨骼数量不代表协议兼容 |

这些规则进入 `KNOWLEDGE_CONTRACT.json`。诊断提取器已经可运行；接触响应、自动修复和人物协议适配仍未接入产品运行时。

## 外部方法如何取舍

Bridson 等人的 2002 年方法适合学习如何围绕已有材料求解加入点面、边边接触，以及响应后再次检查。Pixar 官方课程有助于区分预防和已经纠缠后的恢复，但其中的启发式与艺术制作目标不能作为实体制衣精度证明。C-IPC 提供接触、厚度和应变限制联合求解的参考；其无穿插保证要求可行的初始几何，不能把它当作修复任意纠缠的按钮。

方法摘要、前提、移植成本及完整英文官方链接见 [SOURCES.zh-CN.md](SOURCES.zh-CN.md) 和 `TEACHERS.json`。本轮没有移植论文求解器，也没有使用中文网站。

## 与现有人物系统的关系

附件里的 SMPL24／28 控制节点属于架构与历史母本；本轮读取的 Humanoid 仓库 `main` 固定提交 `fda12bf2fe0262e4d02f1b08508128d17959e0c8` 实际 rig 为 128 节点；R02 冻结人物包含 104 项骨骼数据，但页面显示使用静态 Mesh。当前默认分支不等于已经选定的最新人物整合目标。

最小可用接口应交付一份不可变的最终人体表面快照，包含人物与来源、比例／绑定版本、最终姿态与采样时刻、顶点和三角形身份、坐标与单位、碰撞表示和表面的对应关系。新增字段是提案，不能冒充现有协议。普通姿势更新与体型修改需有不同的失效规则；窗口相机移动不应触发重制衣服。

具体事实和提案边界见 [HUMAN_INTERFACE_NOTES.zh-CN.md](HUMAN_INTERFACE_NOTES.zh-CN.md)。不会删除现有人体哈希保护来实现表面上的“接通”。

## 下一项有价值的实施

优先在一个固定腰部缝合案例上，保留前一份未相交状态，观察从该状态到下一候选的点面和边边移动；对越过表面的候选限制位移并重检，然后检查原应变、完整接缝与身体门槛。应覆盖它声明保护的缝合与整理阶段，而不只保护普通物理步。

先检验这一有限接触策略能否同时保持材料、缝合及身体约束，再考虑将位置标记和工序记录加入新独立网页。已有穿插的恢复是另一项实验。任何修复都必须产生新的完整结果；本轮没有把失败改成通过，没有宣称动态试穿、多层叠穿、真实手机性能或生产就绪。

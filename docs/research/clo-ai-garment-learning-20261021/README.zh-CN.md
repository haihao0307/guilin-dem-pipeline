# CLO 与 AI 服装案例研究及自有平台接入规范

研究日期：2026年10月21日（北京时间）  
范围：用户指定的两条 irinatoxi 帖子、CLO 第一方技术文档、现有裁缝与叠穿代码。  
状态：知识与接入规范候选。运行时接入尚未执行；没有新的三维服装效果或性能提升可供验收。

## 核心判断

两条参考都是 CLO + AI 的服装案例。它们说明了将款式和尺寸变成可编辑服装工程的价值，但没有公开足够信息让我们复现作者的完整自动化过程。值得吸收的是结构化制衣、工具编排和检验反馈的组织方式。

我们的系统已经有参数化纸样、解析曲线、有向接缝、材料裁片和缝合求解。最有价值的增量是补齐布纹与物性依据、工艺及装饰语义、修改后的依赖失效规则，以及可供 AI 读取的合体诊断。新增聊天入口本身不能解决现有试样的穿插和材料变形。

本目录的 KNOWLEDGE_CONTRACT.json 保存来源、知识卡、模块接入点和验收条件。它是供开发读取的设计合同，不是已接入运行时的执行器或已生效 Schema。TASK_ANCHOR.json 与 DELIVERY_RECEIPT.json 记录本次范围和检查边界。

## 2 这类系统怎样搭建

### 已确认的底座

CLO 官方API示例公开了创建二维裁片、分配材料、运行若干仿真步骤和导出渲染的调用。这证实成熟服装软件可以被程序编排。[C01]

当前官方更新记录还包含裁片语义、边界与缝线ID、缝合配对组、人物测量查询和关联等数据接口。接口版本变化需要检查，不能假设所有已安装版本支持同一套操作。[C02]

可复现的同类架构是：

1. 用户提出款式与合体要求。
2. AI把要求转成结构化命令。
3. 插件或脚本将命令交给服装软件。
4. 软件执行制版、排布、缝合、材料设置、仿真和显示。
5. 执行端读取结果、错误和诊断，再决定下一步修改。

两个公开同类仓库分别展示了“Python MCP—文件消息—原生插件—CLO”与“Python MCP—JSON消息—CLO内Python脚本”两种桥接。[O01][O02] 它们可作架构参照；没有证据证明原帖使用了其中任何一个。作者具体的AI型号、提示词、控制方式和人工干预量均为 UNKNOWN。

### 自有系统的对应关系

保留现有确定性制版器与求解器，在其上提供受约束的服装操作接口。AI负责理解请求、选择操作和处理诊断；现有内核负责实际几何与物理。AI不得自行将“完成”文字当作验收结果。

服装参数化仍可产生离散网格参与模拟。CLO官方的Particle Distance就是布面离散点间距；这不是“完全无三角面的函数渲染”证据。[C08]

## 4 应吸收的七项知识

### K01 让修改成为可读取、可回放的服装操作

官方依据：CLO提供纸样、面料、仿真和导出API；公开桥接项目能向AI返回工程和裁片信息。[C01][O02]

自有增量：

- 从现有参数Schema查询真实可用参数及适用条件，再执行修改。
- 每条操作绑定requestId、expectedRevision、人物比例版本、纸样版本、单位、修改目标和证据来源。
- 将读取、预检、生成、求解、诊断和提交分开。非法引用、不支持的操作或过期版本应明确拒绝。
- 一次修改在隔离的候选状态中完成；失败不替换上一份可用状态。
- 纯诊断的无效纸样不得进入物理求解。已有生成器拒绝机制需要保留。

首个增量只连接一个已经存在的制版参数和现有诊断，不急于支持任意自然语言或任意脚本。相同数值后端下检查重放一致性；跨native/WASM不能承诺逐字节相同，现有文档已记录优化器数值差异。[R01]

### K02 补齐裁片、开口和工艺的语义

官方依据：裁片语义标签与接缝配对可以作为下游可重建数据导出。[C02]

自有增量：

- 在现有panelId、edgeId、seamId上补充前身、后身、袖片、袖山、袖窿、领口、腰头、开衩、下摆等角色。
- 明确每条边是缝合边、自由边、折边还是穿脱开口。
- 工艺操作描述作用材料域、前置操作、临时支撑和释放条件。
- 缝线的物理约束、可见针脚、材料边界分别保留。
- 接缝配对遵循原方向、剪口与吃势。不能一律强制两边等长；收褶和有意吃势需要可解释的比例。

这能让“改领口”“缩短裙子”“改变开衩”落到明确结构，而不是在最终网格上整体拉伸。

### K03 面料外观与物性共享材料身份

官方依据：CLO分别表达经纬拉伸、剪切和弯曲；grainline会影响裁片方向与伸长行为；Fabric Kit流程测量质量、厚度、弯曲和拉伸。[C03][C04][C05][C06]

自有增量：

- 沿用既有materialId，并分开appearanceProfile与physicsProfile。
- 每片记录布纹坐标系；针织物使用与其线圈组织一致的方向定义，不能无条件套用机织物术语。
- 物性值带单位、测量或推断来源、材料状态和适用范围。
- CLO的UI滑块数值不能直接复制成我们XPBD的刚度或compliance；需要针对自有离散方式与时间步建立转换和标定。
- 当前local +Y只可标为adapter_convention，不能升级成measured_grain。
- 面料厚度、显示纱线包络和数值接触余量分开记录，避免用不断加厚掩盖穿插。

验证固定同一裁片、人物与姿态，仅改变一套物性或布纹方向，比较可解释的垂坠、伸长和弯曲差异。各向同性材料的方向对照允许接近不变；不能把“旋转后必须有差异”写成万能判据。

### K04 先建立合理排布，再求解成衣

官方依据：CLO自动排布参考裁片形状、对称和缝合关系，小裁片与位置重合的裁片可能降低排布准确性；自动适配自定义人物也有Fitting Suit等前置条件。[C07][C10]

自有增量：

- 利用角色和人体区域关联决定裁片初始朝向、侧别、位置与层次。
- 口袋、领片、袖口等小件保存父裁片关系。
- 折边和翻领预折表达为工艺初态，临时夹具必须有释放规则。
- 输入初始相交或翻面应报告具体位置，不让求解器无条件硬拉到身体外面。
- 可见身体与接触体读取同一个finalPose及人物比例版本。

这项增量针对求解失败的原因。它不能替代完整碰撞和自接触，也不构成任意服装自动排布保证。

### K05 由合体诊断驱动修正

官方依据：CLO将应力、应变、松紧和接触压力分成不同诊断视图。[C09]

自有增量：

- 优先读出已有的接缝间隙、材料拉伸/压缩、身体穿透和层间穿透。
- 每个失败绑定panelId、edgeId或接触对，供工具返回和局部定位。
- 物性没有标定时，可以报告几何应变、距离和求解残差；不能将其直接改名为真实kPa压力。
- 纸样有效、缝制完成、静态合格、动作合格、多体型合格、实时合格、实体生产合格分别保存状态。
- 衣柜展示简明且诚实的可用状态；详细诊断保留在裁缝工作台。

先用当前60款的真实失败检验诊断是否有用，再增加装饰。不要以缩略图完成度或AI自评代替质量门槛。[R03][R04]

### K06 把收边和装饰附着在材料空间

原帖可观察到收边、毛边、纹样、刺绣及珠串，但内部实现未知。[S01][S02] 以下是自有接入设计，不是作者源码还原：

- 绣线、条纹与图案以裁片材料坐标和实际尺寸定位。
- 沿边饰条以稳定edgeId和曲线参数附着，不能只记当前网格顶点编号。
- 珠串或悬挂附件保留锚点、质量和作用范围；纯显示与参与物理必须明确标记。
- 扩展拓扑后，旧三角面附着缓存失效，重新建立绑定。
- 改版后装饰能跟随正确裁片，条纹尺度不随人物整体缩放而漂移。

不要从毛边的视觉外观推断已经实现逐纱断裂；不把珠串外观当作已经参与质量、碰撞和摆动的证据。

### K07 制作成本、查看成本与运行成本分账

官方依据：CLO的离散精度会影响成衣质量和模拟速度。[C08] 我们自身的60款查看器与R03求解也是两种不同计算任务。[R05][R06]

自有增量：

- 分别统计制版、初次缝制/穿衣、着装初始化、每物理步、每显示帧、内存与显存。
- 采用用户既定的连续需求调度。视野、投影尺寸、运动、接触风险和实际误差可成为调度输入；具体权重需测量。
- 不引入固定距离整件高低模切换，也不在本次新增动作缓存。
- 隐藏表面可以减少显示细节更新；仍承载外套或参与摩擦的内搭不能仅因不可见就全部停算。
- 休眠/唤醒需要单独验证边界约束、速度、接触历史和可见性变化；R03目前尚无此能力。
- 纯颜色或粗糙度修改通常只影响显示；若修改涉及位移、纱线直径、碰撞包络或厚度，就必须重新评估物理依赖。

连续调度是我们的目标约束，并非原帖或CLO文档已证实的算法。

### 输入变化与旧验收的失效

人体比例变化和普通动作更新必须分开。比例变化需要更新量体、人物几何及绑定身份；量身制衣重制依赖该量体的纸样，固定尺码试穿则保留明确选定的纸样并重新验收。操作意图必须明确。仅更新finalPose时，纸样静止形状和人体绑定结构不应变化，但身体显示、碰撞体、速度和帧版本必须同步。R03当前静态人体路径不支持通过“清一下缓存”自动获得动作能力；瞬移和姿势不连续还需独立重初始化或失败规则。[R06][R07][R08]

物性修改也不能只重建刚度：面密度影响质量和逆质量，厚度、包络或接触余量影响接触间距与候选对，摩擦影响切向约束及接触历史。需要更新这些依赖，并重新计算受影响的耦合布料；若未来实现休眠，则必须唤醒这些区域。布纹方向与显示织纹共用坐标系时，显示也要同步。每份验收保存输入指纹和测试范围；依赖改变后，旧通过结果保留为历史证据，不能继承为新候选的通过状态。

## 6 第一轮实施范围与验收

建议先做“一个可解释的改衣闭环”，随后扩展。此处是供各开发窗口领取的下一轮合同；本研究没有执行这些运行时任务。

1. **裁缝窗口**：选现有一份解析纸样和当前真实人物，读出其参数、裁片角色、开口、缝合与材料证据。若现有语义不完整，应输出UNKNOWN，不根据最终外观猜造。先只支持一个现有长度参数的修改。
2. **布料窗口**：给现有两种材料补方向与物性来源。未实测的数值诚实标记；先做可复现的对照，不给材料名预设“真物性”。
3. **衣柜窗口**：向原裁缝链发出修改请求，读取新版本与诊断，保留上一版可用结果。生成失败不得留下错误缩略图或假合格标签。
4. **叠穿窗口**：在单件达到对应质量门槛后消费新版本，重新检查接触及附着。换人物时先统一身体显示与碰撞状态。

| 验收 | 必须观察到的结果 |
| --- | --- |
| 参数修改 | 改到声明的参数；未声明受影响的尺寸和缝合关系保持，或明确报告依赖变化 |
| 版本安全 | 重复requestId不重复执行；过期expectedRevision拒绝；并行旧请求不能覆盖新结果 |
| 纸样与工艺 | 边界有效、开口仍为开口、左右和接缝方向正确；吃势有依据 |
| 材料 | 显示与物性版本可追溯；纯外观变化与力学变化分开 |
| 合体 | 使用当前分支原有阈值；失败不降门槛、不无限外推、不自动标合格 |
| 动作 | 站立通过后另测走路、抬手、坐下；没有执行的动作保持未测试 |
| 性能 | 对同人物、纸样、材料和动作测量；显示帧率与求解速度分别报告 |

本轮不规定“几小时实现”或必达帧率：API适配较小，但物性标定、初态质量和动态接触可能成为主要工期。具体耗时应由第一个闭环的真实测量决定。

## 7 普通开发者快速复现的限制

- **桥接不等于引擎**：CLO公开API可被控制，不代表其完整求解器开源或可直接嵌入网页。同类开源桥接也要求已有CLO环境，并有软件版本约束。[C01][C02][O01][O02]
- **尺寸信息不完整**：几个围度不能唯一决定肩斜、胸背形态、姿势和局部松量。自定义人物自动适配有前置条件。[C10]
- **物性需要数据**：纹理照片无法独立给出质量、厚度、方向性伸长和弯曲响应。样布、测量工具、重复试验及求解器标定都是投入。[C03]
- **装饰会改变问题**：悬挂附件的重量、厚度和接触需要建模；复杂装饰并非免费贴一层外观就完成。
- **网页实时是另一项约束**：高质量离线样衣、预计算查看器和大量NPC动态求解不能互相代替性能证据。
- **现实制衣有额外验收**：缝份、穿脱开口、里衬、缝制顺序、辅料、缩水与实体试穿仍需验证。用户当前目标是游戏NPC，可先验收数字服装，但不能标成工业生产合格。
- **多窗口集成有成本**：必须核对各分支版本、人物身份与失败状态；不能用一个笼统“最新版”覆盖多条独立成果。

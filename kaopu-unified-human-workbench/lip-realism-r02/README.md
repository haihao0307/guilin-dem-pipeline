# 嘴唇色域 R02：先诊断，再改变一个原因

当前状态：候选源码已改，等待实际浏览器和独立视觉复核。不得把本文件的计划或构建成功当作视觉通过。

## 审核看到的实际问题

已核对 R07 当前控制审核版，以及已发布的嘴唇 R01 固定构建 `0db4b3c0e5e6e86663be6466fa7ab4b486bd5420`。R01 已减少下唇强亮斑和部分长划痕，并使上唇轮廓更清楚；这些不是 R02 新成果。

R01 底色视图仍近似整片灰粉色，内外唇区差异很弱。边缘虽比 R07 清晰，整体仍有填色感。张口／噘嘴还暴露原有内缘折段、口角硬连接及平面式口腔区域，属于另一项必要几何工作，本轮不声称修复。

## 此次修改与理由

1. **阻止旧唇色先进入皮肤。** R01 先混入 R07 唇色，再以另一个范围覆盖。旧范围与新唇缘不同，分数覆盖留下旧染色。R02 在旧着色入口阻断它；保留原区域变量，避免连带改变毛孔、胡茬、粗糙度。
2. **只与完整口周肤色合成一次。** R01 使用早期肤色快照，绕过后续组织血色、色素和细微色彩；新唇域又乘两次覆盖率。R02 在所有继承皮肤层完成后，以原生唇缘一次合成。外缘自然回到当前人物完整皮肤。
3. **可单独关闭的空间色彩。** 沿本人上／下唇、内／外缘坐标组织有界色彩变化，保留原主色系、种子与控制值。外露区和口角采用不同过渡量。系数属于制作近似，不是实测血色或生理常量；只有实际对照改善才保留。

R01 与 R02 的原生／显示几何、法线、细纹、湿润、粗糙度、灯光和镜头保持一致。R07 作为更早对照保留；它的几何主沟幅度不同，不能把 R07→R02 全部变化算成本轮收益。

## 怎样反驳这次改造

默认完整材质和纯底色均按同相机比较 R01／R02，另看整脸、微距和斜侧。关闭分区色彩只保留边缘合成修正，区分两项贡献。

- 若只是更红、更花、更暗，不能通过。
- 若只有参数隔离成功，默认帧看不出实际必要差异，必须把收益限定为合成修正。
- 若边缘变为描线、口周皮肤变化被擦掉、或新增色带让唇面像涂层，不能通过。
- 若几何、法线、粗糙度、灯光或 ROI 外的像素变化，需定位原因，不以测试误差解释。

独立验证先重建与既有公开 R01 **字节完全一致**的基线，再核对候选内的 R01 对照确实一致。真实浏览器以底色检验旧 `psLip` 残留、湿润与底色独立、口周血色／胡茬仍有效，并验证比较、复位和新增色域状态的档案往返。

## 依据及边界

[Vergnaud 等的原始研究](https://qima-lifesciences.com/wp-content/uploads/2023/10/2023-Vergnaud-H-Cherel-M.-Lip-color-measurement.pdf)使用上下唇分开测量并排除镜面反射，支持将区域颜色和反射分别检查。样本为 19 位法国白人女性，不能推导每个人必须采用同一中央红／边缘暗模板。该文并未给本角色的空间颜色图。

[Epic 数字人官方资料](https://dev.epicgames.com/documentation/en-us/unreal-engine/digital-humans?application_version=4.27)将底色、粗糙度、法线和散射分开处理。R02 遵循通道分离，但没有导入 Epic 资产，也没有新增体积散射。

缺少当前人物的校准实拍和组织参数，颜色仍是有界程序制作。既有微纹组织和口腔结构仍有不足。软件浏览器性能不能代表实机帧率；390×844 视口不等于真手机。

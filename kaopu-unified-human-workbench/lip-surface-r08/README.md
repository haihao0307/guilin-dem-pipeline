# 嘴唇质感 R08：由真人参考重新校准的双因素实验

当前状态：源码与事前审核完成，等待固定提交网页的实际 GPU 检查及原图视觉审核。技术检查不自动产生视觉批准。

## 这一轮要解决什么

当前人物已经有上下唇色差、色素与湿润控制；它并非完全没有分区。重新对照真人研究原图后，最普遍的差距是唇面内部的颜色仍近似大片填色、外唇边缘整体过于柔化、细纹与反光的层次不足。

上一轮 R07 的下内缘平滑改善了几何角度，却没有带来足够可见收益。本轮以已接受的固定 R06 人物为基底，保留 R07 的失败记录，不将未通过的几何改变混进新的材质对照。

## 两项可以独立检查的改动

| 因素 | 实际改动 | 范围与理由 |
|---|---|---|
| 外唇边界 `edge` | 缩窄并保留沿唇缘变化的共享覆盖过渡；将向周围皮肤的混合收回到外缘附近 | 针对宽柔边的喷涂感。这个共同遮罩影响颜色、shader 细高度、粗糙度和水膜覆盖；它不是纯颜色改动。原生网格不变。 |
| 唇面颜色 `colour` | 保留原有底色及作者参数，改变附着于原生静止坐标的局部色彩结构；分开色度与双向明暗场，并衰减远处新增的细色彩场 | 针对默认色差过弱、较大块面占主导。它是工程外观场，尚未测量血红蛋白、黑色素或真实组织光学。 |

完整模式 `r08` 组合上述两项；`r06` 返回原始 fragment、原始 cache key 和原有外观。三个声明替换由 `SurfaceMaterial.js` 给出，验证器在独立 VM 中读回替换清单，并对真实展开的 GPU shader 逐字复算和逆向还原。

本轮不重写细纹函数、主唇沟深度、内壁形体或口腔模型。需要在实际对照中判断改动是否有收益；不能把更多噪声、更红或更清楚的边界当成必然更真实。

## 参考证据

- Vergnaud 等，2023，*Lip color measurement: A new hyperspectral imaging device*：https://onlinelibrary.wiley.com/doi/full/10.1111/srt.13418 。19 名法国白人女性；同一真人的普通光、交叉偏振、平行偏振照片提供颜色与反光区分。不能由这些照片直接反求沟深或粗糙度。
- Charton 等，2026 年卷期、2025 年在线发表，*Development of a lip colour chart across four ethnicities*：https://onlinelibrary.wiley.com/doi/full/10.1111/ics.70004 。514 名女性；53 个色调表达人群下唇局部测量的色域，不是每张嘴应包含的 53 个分区。去镜面图适合比较颜色，不适合直接指定高光。
- Epic，*Digital Humans*，UE 4.27：https://dev.epicgames.com/documentation/en-us/unreal-engine/digital-humans?application_version=4.27 。分离底色、粗糙度、反射、散射、法线，并对照人物实拍。它未提供当前原生嘴唇的生理参数。

`research/reference-review.json` 保存原始图片来源、原文件哈希、实际看图意见、样本限制、工程值及事前拒绝条件。研究照片不作为产品贴图，也不复制进本仓库。

## 验证与接受条件

计划实际检查 7 组同条件 A/B：闭口正面、斜侧及整脸，张口正面及斜侧，说话正面、噘嘴斜侧；另有两个单因素及恢复图、独立原 R06 对照、真实保存下载和新页面恢复。

全部原生及 draw attributes 必须精确一致，不能只比较部分保护顶点。关闭 R08 后，实际 GPU shader、全部 active uniform 数值和原生像素必须等于独立固定 R06。保存验证包括真实旧 R02 按钮，三个真实下载入口，坏档案无副作用，以及新页面从下载档案恢复半进度张口。

计划数量：14 项测试、20 张保存的原生图、21 次 GPU readback、1 张实际页面截图。以最终 `evidence/candidate-01/qa.json` 的真实结果为准。所有自动报告保留 `visualAcceptance:false` 与 `productionReady:false`。

人工拒绝条件包括：出现硬描边、亮缝、颜色越界、杂斑或淤青感；只在单一角度改善；组合效果掩盖单因素恶化；只看到像素响应而没有可辨的质感收益。最终源提交、构建提交、证据提交及固定 HTTPS 入口将在实测完成后登记。

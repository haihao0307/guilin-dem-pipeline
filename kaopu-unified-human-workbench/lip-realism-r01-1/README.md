# 人物总台 · 嘴唇专项 R01.1

这是一份从嘴唇专项 R01 接续的完整人物存档修复。它继续使用同一原生人物与 R01 唇部外观。

## 这次修复的实际问题

R01 顶部的嘴唇保存入口已经写入 `lipRealism` 参数及两份原生唇纹校准。保留在旧皮肤面板中的完整人物保存、载入按钮，以及头部和全身皮肤的公开档案 API，却仍调用较早捕获的 R02 函数。通过这些入口保存会漏掉嘴唇内容。

R01.1 只把这些遗留的完整人物入口接回当前档案函数。原本通过人物控制器动态调用的眼、耳、原生嘴唇和形态存档保持其工作方式。局部参数记录与模型导出不属于这次重定向范围。

生产修改位于新目录的 `LipSurface.js`。原 R01、冻结 R07、皮肤工作线及另一条 `lip-control-contract-r01` 审核支线不变。档案 schema 沿用 `kaopu/lip-realism@1`，没有校准段的旧档案继续使用兼容路径。

## 如何使用

页面顶部仍提供“保存完整人物”和“载入人物档案”。展开旧皮肤面板后，其中保留的完整人物保存、载入入口也应处理同一份完整档案。

“本版嘴唇 / 原版嘴唇”、唇色参数、干湿反射、细纹和视角按钮保持 R01 行为。本轮没有更换唇形、调色、增减沟深或改变灯光。

## 验证范围

`verify-fresh.cjs` 先在冻结 R01 上复现旧保存入口漏字段，再检验候选入口。测试通过实际按钮下载 JSON，关闭生产者页面及其 BrowserContext，然后在两个全新 BrowserContext 通过文件输入载入磁盘上的档案。比较原生校准数组、参数、控制网格、最终显示几何与同条件下的完整 framebuffer。

相机和诊断灯光是明确设置的比较条件。人物档案没有新增“保存任意观察视角”的承诺。相同页面中的内存往返与跨新页面恢复分别记录，旧报告不冒充本轮测试。

最终固定入口、源码、构建、实际检查时间和结果以 `PUBLICATION_PROOF.json` 为准；该文件尚未生成或 `shareAllowed` 不为 `true` 时，候选尚未完成交付。必要 JSON 和真实运行截图保存于本目录可跟踪的 QA 路径。

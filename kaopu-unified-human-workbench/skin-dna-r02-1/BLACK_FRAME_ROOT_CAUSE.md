# R02 黑屏根因与 R02.1 修复边界

2026-10-13。用户截图显示80.2MiB资源已完成校验/缓存复用、侧栏已创建，但三维画布全黑，并提示“新皮肤首帧校验未通过”。这是显示失败，不能称交付成功，也不能仅凭旧CI通过要求用户清缓存。

## 已复现的首要错误

固定旧 R02 `69d5cb9bfd68c2950112346403f1bf530d4180c0` 在 Windows / ANGLE Direct3D11 WARP 上的驱动链接日志：

`FRAGMENT shader texture image units count exceeds MAX_TEXTURE_IMAGE_UNITS(16)`

旧人物材质片元阶段实际需要18个纹理采样器；该D3D11环境上限16。顶点阶段另有1个采样器。旧验收使用的Linux SwiftShader片元上限32，不能代表16上限的浏览器。`onBeforeCompile`回调被调用也不能证明图形驱动已成功链接程序。

原版Windows复现：Actions38397563557 / artifact11812538605。更贴近真实桌面打开路径的复查：Actions38406210206 / artifact11817249313，实际安装的Google Chrome154.0.8037.58，同一D3D11 WARP16上限环境中，旧R02黑屏，新R02.1能显示完整人物。修复版在Chrome现代无头和普通有窗口模式均可显示。

该对照的实际JSON与PNG已下载检查，旧黑屏、新有窗口面部图均实际查看。它证明此缺陷确实存在且修复版在该环境有效；没有远程读取用户显卡，不声称已检查用户物理GPU或找到了所有机器上的全部问题。

## 修复方法：改变数据组织，不改变皮肤规律与人物

R02.1独立目录为 `skin-dna-r02-1`。原R01/R02/R04和旧链接保留，不合并、不强推。

三张同规格sRGB眼部颜色图改存为同一纹理数组的三个独立层，血丝线性数据仍独立采样。三个源PNG逐个校验SHA256；精确解码并核对完整RGBA摘要，保留透明像素下的RGB，避免Canvas2D预乘透明度改变源像素。图像尺寸、区域、sRGB解码、过滤和mip设置保持，减少2个片元采样器。

BioSkin原Float32查找表数值原样附加到既有面部毛孔Float32表末尾，原毛孔记录前缀逐项保持，使用明确行偏移读取，不另占一个片元采样器。BioSkinLUT.json文件摘要不变。新表额外17行、每行512个RGBAFloat32像素，共139264bytes；这是资源组织的成本，不称为内存优化。

最终人物材质为15个片元采样器、1个顶点采样器。眼睛、耳R06、唇ET19、毛孔、EB1灯光、六套肤质、BioSkin配方及原人物/骨骼没有为了预算被删除。本轮没有导入另一张头、新增雕刻皱纹、减掉人物三角形或用生成图片代替三维。

运行时新增实际程序LINK_STATUS、活动采样器和设备能力检查；失败诊断保存图形日志，而不是只报告模型加载完成。检验后再完成最终绘制与像素读取，避免把已经提交的画面误认为没有绘制。

## 需要保留的失败记录

第一次眼部打包用Canvas2D，原图透明像素的RGB受预乘/反预乘影响；真实GPU采样对照发现差异，因此未交付该版。最终直接解码经过摘要锁定的原PNG，九个GPU用例比较原2D采样与数组采样，覆盖三层和不同mip级别。

Windows工作树自动CRLF转换曾让字节预检失败；改为对比公开HTML、Git原始blob和BUILD摘要，而不是放宽网页内容校验。

旧Playwright141版Windows headless-shell在链接修复后仍出现上下文丢失。这个旧测试运行没有通过，未删除记录，也不将其失败宣传为成功。继续在实际安装的Chrome154普通窗口及现代无头模式做同源/同后端对照，修复版能显示，而旧R02仍然因18超过16而失败。没有关闭GPU看门狗、系统TDR或浏览器安全机制来换取通过。未证明旧141上下文丢失的唯一根因，不能简单称为像素过多或某种超时。

Linux高DPI早期截图API超时发生在已经完成首屏、六套切换和九项采样证明之后；后续改用浏览器合成器截图进行只读取证，不替页面强制渲染。实际图形功能、截图工具可靠性和视觉质量必须分开报告。

## 这次的实际根因

原R02在Windows的16片元纹理上限环境中，需要18个片元采样器，驱动不能链接人物材质。精确错误：`FRAGMENT shader texture image units count exceeds MAX_TEXTURE_IMAGE_UNITS(16)`。此前只用支持32个的SwiftShader验收，遗漏了这个兼容性问题。资源加载完成、JavaScript回调完成，均不能代替驱动链接成功和实际人物画面。

Actions38406210206使用同一台Windows、相同Google Chrome154.0.8037.58和ANGLE D3D11 WARP后端做固定旧/新页面对照：原R02黑屏，新R02.1显示完整人物，普通有窗口与现代无头模式均有实际PNG。旧失败和新成功都保留在acceptance/old-new-chrome-comparison，而不是只保留成功截图。

这是页面实现的兼容性错误，不是用户需要重新下载人物。未读取用户实际显卡型号，不能将这次复现夸大为已经进入用户设备检查。

## 改动范围：保留外观数据，只重组读取方式

三张同规格sRGB眼部颜色图装入三个独立纹理数组层，精确保留原PNG全部RGBA，包括透明像素下的RGB；线性血丝图继续单独读取。原始PNG、解码RGBA逐个摘要检查，尺寸、色彩空间、过滤和mip规则保持，减少2个片元采样器。

原BioSkin Float32色彩查找表附加在既有毛孔Float32表末尾，原毛孔记录保持不变，查表数值与BioSkinLUT.json摘要不变，再减少1个片元采样器。最终为15个片元、1个顶点采样器，在受测16片元上限内留出1个位置。

原人物、骨骼、眼睛、耳R06、唇ET19、毛孔、EB1灯光、六套肤质和NSR-01自然皮肤规则保留。本轮没有换头、删掉材质功能、减少人物三角形、新增雕刻皱纹或用图片替代三维。新规则是图形资源预算，不是新的皮肤造型规律。

新增实际LINK_STATUS、活动采样器、设备上限与图形错误诊断；不再把onBeforeCompile回调次数当作驱动编译成功。人物画面仍必须通过真实首帧像素检查，未关闭黑屏检查来伪造“就绪”。

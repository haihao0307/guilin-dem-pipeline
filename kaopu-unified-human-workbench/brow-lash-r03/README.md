## 当前可以操作

默认双眼近看，支持单眼、正面、斜侧、侧面、完整脸和完整人物。四个眉睫预设、密度/长度/宽度/卷曲/单根粗细/粗糙度、眉睫独立开关、同灯光有无眉睫对照及版本化眉睫配方保存载入保留。

点击“准备闭眼检查”后，可以眨一下或拖动0–100%闭眼滑杆。只准备原人物左右眼的两个原生闭眼目标，不再要求先准备完整待机系统。R03另外生成两份局部闭眼修正，原两个目标对象和数据保留。修正量默认85%；“对照 R02 原闭眼轮廓”关闭本轮闭眼修正，再次点击恢复。这个对照只比较闭眼轮廓，不是将R03眉毛造型也换回R02。

闭眼修正量目前属于本窗口检查状态，尚未加入永久人物身份/通用撤销历史；原眉睫配方参数仍可保存。不要宣称本轮已完成全平台状态中心合入。右上角保留原人物参数界面。这里只逐项验收当前同一人物，不等于36人、任意极端脸型及所有动作都已复验。

## 解决的具体问题

原生闭眼的中央下垂较深，睫毛贴合正确仍会显得不自然。R03在实际连接的眼睑皮肤上建立连续闭眼修正场，保留眼角倾斜和左右差异；只对闭眼目标添加可撤回的残差，中性睁眼形状及原生作者数据不修改。根部继续使用实际表皮三角形重心坐标，睫毛方向继续使用R02相对原眼球的眼睑转角，而不是刚性贴在头部。

第一候选数值检查通过，但实际PNG在外眼角下方出现竖向痕迹，所以没有将其当作视觉完成版。仅扩大深度/支持域渐变仍未消除。独立只读诊断38542224262确认相邻约0.478mm的中性边上出现约1.041mm的修正差，最大比值2.17889；不是简单的毛量不足。

最终将狭窄眼角门槛改为覆盖完整眼裂的平滑分配，同时保留支持域和深度边界渐变。最终实际修正差/中性边长的最大值降为0.92069，并新增小于1的验收门槛。最终正面闭眼PNG中早期那道竖痕已经消除。这个边指标是修正场梯度诊断，不是总变形应变、零碰撞或自然度评分。

在当前人物、当前85%设置下，中央选定睫根相对两眼角连线的下垂：左4.639→2.732mm，右4.533→2.692mm。它表示闭合轮廓变浅，不是医学测量或电影质量分数。完整生成修正通过绕原眼球轴的径向构造；运行时线性混合、整根毛碰撞和所有闭眼阶段的实际组织接触不因此自动得到保证。

本轮同时缩短主眉毛、增加主眉毛覆盖，保留细毛和长短差异。最终默认左右合计1380根眉毛、238根上睫毛、108根下睫毛。眼角不能确认根部的26根上睫毛和12根下睫毛候选被明确跳过，而不是猜测位置后声称成功。

## 实际验收和成本

本轮5项修正单元测试通过；继承的R01/R02各5项数学/数据测试另外在本地复跑通过。候选13项检查，最终固定公网33项检查，22张真实浏览器PNG；页面异常、着色器/控制台错误和失败请求均为0。测试涵盖首屏、实际画布像素A/B、四预设、参数、配方往返和非法配方、原数据不变、五个闭眼位置、原闭眼/修正对照、重复闭眼不重建、手机尺寸布局。所有原始数据在acceptance/public，不用图片生成器替代。

最终公网环境是Linux Chromium + SwiftShader。冷开到就绪约17.57秒，首次两眼准备整个操作约14.31秒；其中原生计算记录11.76秒、局部修正约0.716秒，计时口径不同，不直接相减归因。静态眉睫无需等待闭眼准备，后续闭眼不重新生成毛囊或整套待机。这里没有消费级显卡帧率保证，390×844只是视口布局，不是手机实机。

新增眉睫3个批次、55,232三角形、几何数组约4.79MB；表皮采样临时数组约6.39MB，四份位置/法线形变数组约25.55MB。它们不是整页内存，原完整人物、贴图、其他JS对象和GPU目标仍占资源。不要将某段CPU采样时间冒充整帧FPS。

## 仍未达到的质量与边界

实际单眼与闭眼画面仍有原R06眼皮偏厚、眼角和闭合细褶不够自然、皮肤偏平滑的问题；眉毛在极近景仍有明显梳理线条感。减少闭眼深弧不代表完整眼睑解剖重建。仍未完成影视级纤维互相遮挡、全部间接多重散射、全段毛发碰撞或动力学。默认保留宿主照明，不把没有开启/实现的微阴影写成完成。

继承R02的四条纤维直接光散射路径，只是实时光学实现范围，不是完整离线路径追踪器。学习依据包括PBRT4 Scattering from Hair、Disney的人物特定眼部绑定，以及SideFX的局部毛发梳理/表皮变形方法。本轮闭眼场是自有形态修正，没有声称复现其采集设备、人物扫描或精确生物力学。

# 人物总平台 · 参考表面程序表达 R03

本版回应 R02 与教师示例差距较大的反馈。先研究 [lo-th/head](https://github.com/lo-th/head) 的实际运行代码和表面数据，再用小型数值场、稀疏余弦函数与材质表达重建外观。成品继续使用本平台既有原生人物底座；没有引入教师人物、原图、HDR 文件或运行 bundle，也没有使用旧唇部几何加工来制造新的纹理。

**尚未达到整幅画面逐像素一比一。** 已拟合的表面信号、实际头型、相机、光照、阴影和整体观感是不同的验收项目。函数系数的误差不能当作画面相同的证明。

## 审核

打开 `preview.html`。默认显示中性原生头型的下半脸，使用“参考基准 / 细腻柔润 / 清晰肌理”，或者“唇纹微距”观察细节。界面保留人物、肤质、光线及保存结果等预设，不提供数值调节。

“对照上版材质”是在当前头型、拓扑和光线下切换表面表达，不是完整恢复旧网页。历史 R02 固定页面保留在原目录和原提交。

## 主要实现

- `integration/ReferenceProceduralSurface.mjs`：数据场、法线方向、粗糙度、绒面反射、薄组织受光与遮蔽组合。只处理材质；不写入顶点或索引。
- `ReferenceSurfaceFit.json`：参考的原生 UV 与前表面对应采样；区域肤色、粗糙度及散射色数据；上、下唇各自的多项式系数。
- `LabialNormalFit.json` / `LabialSignal.mjs`：上、下唇细节法线的稀疏余弦函数。运行时重建到既有唇部图集的闲置 B/A 通道，不增加纹理采样器，也不增加该图集尺寸。
- `SkinNormalFit.json` / `SkinSignal.mjs`：面颊、鼻部、下巴及额头的表面信号。运行时重建到现有 Float32 数值表尾部，新增缓存 0.5 MiB，不增加采样器。
- `SurfaceOcclusionFit.json`：原生表面遮蔽数据的局部正高斯衰减近似，减弱内侧组织不合理的发亮；它没有改变鼻孔或嘴唇几何。
- `ReferenceEnvironmentFit.json` / `Environment.mjs`：环境辐亮度的低分辨率数值拟合与连续重建，不加载 HDR 图片。

唇部旧 ET 网格细化、塑形与几何刻沟阶段在本版构建中旁路；旧皮肤褶皱与表面结构位移的增量被关闭。既有头型预设、原生骨架、眼睛和耳部仍属于原平台，不把“新材质不改顶点”泛化成整个项目不使用模型或第三方底座。

## 复建与运行

需要 Node.js、npm 和支持 WebGL2 的浏览器。

```powershell
npm install
npm run build
npm start
```

本机入口为 `http://127.0.0.1:8905/`。服务器可以复用已有原生资源缓存；缓存缺失时从本平台固定的原生资源地址读取。浏览器和网络仍是既有平台的运行依赖。

正常复建只使用本目录内保存的系数与源码，不需要下载参考图片。研究采样与拟合在独立分析环境完成，原图、教师 bundle、模型缓存及逐点测量不随本版发布。来源、采样范围、失败尝试及误差见 `docs/reference-surface-study.md`。

## 验证范围

`qa-procedural.cjs` 在离屏浏览器中检查真实材质链接、16 采样器约束、教师资源依赖、顶点摘要、三种表面预设、人物切换、存档及移动界面，并生成当前画面的截图。脚本默认使用本机 Chrome 与当前 Codex 的 Playwright 路径；移到其他机器时需要调整这两个本机路径。

研究信号的方差保留率只衡量采样信号的近似重建；它不是整图相似度、医学准确性或视觉质量认证。原平台和历史版本的署名、许可及光学资料仍保留。

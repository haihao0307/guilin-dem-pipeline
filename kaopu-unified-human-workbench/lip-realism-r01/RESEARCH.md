## 1. 任务与证据边界

用户要求学习唇色研究和数字人方法，观察最新版人物总工作台，改善嘴唇的自然感；皮肤细节由另一条工作线处理。本专项应围绕现有人物的嘴唇做局部、可回退的改动，保留与皮肤工作线的明确接口。**本次保留母型、拓扑、绑定和全脸皮肤代码。首轮真实截图暴露继承主唇沟造成长条反光，因此只允许缩小原生唇红权重内的主沟幅度；不改变唇峰、体积、表情或皮肤几何。显示网格这一局部变化必须独立验证，并在关闭专项时精确恢复。**

两篇指定的 Wiley 论文提供的是**受控测量的局部唇色及其多样性**，没有提供一张能直接覆盖整唇的颜色地图，也没有给出完整的微几何、粗糙度和动态形变模型。把色表中的一个颜色铺满嘴唇，或根据族群名称固定唇色，都超出了证据支持范围。[S1][S2]

本文使用以下区分：

- `MEASURED_RELATION`：原研究实际测量或观察到的关系，保留样本及方法限制。
- `ENGINEERING_HYPOTHESIS`：为表达已知关系提出的程序结构和校准初值；不冒充生物测量值。
- `MEASUREMENT_REQUIRED`：当前人物的边界宽度、色差、纹理尺度、湿膜范围及性能开销，必须由实际观察或测试补齐。

## 3. 可直接转成程序的区域与参数

下表右侧均为 `ENGINEERING_HYPOTHESIS`，数值范围和视觉效果待实际人物校准。上表提供生物关系；下表不声称这些参数已具有生理量单位。

| 字段或蒙版 | 作用与依据 | 实现约束 |
|---|---|---|
| `lipDomainUpper` / `lipDomainLower` | 独立承载上下唇差异。[S1] | 根据现有真实外缘、内缘建立，使用稳定 UV 或静止空间坐标；避免一个椭圆盖住整块口周皮肤。 |
| `baseTone` / `upperToneDelta` | 基色与上唇相对偏移。[S1][S2] | 默认差异只是可逆初值；允许差值归零或反向。不得按族群锁定，也不强制“上暗下亮”。 |
| `edgeTransition` | 唇红与皮肤之间的局部边界。[S3] | 保留唇峰、唇角等实际形态；边界位置、渐变宽度待测，避免整圈同宽描边或向下巴晕染。 |
| `intermediateZone` / `innerMucosa` | 唇红向口内的组织变化。[S3] | 与嘴缝遮挡分开；不同区域可有不同纹理和材质响应，不用一条深红线代替组织结构。 |
| `pigmentField` | 局部色素深浅。[S7] | 使用有区域约束、稳定的低频变化；避免白噪声、随机彩点和完全左右镜像。它是外观控制量，不是真实黑色素浓度。 |
| `bloodColorField` | 红润程度及局部差异。[S6][S7] | 与棕褐色素独立；不把所有嘴角固定涂黑或把中央固定鲜红。不得命名为测得的血氧或血流量。 |
| `salivaFilm` | 表面水膜与镜面反射 | 与组织含水参数独立。[S4] 高光必须随灯光和视角变化，不能画在基色里。湿膜宽度、覆盖率和反射参数待校准。 |
| `foldPrimary` / `foldSecondary` | 主纹、横向短纹、分叉。[S5] | 上下唇分别控制，允许长度、间距、方向变化；不制造一排等长、等深、等距竖沟。形变时须跟随嘴唇，不能在世界坐标中滑动。 |
| `dryness` / `flakeCoverage` | 可选的干燥、局部脱屑 | 与年龄、唇色及水膜分开控制；本轮未标定个体脱屑量，不能默认铺满白屑或用深沟增加“真实感”。 |
| `mouthOcclusion` | 嘴缝、接触区域及口腔遮挡 | 应检查实际接触和光照遮挡；避免将一根粗黑线永久烘焙到基色中。 |

### 3.1 湿膜、组织含水和粗糙度不能合成一个概念

`salivaFilm` 描述表面液体造成的反射，`tissueHydration` 描述组织状态，`roughness` 是选定渲染模型的表面统计参数。S4 的位置测量提醒我们：不能用“越靠近口内”这一梯度，同时推导更含水、更红、更光滑。若建立联动，必须记录这是待校准的工程关系。

### 3.2 与皮肤细节工作线的接口

唇红区域应从普通面部毛囊、胡须根和常规毛孔生成域中排除。[S3] 粉刺、泛红等皮肤装饰也不能因为共享脸部材质而无条件穿过唇红边界。靠边缘的异位皮脂腺微点如需要表现，应作为独立可选特征；不因组织学上可能存在就给每个人默认添加。

边界接口应只提供稳定的唇部覆盖与过渡权重。不得为方便嘴唇改动而覆盖另一条正在开发的全脸皮肤程序；集成方式和具体允许路径由 root 的任务锚点确定。

### 3.3 颜色运算的校准位置

S1、S2 的 Lab/LCh 数值对应特定测量与颜色计算条件。它们可以检查色域和基色选择，但不能直接当成已经校准的 PBR `baseColor`。应明确区分输入色、线性运算、材质响应和最终屏幕色；在固定曝光、白平衡、相机和灯光下比较，避免用换灯光掩盖基色问题。

## 4. 普通开发者难以立即实现的实际约束

| 约束 | 为什么会阻碍快速完成 | 本轮应怎样收口 |
|---|---|---|
| **缺少校准数据** | 普通照片混合了曝光、光源、白平衡、表面反射与后期处理；仅凭一张照片不能唯一分离色素、粗糙度和散射。[S1][S2] | 先把同一人物的受控对照固定下来。没有原始光谱、偏振、多光照数据时，只宣称外观改善，不宣称反演出真实生物参数。 |
| **缺少全唇空间测量** | 指定论文的局部 ROI 和群体色表没有提供唇角、干湿界面、唇峰的通用纹理地图。[S1][S2] | 这些部位标记 `MEASUREMENT_REQUIRED`；通过实际基线观察调整局部场，不用随机噪声填满未知区域。 |
| **几何和接触问题** | 嘴唇体积、唇峰、外翻角或闭口接触线错误时，颜色无法修好轮廓；表情还会暴露裂隙、穿插和贴图滑动。 | 先检查现有几何与中性表情，再分别验证颜色、材质和运动。本研究不独立诊断几何；候选对继承主唇沟的局部调整及验证结果见实现记录。 |
| **样本外推** | 主要唇色研究为成年女性；组织学样本较小且部分偏老年。群体相关性不决定某个人。[S1–S7] | 参数允许独立变化，避免族群或年龄决定论；儿童、男性及未覆盖肤色的精确标定保持未知。 |
| **渲染和运行成本** | 高分辨率纹理、额外纹理采样、复杂散射、多层透明湿膜、动态法线与形变都有资源成本；小高光和细纹还可能闪烁。 | 优先局部蒙版、稳定坐标、缓存静态场和适当像素过滤。记录构建、启动、CPU/GPU 帧耗与内存的实测增量，不以“纯程序”推定开销低。 |
| **多模块集成** | 皮肤工作线并行变化，若嘴唇修改共享全脸材质，容易覆盖别人的成果或重复染色。 | 保留来源版本与局部接口；只让一个 owner 修改共享权威文件，集成及回归由 root 核验。 |
| **参考资产权利** | 可阅读论文不自动等于可把其中人像、色卡截图和第三方贴图改成商用资产。 | 本文只引用与归纳方法；不复制论文图像进运行时，不新造参考图。需要引用图像时单独核查具体许可。 |

资源规模可以先算，但计算不能代替测量。例如，一张未压缩 2048×2048 RGBA8 纹理的基础数据约为 16 MiB（宽×高×4 字节）；实际显存还受 mip、格式、驱动与副本影响。这只是工程算例，不是本候选已测内存。帧率、移动设备能力和新旧版开销差异全部待 root 实测。

### 5.2 候选待验证项目

使用同一实际人物、同一表情、同一尺度和明确标注的 baseline/candidate 对照。先检查正面与近正交视角，必要时辅以侧向视图；禁止采用会造成大小误判的反常透视。保留既定 EB1，另用固定的中性控光观察基色，分别记录用途。

## 8. Epic 数字人方法如何用于当前平台

用户提供的 [Epic Digital Humans（UE 4.27）](https://dev.epicgames.com/documentation/unreal-engine/digital-humans?application_version=4.27) 已核读。文档将底色、粗糙度、反射、散射及法线分别处理，并说明中尺度法线可随表情混合、微法线用于更小细节。其双反射瓣组合不同宽度的反射；唇、牙齿等散射材质相邻时还需控制屏幕空间串色。**本项目采用通道分离和多尺度检查原则，没有声称移植 UE 的扫描资产、双瓣模型或次表面散射实现。**

当前母台采用 Three.js WebGL 材质。依据 [Material.onBeforeCompile](https://threejs.org/docs/pages/Material.html) 与 [MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)，本模块在既有最终材质链之后补充唇部字段，沿用其表面反射与局部 clearcoat 表达湿膜；clearcoat 不是完整体积散射，transmission 也不能直接等同皮肤 SSS。额外着色计算即使没有新增贴图也有成本，因此需要对原版和候选的同机实际帧耗作比较。

依据 [Three.js 色彩管理](https://threejs.org/manual/pages/color-management.html)，颜色应转换到线性工作空间再参与光照。底色观察通道用于把色彩问题与高光问题分开；它显示的仍是经过渲染输出流程的屏幕结果，不是新的实测光谱或临床数据。法线和粗糙度等数据场不应当作 sRGB 颜色处理。

以上实现说明由 root 在 2026-10-17 补充。具体候选是否编译、运行、公开可用，以及视觉差距是否缩小，仍以本轮独立 QA 和实际截图复核为准。


## 9. 第一轮真实运行后的修正依据

2026-10-17 的 Chromium run `39017094445` 已实际运行原 R07 与首版候选。原版／关闭专项的正面和嘴部画面、几何逐项一致；开启后口周以外仍有一个像素发生 1/255 级差，因此该轮未通过、未公开发布。候选真实截图同时呈现过强的深红色块与硬唇缘，不能作为自然裸唇接受。后续修正降低基色的红绿差，在唇缘内部加强局部组织过渡，范围权重为零时跳过材质赋值；这些修正的效果仍须新一轮证据验证。

源码追踪还确认：原 `LipBiomechanics.apply` 将主沟高度乘 `microGeometry × q.red` 后写入显示顶点并重算法线，替换片元高度不能消除该部分。候选改为仅在原同步 `mother.update` 执行期间把主沟幅度乘 0.35，立即恢复原 DNA 数值；每次由原无沟派生表面重建，不累积修改。0.35 为基于当前画面的制作起点，不是人体实测比例。独立检查应限定变动到原生唇红顶点及法线一环，并验证 canonical、索引、绑定、其他 DNA、表情、灯光与关闭还原。

## 10. 第二轮真实截图与档案恢复发现

Run `39018341941` 的真实 Chromium 证据通过前六项检查：原 R07 还原、三个视角的局部像素与几何范围、四项材质诊断、全部制作参数、可信滑杆事件，以及原生张口／噘嘴及其档案还原。三个中性视角在保守口周矩形以外的 RGB 差均为零；显示位置变化最大约 31.93 微米，张口约 38.36 微米、噘嘴约 53.86 微米。原生唇红范围外位置变化和移动顶点拓扑一环外法线变化均为零。这里报告的是新旧网格的差值，不是人体组织的实际沟深。

Root 与独立审查者查看实际 before/candidate 正面、嘴部及斜侧图后，一致看到原下唇强白亮长条明显减轻，默认唇色与脸部更协调，唇峰、下唇饱满度和嘴缝连续性保留。上唇色素覆盖仍较均匀，噘嘴近景仍有轻度裸色口红感；原张口画面中的块状牙齿、硬口腔边及口角小折片在关闭新版时同样存在。因此不能宣称整个口腔已经写实，或当前裸唇已等同真实扫描。

该轮第七项在切换两个原生人物、再载入原档案后发现显示 position/normal 哈希不同；canonical、rest、拓扑仍精确相同。公开发布被阻断，性能测试尚未执行。源代码表明原生 `reference` 与 `referenceHorizontal` 校准缓存参与主沟拉伸增益，却未进入原档案；其初始化历史可以随人物切换改变。后续修复在新 `lipRealism.calibration` 中保存这两个数组和来源 key，完成原人物载入后恢复参考并重建显示几何。独立验证会对照缺少校准段的旧路径及完整新档案，并要求参考数组、完整显示几何及像素精确还原；验证前仍把具体运行因果标为待确认，不通过放宽哈希或像素标准消除失败。

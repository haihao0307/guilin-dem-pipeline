# 人物总台 · 嘴唇专项 R01

本目录在当前 HUMAN-INTEGRATED-R07 / SKIN-FULLBODY-R02 的真实人物上改善嘴唇。它使用原有头部、全身、骨架、人物档案和动作系统；运行时没有新增替代嘴唇网格或参考照片贴图。

## 打开和判断

经验证的固定 HTTPS 入口与其源提交、构建摘要由 `PUBLICATION_PROOF.json` 记录。没有该文件或 `publicHttpsPassed` 不为 `true` 时，不把某个原版入口当作本轮完成交付。用户视觉验收与机器检查分别记录。

进入页面后，先使用“嘴部正面”，在“本版嘴唇 / 原版嘴唇”之间切换。此开关保持镜头、灯光、人物身份和表情；新版会同时采用独立唇面材质及较轻的原生主唇沟。再查看“整脸正面”和“嘴部斜侧”，避免只按极近景判断自然程度。

“红润程度”“棕褐色素”“上下唇色差”和“局部色彩变化”控制颜色。“内缘湿润反射”和“外露唇面粗糙度”控制表面响应。“细纹起伏”控制较细的程序法线细节。观察通道可分别查看作用范围、底色、粗糙度和法线。湿膜控制不改变底色，色彩滑杆不改变几何。所有数值均是制作参数，未标定为人体组织浓度或临床测量值。

保存完整人物会保留原平台档案，并增加 `lipRealism` 参数段。载入不含该段的旧人物档案时采用本版默认唇面参数；原有身份、DNA、唇形和动作数据仍由母台处理。

新档案还包含原生唇纹的参考校准。原系统用这份历史参考计算纹理随拉伸的起伏，却没有将它写入原人物档案；切换人物后重新校准，可能在身份和 DNA 相同的情况下产生很小的显示差异。本模块用明确的小端 Float32 编码保存两个参考数组，在原人物载入完成后恢复并重建一次。没有校准段的旧档案仍走兼容路径；这一补充不重写原人物的形态参数。

## 这次解决什么

源码追踪确认，R07 的新皮肤材质保留 ET19 顶点流程，但替换了旧唇部片元着色。只修改旧 `LipOptics.mjs` 并不能可靠改善当前总台。因此 `LipSurface.js` 等待最终全身皮肤挂接和原人物加载完成，再追加唇部字段。

第一轮真实浏览器图像暴露两个需要继续修正的问题：全唇色块偏红且唇缘生硬；原主唇沟仍产生长条反光。后续实现降低默认色彩对比，在唇缘内部加入局部组织过渡，并分别控制干唇面和内侧湿膜。细纹采用不同长度、弯曲、分支及弱横向变化，并随像素覆盖过滤；它不把整齐的深沟当作自然感的替代。

原主唇沟已经写入显示网格。模块仅在同步的原生 `lipStructure.mother.update` 调用期间，将 `microGeometry` 的有效幅度乘 `0.35`，并在 `finally` 中恢复原 DNA 值。母台每次先从原 source 重建显示表面，因此没有累积衰减。原生唇峰、唇珠、体积、表情、口腔接触及身份参数不受此系数控制。这个比例来自当前画面的工程调整，不能引用为人体实际沟深。

## 隔离与后续皮肤集成

`build.cjs` 对冻结 R07 HTML 校验 SHA-256，再在新目录生成追加模块的预览。移除追加部分后必须精确恢复原 HTML，原有两个脚本的哈希也必须相同。它不会调用会清理原证据的 R07 构建脚本。

本 PR 的允许路径只有本目录和 `.github/workflows/lip-realism-r01.yml`。Codex 的皮肤工作可以继续。未来集成新的皮肤版本时，应先核实新的最终材质链，再更新显式锚点和冻结摘要；不要简单覆盖七个原皮肤模块，也不要删除“锚点改变即失败”的保护。

与皮肤工作线交换的边界是本人的原生唇缘、静止坐标和局部唇红覆盖。普通毛孔、胡须根等细节应在各自生成域里避开唇红；本模块对颜色、粗糙度、微高度和局部湿膜取得最终控制权。覆盖域包含需要修正的旧唇色羽化区域，不能夸大成每一个几何唇红之外的像素都完全不变。

## 验证内容与真实限制

`verify.cjs` 独立从原平台获得人物几何、绑定、唇红权重和口周投影区域，而不是相信新模块的成功标记。它检查原版还原、真实着色器链接、同镜头同灯光对照、九项参数、真实滑杆事件、原生张口和噘嘴、人物与肤色变化、档案恢复、局部几何边界，以及同机原版／候选的微距和头颈帧耗。

允许的显示位置变化只在原生 `l19State.z > 0` 顶点，法线变化只在实际移动顶点的一圈邻域；canonical、索引、顶点数和蒙皮绑定不变。口周保守矩形以外的 RGB 比较保持零容差。关闭专项后要求原版几何和画面精确恢复。100 微米是回归检查上限，实际位移以 `geometry-*.json` 为准，不用上限冒充测量结果。

通过候选检查后，工作流只向本 feature 分支普通快进提交，再以固定提交的公开 HTTPS 页面进行独立回读和真实浏览器复测。它不合并主线、不强推、不修改其他工作分支。

运行证据来自 Chromium WebGL 与 SwiftShader；同步帧耗不是用户 GPU 的帧率承诺。390×844 视口检查不等于实体手机认证。原母台仍使用既有的冻结远程人物数据读取，本目录没有声称整个运行时完全离线。表面 clearcoat 只表达局部湿膜，本版没有实现或测得完整体积次表面散射。

研究全文与第一手来源见 `RESEARCH.md`。最终机器结果见 `PUBLIC_QA.json`、对应运行的 `evidence` 目录和交付记录；机器成功不自动成为用户视觉验收。

第二轮实际截图已显示：主沟中的白亮长条减弱，默认唇色比首轮协调，唇峰和下唇体积保留。上唇仍有轻度均匀着色感，原张口状态的牙齿及口腔边界也未达到扫描人物的观感。这是本轮图像的明确限制，不用参数或机器检查通过来替代视觉判断。

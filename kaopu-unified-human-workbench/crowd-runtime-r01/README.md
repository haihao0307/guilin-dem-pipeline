# 完整人物多人运行台 R01

同一三维场景、同一 renderer 中运行 1 / 2 / 4 位人物，将原 P01/R07 身体与动作、F13 完整发丝、T03/P02 实体服装及 R14 帆布鞋实际接在一起。每个所选模块保留原显示部件；各自的物理范围如下。

[打开固定 HTTPS 试用页](https://htmlpreview.github.io/?https://raw.githubusercontent.com/haihao0307/guilin-dem-pipeline/2a80bd5d584a3bb64610ebc27ed468eb490065fb/kaopu-unified-human-workbench/crowd-runtime-r01/public.html)。首次载入会准备完整原始发丝并适配衣物，请等待“完整人物已就绪”。

打开本目录 `public.html` 的固定 HTTPS 发布入口。准备完成后，可切换人数、行走/跑步/跳跃/静止，开始、暂停或单步；拖动旋转视角，滚轮缩放，选择人物后近看与移动。测量按钮记录当前配置的 60 个完整求解步骤。

测量期间锁定人数、动作、物理设置和视角；可以点击“暂停并中止”结束本次测量。记录会区分中止和完整的 60 步，不混合两种配置或把中止写成测量完成。

每人只有一个最终骨骼姿态来源：主控每步推进一次原动作，衣物和头发读取同一最终姿态。所有人物的衣物响应完成并接受当前步后才提交整场画面。原求解安全门槛保持；发生拒绝时冻结最后已提交的画面，等待完整重建。

身体、头发和同款鞋共享原静态几何、纹理及固定材质输入；每人的骨骼、身体/头发材质中的形变状态、头发求解和衣物 Worker 状态独立。鞋的配尺只作用于完整原鞋的对象变换，原 buffers 和身体足部保留；鞋底厚度也随整体高度比例变化。内层三角截面检查属于采样贴合证据，完整穿着效果仍需验收。实现与来源见 [身体/鞋](src/actors/README.md)、[头发](src/hair/README.md) 和 [衣物](src/cloth/README.md)。

## 测量与范围

记录包含动作计算、头发求解、衣物等待、CPU 渲染提交、提交完成间隔及绘制提交数。页面 FPS 是完整更新与渲染提交的速率；没有测量 GPU 完成或屏幕真正呈现。模拟时间与实际经过时间分别列出。衣物 Worker 与头发计算有重叠，其用时不能直接相加。

- 当前为整合试验；穿着与最终视觉验收仍待用户确认。
- 头发选用此前公开的 F13 密发候选，未宣称更新的头发结构线已验收。
- 衣物采用原骨骼参考上的区域物理，没有逐纱线受力、完整自由布料、完整自碰撞/CCD 或任意叠穿求解。
- 鞋没有足底压力、材质受力或动态弯折求解；静态配尺不等于鞋材力学或舒适度验证。
- 未实现头发与衣物之间、跨人物之间的力学接触耦合，亦未接入 NPC 生活行为。

[浏览器记录](validation/README.md) 按候选版本保存。首轮 `*-first.json` 来自旧网页候选，已暴露鞋包头贴合问题；它们不证明当前修订或鞋已验收。当前源码的局部回归与后续新候选的实际画面证据分别记录，旧报告不改写成新版本结果。人数切换会改变构图和原服装的连续像素采样，首轮不同人数结果不构成受控的扩展效率比较。

## 可重建源码

`src/` 为本次接入与调度源码。原始依赖在固定 SHA 清单中记录，构建时按原字节恢复：

```bash
npm install
python3 build/prepare-sources.py
python3 src/cloth/prepare-upstream.py
node build/main-bundle.mjs
python3 build/pack-app.py
```

构建依赖 Node、Python 3 与 esbuild；版本见 `package.json`。`CROWD_ESBUILD_PATH` 可指定安装后的 esbuild 模块路径。网页加载时校验原 F13 运行包以及本轮运行包的完整 SHA-256；初始化衣物时仍需读取固定 commit 的原人物/SDF/衣物资产，不从移动分支读取人物内容。

各适配器目录的 `verification.json` 记录其独立验证；公开浏览器证据单独存放。局部测试通过不等于完整画面已验收。

此目录独立于 NPC 生活观察、服装叠穿修复与更新的头发结构分支，提交为 Draft PR，不合并主干。

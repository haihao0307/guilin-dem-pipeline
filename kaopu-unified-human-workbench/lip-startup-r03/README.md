## 证据纠正

用户实际截图显示“载入失败：signal timed out”，底部为下载76.9 MiB、缓存复用0.0 MiB。此前P2记录把它描述成“程序 HTTP404”是误读，已在PR #234补充纠正。404故障注入只证明该测试场景，不能作为用户发生404的证据。

## 实际代码改动

保留P2内置程序、正式Pages同源发布和原有完整人物。对固定摘要的应用包只替换原始模型字节读取接口，并更新本版本资源前缀；后续原生数据解析、解压后校验、模型构造、嘴唇形变、皮肤和眼球渲染不变。构建采用显式函数边界和原程序SHA-256断言；它是当前固定版的适配，不是可盲目套用到未来任意打包程序的通用补丁。

26个模型传输文件共84,045,179 bytes，拆成93个不超过1,048,576 bytes的小块。每块完成SHA-256校验并写入缓存后才记作完成，组装完整文件后再检查原文件摘要。恢复单位为已经完成的小块；一个只收到部分数据的小块仍需重下，不冒称HTTP Range字节级续传。存储写入失败时会警告并继续使用已校验数据，但无法保证该块跨刷新保留。

重试覆盖响应头、响应体断开、长度错误及校验错误。连续30秒没有新数据时才中止当前尝试，最多3次；仍有数据持续进入时，不因累计90秒或150秒而杀死下载。404/403等不可由重复下载修复的响应直接给出具体错误。模型下载最多3个并发请求。

页面提供暂停、继续载入、已校验数据/总量、缓存复用量、当前文件和分块、重试次数、复制诊断。原加载器会自行捕获错误，所以新增显式错误边界，不再仅依赖unhandledrejection。就绪后的诊断按钮放在原嘴唇控件内，不覆盖画布或原导航。

P3仅写自己的kaopu-lips-verified-chunks-p3缓存，预算128MiB，淘汰仅限本缓存；兼容的P2完整文件缓存只读复用，不删除或覆盖。这个预算不是浏览器全部磁盘、运行内存或显存上限。人物档案、localStorage和其他项目缓存不清除。缓存拒绝、配额和淘汰会影响刷新后的复用，网络校验加载仍可继续。

## 实现和使用边界

首开仍有约84MB模型传输数据，另有内置程序与贴图，不能称作1MB即可完整打开。拆块增加请求数，并非所有顺畅网络下都更快；目标是失败不丢掉已经完成的下载。

不承诺用户设备秒开。浏览器缓存被拒绝或淘汰、站点连接完全不可达时，恢复能力有边界；完整模型的RAM、显存和初始化计算没有因此消失。旧的嘴唇、口腔交界与整脸视觉质量问题未在本轮改造，也不宣布全口腔连续碰撞或影视级画质通过。

旧P1/P2/ET19与其他人物模块源码未改。新运行时和测试只在lip-startup-r03及两个专项workflow。可选旧动作研究和外部文档仍保留原路径，未验收整个总平台离线运行。

## 为什么做这一轮

接手任务已定位到 `haihao0307/guilin-dem-pipeline` 的嘴唇专项。R01.1 完成了旧皮肤面板保存完整人物时遗漏嘴唇参数和原生校准的修复，但没有改变视觉效果。继续检查当前画面后，本轮锁定一个可见缺陷：程序化唇纹的主线长度、方向和分支过于相似，仍有连续刷纹感。

R03 从 R01.1 已验证的交接头 `57cfade66fb37c260df1dcd836f5cd239cccef41` 派生，隔离在 `feature/lip-detail-r03-20261018`。这是同一原生人物的细纹材质改动，不是新的替代模型。

## 页面中的对照

- **本版细纹**：使用 R03 的有限长短纹、较浅的斜向细节和稀疏分支。
- **上一版 R01.1**：调用保留的原细纹函数。切换只改变这一个表面分量，人物、唇色、粗糙度、湿润、镜头和灯光保持相同。
- **原始 R07**：保留最早原人物材质的对照。它有不同的原生粗纹起伏，不能替代上一版 R01.1 的比较。

原有正面、斜侧、整脸、头颈镜头和全部嘴唇参数继续使用。`细纹起伏` 为零时，R03 与 R01.1 对照的细纹差异应完全消失。

完整人物档案记录所选表面版本和两组原生唇纹校准数组。嘴唇面板、旧头部皮肤面板、身体面板和完整人物 API 沿用 R01.1 的统一存档路线。

## 验证要求

实际结果以本轮 CI 和原始 `qa/` 为准，以下是门禁而非预先宣布的通过结果：

1. 两个人物、闭口与轻张口的同状态实际画面对照；R03 的 R01.1 模式必须匹配固定公网旧版。
2. 原生几何、拓扑、校准、颜色和粗糙度不变；嘴唇独立边界外的像素不变。
3. 原有与新增比较按钮、细纹滑杆、强度归零和往返恢复实际有效。
4. 各完整存档入口产生相同档案；一个完全新建的浏览器上下文仅凭导出的 JSON 还原非默认人物、所选细纹、校准和同条件画面。
5. 固定公网 HTML 正文、关键资源、桌面与 390×844 浏览器视口检查，实际 GPU 同步比较，以及全部浏览器进程正常收尾。
6. 生产者之外的审查者检查源差异与实际图像。自动测试成功不等于用户最终视觉认可。

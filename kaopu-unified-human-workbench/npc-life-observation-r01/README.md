# NPC 生活动作观察 R01

在当前 R07 完整人物上验证一个可重复的小闭环：身份分工、共享物品预约、实际表皮接触、有限力辅助握持、刚体拿放和真实世界结果回执。

## 本轮实际范围

- 三个完整原生人物：`tall-slim / P01`、`short-heavy / P02`、`sturdy / P05`。形体由现有生成器及人像预设生成，不以根节点缩放替代。
- 保留原生 104 骨骼、完整 CSR 蒙皮影响、完整显示网格与两组 R07 程序皮肤。
- 固定桌边站位。上肢用原生骨骼 IK 与逐人物、逐侧标定的抓握姿态；不延长骨骼补偿不可达目标。
- 水平环抱竖直瓶身：从实际凸起掌垫选择接触点，按完整原生手部表皮对有限圆柱求各指首次接触和闭合上限。标定无解时禁止握持。每侧检查 21 个开合姿态，运行时再检查物品实际位置和旋转下的表皮间隙。
- 一件真实共享刚体物品、一张可移开的刚体桌面和可移动收纳区。物品状态来自 Cannon 模拟，动画不能直接改写搬运中的物品位置。
- A 整理、B 等待或接手、C 读取实际释放/支撑/稳定结果并复核。身份分工是显式规则，不是开放式语言模型规划。
- 预约与握持分别记录，实际握持约束最多一个。中断会释放约束与占用；物品继续受重力影响。
- 成功需要实际释放、进入当前收纳区、碰到真实支撑面并稳定。撤走支撑或改变目标能改变结果。

这不是完整人体动力学、手指摩擦抓握、室内自主导航或跨设备联机。单场景内多个 NPC 共享一个权威物理世界。手部使用接触后有限力辅助约束；这项假设在界面与数据中明确记录。

## 使用

进入公开观察页后可依次尝试：

1. 切换 A / B / C，点击人物拿放，再切换“手部接触”或“侧面”。
2. 点击“按身份开始整理”，观察 A 执行、B 等待、C 复核。
3. 在抬起后点击“中断当前持有者”，观察约束释放及 B 接手。
4. 在搬运时移开支撑面，观察物品真实下落与失败回执。
5. 运行本页六项验收，或展开实时数据并导出当前 JSON。

JSON 包含物品位置、四元数、速度、质量、尺寸、持有人/预约、任务阶段、结果、事件与明确的实现范围。

## 构建与验证

```sh
node prepare.cjs
node build.cjs
```

构建从固定 canonical R07 源读取并验证 SHA256，不修改原文件。新增程序与 Cannon 内联，Three 使用原宿主同一实例。在线版本保留原生数据的固定版本网络装载，不宣称离线通过。

最终 HTML 的每段脚本都会单独进行语法检查，包括构建注入和第三方许可。`BUILD.json` 保存宿主、生成文件和各源文件哈希。

项目 Chromium CI 的 `verify-browser.cjs` 会检查实际 GPU 程序与画布、原生人物来源及骨骼/材质完整性。`NPC_QA_PHASE=suite` 还执行三人的实际 UI 拿放、六项观察流程与 390 × 844 视口检查。每次结果与截图保留于对应工作流产物；软件渲染环境与实体手机性能明确区分。

观察器保留完整源渲染，以 WebGL2 fence 保证最多一帧 GPU 工作在途。相机及物理更新合并到下一帧，暂停时停止重复提交同一画面；实际绘制完成耗时与 JavaScript RAF 间隔分别记录，长停顿不会从统计中丢弃。人物材质各自保留 uniform、皮肤及骨骼纹理；相同着色器代码只共享程序缓存。

只有本地真实浏览器完整检查通过后才发布新的源提交目录，随后回读该固定公网 URL 的 HTML 与 BUILD 哈希，并用 `NPC_QA_PHASE=public` 启动原生人物、完成一次真实 UI 拿放、检查 390 × 844 视口。

独立物理因果检查在 `qa/motion_sources-causal.mjs`，使用真实生产 `LifeWorld` 与 Cannon，但运动输入是标明的隔离测试桩。它能证明物品物理和状态逻辑，不能代替完整人物的浏览器检查。

## 发布规则

只向新的按源提交分隔的目录发布。旧总平台与既有公开版本不覆盖，功能分支保留 Draft PR，不自动合并。发布后还需在最终公开 URL 回读同一 HTML 哈希、启动完整人物并实际操作；未取得这些证据前不能称为已完成交付。

用户视觉验收与生产就绪始终分开记录，自动测试通过不代替用户验收。

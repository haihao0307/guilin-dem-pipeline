## 2. 本次采用的技术决策

### 2.1 延续原运行时，交付独立的 R02 研究范围

R02 沿用既有 Three.js / WebGL2 / ES modules 运行时，保留原人物、原衣物材料与实体纱线表现。此决策用于在相同人物和材料基础上验证独立叠穿、接触修复与有证据的减负，避免在同一次验收中混入渲染后端或语言迁移造成的变化。

母本的 WebGPU / TypeScript 总体路线继续保留。当前实现与该总体路线的差异在此明确登记，不将 R02 的通过表述为 WebGPU 或 TypeScript 迁移已完成。01 §21 的阶段计划亦保留 WebGPU 回退工作；具体后端升级需要另行实施与验收。

R02 采用独立发布路径。R01 和其他项目的保留以既有逐树核验记录为依据，本说明不改变那些路径和内容。

### 2.2 一个原人物，三件独立衣物

本次衣物为高领内搭、V 领外层与原款短裤；各件保留独立身份和几何，并在共享物理求解中处理相互接触。

02 的“场景中只能存在一个最终人物表皮”约束的是人体 Skin，不要求把服装合成单一网格。对齐参考几何与碰撞数据不作为第二个可见人体表皮。参考体几何包的减载不等同于删除、替换或简化当前实际人物表皮。

叠穿功能不通过改变人物比例、骨长、父子层级或骨骼缩放来解决衣物问题。摄像机、单独查看与分开查看属于显示状态；显示变换不作为物理几何或接触求解结果。

### 2.3 保留来源与可回溯性

原始上游资产与派生适配分开保留，并记录来源和内容摘要。固定提交、来源记录、验收证据及独立发布路径共同提供本次结果的可追溯依据。对实现与母本的差异，按 01 §27 保留技术决策和阶段边界，不把尚未实现的方案写成已完成能力。

## 4. 六项验收通过的作用范围

固定候选的 `native-baseline`、`native-perturb`、`display`、`demand`、`continuous`、`reentry` 六项验收已通过。它们支持对应测试条件下的几何、显示、接触、持续模拟、卸下重穿及按需更新结论。具体计数、阈值、运行条件与原始证据以该候选的验收报告为准。

原生数值回放按其记录对每个离散状态进行检查；浏览器验收包含实际界面操作、物理步回复和选定状态的独立全几何检查。不能将二者混写成浏览器每一个物理步都进行了全三角审核，也不能从截图推出任意连续运动下均无穿插。

六项通过不代表达到实时性能。01 的接近 60 FPS、16.7 ms 帧预算、分项求解预算与交互延迟是总体性能目标；本次没有据此宣称普通设备或所有场景已经达标。固定物理步长、模拟时间推进和真实墙钟耗时必须分别描述。

## 5. 已实现减负与未实现能力的边界

本次按需上传依据精确几何变化和实际显示需求，保留最新物理状态；显式隐藏衣物可以延迟显示更新，恢复时采用最新变形。隐藏期间承担接触和结构约束的内层仍参与物理计算。参考体减载、避免重复上传及到期缓存清理的效果分别以相应证据为依据，不合并成未经测量的整体帧率或显存收益。

目前没有把被外衣覆盖的区域自动裁掉，没有用不透明替代面遮住实体针织孔洞，也没有将一次遮挡判定转成永久裁剪或物理休眠。母本关于后台窗口降低刷新频率的要求，不能解释为隐藏内层可停止碰撞和结构计算。自动遮挡、可靠休眠与唤醒、任意动作下的连续防穿插仍需独立设计与验证。

## 6. 后续记录方式

本说明作为发布后补充证据独立保存。未来接入统一人物状态、动态最终姿势或更换渲染后端时，应按 01 §24、§27 和 02“文件维护规则”分别记录输入、数据版本、实现、客观验收条件、结果、风险与回退方式；已有 R02 的验收结论只对应其固定候选和已测试范围。

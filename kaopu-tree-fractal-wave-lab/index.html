KuKo 老师带来的，是确定性路径寻址、局部变换链、SDF 并集、查询剪枝和节点风相位。R05 树生命母台继续负责 Seed、Root↔Shoot、主干与半径、生命历史、树叶和三维连接。两个系统在这个工作台里共同训练，但老师的二维画面不会被误写成真实三维树。

① 分枝路径寻址

TOTAL / BR / off / dec / path

把整数枝号解码成每一层的选择，成为可复现的谱面地址；不必先把全部节点烘焙成模型。

② 局部变换链

R(angle) × disp(distance)

每一级只在自己的局部框架里转向与前进，适合作为分枝演奏指令；三维版仍需补局部正交框架。

③ SDF 并集

min(branchDistance, leafDistance)

适合轻量老师预览、结构对比和像素查询；它不能证明三维截面、连接与受力正确。

④ 整组后代剪枝

c += off - 1; break

当前像素不可能命中时跳过整个子树，是运行期查询优化；它不是“近处换高模”的传统 LOD。

⑤ 节点风相位

wind0 / wind1

风进入指定语法节点，而不是整体平移画面；进入三维树前还要升级为从主干到枝叶的力传导。

⑥ 二维→三维 Lift

XY teacher lock + independent Z

先把老师的逆查询链重建成正向节点图，再给每个局部节点增加 Z 自由度。二维投影不随 Z 改变，所以可以随时压回老师平面检查；Z 目前只是假设声部，不冒充物种事实。

⑦ 原生三维 Bud / Field

Bud(T,N,B) → 3D Field → Shoot

不再固定 XY。潜在芽先在三维局部框架中产生，再读取光、空间占据、重力、障碍和父轴连续性；只有被释放的芽才真正生成枝条。

⑧ 三维空间哈希 / 感知体积

Bud Perception → SpatialHash → Occupancy feedback

R03 不再让每个芽全局扫描整棵树，而是在局部三维感知体积里查询已占据空间；新 Shoot 立刻写回哈希，后来的芽看到的是一个已经被改变的世界。

⑨ 下游支撑反传

tip load → parent support → radius

枝条生成后，从末梢向基部反传支撑需求，让粗细开始服从三维拓扑与下游负载，而不是简单按递归层级缩放。

树知识继续保留

Seed → Root + Shoot → History

根和冠不是镜像；年龄改变拓扑；受光只影响地上、水分只影响地下；根、干、枝、叶继续由三维函数生成。

当前阶段已经分成四层：老师 R01 保持二维原谱；Lift R01 验证二维理解；Native 3D R02 建立三维 Bud / Field 因果关系；Native 3D R03 把三维感知体积、空间哈希、占据反馈和支撑反传并成可继续扩展的三维总台。R03 仍然只是演奏技巧，不绑定 Pandanus 或任何具体树种。

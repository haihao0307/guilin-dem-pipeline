# Ocean Mother 当前实现答卷

日期：2026年9月7日。答卷依据 V0.3.11 全量包、当前工作分支和小妈 Ocean Coast R1 的十道问题整理。

当前接续分支为 `work/ocean-mother-r01812-depth-materials-20260905`，HEAD 为 `6f07e94069ad4833eda6204ec0d5cd45f8ebf5a4`。这个 HEAD 只增加 Three r185 离线子集准备工作流。

## 2. 海底、静态海面、潮汐和动态波来源

当前近岸海底来自 `terrainHeight(p)`。岸外部分使用程序化海床公式，岸内部分组合沙滩、坡地、山体、沟谷和岩石。它没有接入实测 DEM 或真实 bathymetry。

当前近岸没有单独保存永久静态海面。动态表面由 `waterHeightAt(p, sd)` 计算，包含三组解析正弦涌浪和三层 `breakerBandAt` 破浪抬升。

当前近岸没有 `eta_tide` 潮位层，也没有由潮位与海床相交产生的动态 wet shoreline。

冻结深海 V001 属于另一套解析 Gerstner 海面，并暴露自己的 `sampleHeight`。它与当前近岸 R018.11 没有统一为同一个 WaterBody 查询接口。

## 3. 可见海面与水位、浮力、碰撞查询是否同源

近岸着色器内部的水面命中 `traceWater`、法线 `waterNormal` 和着色 `shadeWater` 都读取 `waterHeight`，所以内部可见交点和法线具有同源基础。

当前网页没有近岸对外的世界水位查询、浮力查询或碰撞接口，也没有 CPU 与 GLSL 的逐点一致性证据。完整 Render Query 门禁尚未通过。

## 4. 当前波是否包含水平位移

当前近岸 `waterHeightAt` 是单值高度场，只改变 Y 高度，没有 XZ 水平位移。当前近岸查询无需反求参数坐标。

冻结深海 V001 使用 Gerstner 分量并含横向位移。它的 `sampleHeight` 需要另行审计输入空间和逆映射，当前学习接入不修改冻结深海。

以后在近岸加入水平位移时，世界查询必须求解参数坐标 `q`，并报告残差、迭代次数和近似状态。本目录的 `reference-kernels.mjs` 已提供隔离参考实现。

## 5. 主波、小波、泡沫和材料函数

主波与破浪高度：`waterHeightAt`、`breakerBandAt`、`swellExposure`。

水面法线与命中：`waterNormal`、`traceWater`。

泡沫外观：`foamField`、`foamFilament`。它们根据位置和时间即时求值，没有独立覆盖状态、寿命、输运速度或消退历史。

卷浪与飞沫体积：`curlDensity`、`sprayDensity`。当前用于可见体积近似，没有形成完整自由表面或守恒液体。

水材质：`shadeWater`。它组合简化 Fresnel、固定调色板、几何水深指数项、泡沫和太阳高光。

## 6. 水面界面与水下介质是否分开

当前只完成部分职责分开。`shadeWater` 同时处理界面反射、固定水色、水深混色和泡沫。代码没有独立的 `WaterVolumeOptics` 对象，也没有按米制光程保存 `sigma_a`、`sigma_s` 和悬浮物状态。

卷浪、飞沫和烟在后续体积步进中另行累积，但这条体积循环没有构成水下介质模型。

## 7. 浅水与深水颜色来源

当前使用真实几何差值 `p.y - terrainHeight(p.xz)` 估计水深，再用指数函数控制浅水权重。颜色来源仍是固定 `deep`、`shelf`、`lagoon` 和 `seabed` 调色板及经验混合。

它具有水深驱动关系，尚未使用沿视线光程的吸收与散射积分，也没有把真实底部材料通过水体介质观察出来。

## 8. 岛体、海底和烟场边界表示

岛体边界由 `shoreDistance(p)` 隐式定义。海底和陆地由 `terrainHeight(p)` 定义。水面与岸体通过水深和命中顺序发生视觉关系。

当前烟由 `smokeDensityAt(p)` 中四个程序化源直接生成。烟的横向漂移随高度和风参数变化，密度没有历史状态。它没有固体占据查询、岛体防穿透、有限域开放边界或离域后消失的连续输运证据。

## 9. 第一块 Render Query 实验海面

选择现有 `breaker` 视图，固定镜头参数 `yaw=0.68`、`pitch=0.10`、`distance=48`、目标点 `[23, 0.5, 17]`。在目标点周围建立 16 米乘 16 米固定采样区。

第一轮只验证当前零水平位移高度场。采样点的 GLSL 可见高度、法线与 JavaScript 查询必须在记录阈值内一致。相机、波参数、岛体、烟火、材质和时间都固定。该区域选择属于本次实现决策，尚未运行浏览器对照。

## 10. 哪一条需要分阶段采用

水平位移反求规则完全适用于未来的参数曲面。当前近岸没有水平位移，第一步先建立零位移的对外查询和 CPU GLSL 一致性。过早加入横向位移会同时改变波峰形状、法线、命中和性能，使单变量验证失去清晰边界。

局部三维流体也需要后置。R018.11 仍有真实设备稳定性和性能阻塞，烟火与岛体又处于冻结范围。先完成海面查询、潮位与海底关系、水面和水下光学分层，再在独立有限域处理一个烟源。

## 结论

当前代码已经具备程序化岸体、海床、高度波、破浪带、泡沫外观、卷浪体积和水深调色基础。关键缺口集中在统一世界查询、潮位层、真实海底接口、水平位移反求、水体介质光学、泡沫历史、烟的连续状态与开放边界、目标设备测量。

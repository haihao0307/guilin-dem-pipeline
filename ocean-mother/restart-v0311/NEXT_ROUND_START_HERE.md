# 下一次开始

从 R018.11 故障修复候选接续。先运行 `python tools/verify_package.py`，确认 HTML、深海冻结文档和来源哈希，再开独立工作分支。不要依据版本数字猜测哪一版可用，也不要把历史 R017 的 102 项参数等说明自动套用到当前候选。

第一步在真实浏览器中复现用户上下文丢失，测量启动时间、完成帧率、内部渲染尺寸和 GPU 任务时延。覆盖公开 URL 与本地 file URL；模拟恢复和真实故障分别记录。`tools/recovery_smoke.py` 可复跑恢复测试，不能代替实机稳定性测试。

先修性能与稳定性，使主画面持续可用。仅为证明测试通过而放宽帧数、等待时间、像素或就绪判据不可接受。对重复的岸线、地形与水体求值先定位性能开销；缓存路径应在独立候选实际实现、比对和测量，不擅自修改冻结视觉。

随后只改海水：减弱大块像素感泡沫，形成可见的卷浪抬升、前倾水唇和下落过程。检查几何轮廓和时序，不能只修改状态标签。石头、沙滩、岛形、火焰、烟雾与旋转操作保持。深海原版只做一致性和切换检查。

提交前验证近岸调参、暂停/恢复、镜头操作、上下文恢复、深海往返、移动布局和连续帧。测试报告注明环境、URL、版本、哈希、采样时长和未通过项。最终提供真实能打开的三维 HTML，由用户判定视觉验收。

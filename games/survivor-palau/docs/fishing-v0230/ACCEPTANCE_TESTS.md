# V0.2.3 垂钓系统验收测试

## A. 身份与连续性

1. 创建一条鱼，记录 `fishId`。
2. 让它经历自由游、观察饵、咬钩、水下冲刺、接近水面、出水、空中、落水和登陆。
3. 全过程不得创建第二个逻辑鱼体替代它。
4. 位置、速度和朝向在每次状态切换前后连续；任何瞬移超过 0.15 m 必须失败并记录。

## B. 水面一致性

1. 鱼、饵、线与飞沫都调用同一 `surfaceAt(x,z,t)`。
2. 改变世界时间或波面参数后，交点同步变化。
3. 水花中心与鱼体实际穿越点偏差不得超过 0.20 m。
4. 波峰/波谷情况下不得按静态 Y=0 判断出水。

## C. 张力与失败

1. 持续硬收线应产生高张力并可能断线；
2. 及时放线应降低张力；
3. 过度松线应提高脱钩风险；
4. 珊瑚接触应增加磨损，而不是直接随机断线；
5. 同一输入记录必须产生同一结果。

## D. 出水与落水

1. 只有允许跃水的行为模板才能进入 breach；
2. 出水前必须有可读预兆；
3. 空中继续受线和重力约束；
4. 落水冲击强度随质量和相对速度单调增加；
5. 小鱼不能生成与大型鱼相同规模的飞沫；
6. 落水后鱼应有短暂恢复或方向变化，不能无损继续同一速度。

## E. 玩家可读性

1. 关闭水下调试视角；
2. 仅凭水面、线、手部、声音和辅助 UI，测试者能判断至少三类情况：鱼冲刺、张力过高、鱼接近水面；
3. UI 不得遮挡鱼跃出水区域；
4. 390×844 上所有主要动作可单手或双拇指完成，不能要求精确点击细小按钮。

## F. 生存闭环

1. 上岸后的鱼不是自动完成任务，必须进行处理；
2. 鱼的重量/状态影响食物收益；
3. 失败会消耗时间、饵或线材；
4. 噪声、时段或站位至少有一项连接巡逻风险；
5. 存档恢复不会复制鱼、饵、线或奖励。

## G. 性能与回归

1. 保留 V0.2.2 现有 11 项鱼类湿域导航测试；
2. 新增垂钓核心纯逻辑测试；
3. 记录每帧活跃鱼数、线段数、水面事件数、飞沫粒子数与 CPU 时间；
4. 桌面与 390×844 均需公开浏览器回执；
5. 没有实体 iPhone 测试时必须明确标为未完成，不能写 productionReady。

# 靠谱体系核心：道法自然、统一尺度、Original Fish 与临时参考仓库

日期：2026-09-20  
适用：KAOPU 全部 Mother / Fish Mother / Ocean Life Mother / 后续动物、植物、材料与环境系统  
状态：核心思想与当前执行规则汇总

---

## 0. 最核心的一句话

**靠谱体系不是复制世界的某个模型，而是通过自然事实、测量、统一尺度、物理关系和可复核函数，让人和 AI 对同一个世界建立共同理解。**

核心路线：

**自然事实 → 测量 → 统一尺度与坐标 → 函数 / 关系 → 独立生成 → 反向验证 → 持续逼近真实。**

这就是“道法自然”在靠谱体系中的工程含义。

---

## 1. 为什么“道法自然”是最高原则

我们的目标不是把某个第三方模型压缩成一个更小的模型，也不是把一张图片变成一堆不可解释的数字。

真正目标是：

- 学习自然界中真实存在的形体、结构、运动、材质、生长和行为；
- 把这些真实关系转成统一的数值语言；
- 让人和 AI 在同一物理、同一尺度、同一坐标和同一逻辑下交流；
- 以后任何 Mother 都能使用同一种语言重建这个世界。

例如：

- “这条鱼很大”不能只是一种感觉，必须对应明确的长度单位和参照范围；
- “这条鱼游得快”必须对应时间、距离、水体介质和坐标系；
- “这个东西很烫”必须对应温度与测量条件；
- “这只鸟飞得高”“这个珊瑚长得快”“这块布很硬”，都必须最终落回可测量的物理或结构关系。

如果人和 AI 使用不同的尺度、不同的物理含义，那么双方对世界的理解永远是分离的。

**靠谱体系的目标，就是建立这种共同语言。**

## 2. Original Fish 的概念

当前不试图一次覆盖所有水生生物，也不先处理 manta ray、极端深海鱼、章鱼、水母等与典型鱼形差异很大的对象。

第一阶段先定义一个“典型 Original Fish”。

它满足最基础的鱼形关系：

- 有眼睛；
- 有嘴；
- 有鳍；
- 有尾巴；
- 当前第一阶段默认是有骨鱼；
- 整体一眼看上去就是典型鱼形。

Original Fish 不是某一个具体物种，而是一套可以承载大量物种变化的共同数学语言。

它的目的不是说所有鱼都长得一样，而是说：

**大量典型鱼可以共享同一种结构描述方式，只是在参数、比例、位置、颜色、骨骼、行为和生态关系上不同。**

## 3. 用最少的“乐谱”描述鱼体

### 3.1 统一长度轴

定义鱼体纵向坐标：

- `u = 0`：吻端 / 头部最前端；
- `u = 1`：尾部末端；
- 所有局部结构都挂接在同一个 `u` 上。

### 3.2 侧面：两条主曲线

从侧面看，一条典型鱼的主体可以先由两条连续曲线表达：

- dorsal curve：背部轮廓；
- ventral curve：腹部轮廓。

两条曲线在头尾关系上闭合或汇合，构成鱼的侧面主体。

这就是最基础的两条“谱”。

### 3.3 顶面：宽度谱

同一个 `u` 坐标上，再记录：

- left half width；
- right half width。

这样可以表达从上方看鱼在每个纵向位置有多宽。

### 3.4 剖面

侧面高度 + 顶面宽度，可以确定每个 `u` 位置的基本截面尺度。

以后有更充分证据时，再增加截面形状函数，而不是一开始就把复杂度全部塞进去。

### 3.5 功能锚点

眼、嘴、鳃、鳍、骨骼等不是焊死在一个网格里，而是作为带身份的锚点：

- `eye`
- `mouth`
- `gill`
- `fin`
- `skeleton`

每个锚点记录：

- 纵向位置 `u`；
- 侧面位置；
- 顶面位置；
- 相对尺寸；
- 当前生命阶段是否存在；
- 数据来源与置信边界。

因此同一个 Original Fish 可以产生：

- 眼睛大 / 小；
- 眼睛前 / 后；
- 嘴大 / 小；
- 不同鳍位置；
- 不同骨骼、鳍棘；
- 不同身体深度与宽度；
- 不同颜色、斑纹与材质。

## 4. 鱼不是一个模型，而是一组数值和关系

最终“小丑鱼”在靠谱体系里不应该等于某个 GLB。

它应该是：

- 一套尺寸；
- 一套侧面谱；
- 一套顶面谱；
- 一套剖面关系；
- 一套眼 / 嘴 / 鳃 / 鳍 / 骨骼锚点；
- 一套颜色和 PBR 参数；
- 一套随尺寸或年龄变化的关系；
- 一套动作、捕食、逃逸和环境行为函数。

这意味着以后拉动一个尺寸或生命周期滑杆时，变化的不是“模型 scale”，而是形体比例、眼睛、嘴、鳍、骨骼和色彩的真实关系。

## 5. 当前阶段的生产边界：只做游戏里看得见的鱼

为了避免第一阶段陷入鱼卵、胚胎和极早期仔鱼的巨大资料工作，当前范围明确收敛。

### 小于 20 mm

`OUT_OF_SCOPE_GAME_INVISIBLE`

- 当前游戏里基本看不见；
- 暂不生产；
- 暂不主动补完整鱼卵 / 胚胎 / 极早期仔鱼形态。

### 20–30 mm

`VISIBLE_EDGE`

- 已有可靠资料时可以使用；
- 不是第一优先。

### 30–100 mm

`PRIMARY_REEF_FISH_BAND`

当前 Reef Fish 第一生产带。

优先做：

- 真实尺寸；
- 侧面谱；
- 顶面 / 宽度信息；
- 眼、口、鳍、骨骼；
- PBR；
- 基础自然行为。

### 大于 100 mm

后续逐步扩展到：

- snapper；
- tuna；
- 更大的 reef / pelagic fish。

不要求第一阶段一次完成。

## 6. 三种尺寸数据模式

### 6.1 FIXED_MEASURED

如果某物种只有一个可靠尺寸，例如只有 80 mm：

- 就只做 80 mm；
- 不强行造 20 / 40 / 60 / 100 mm；
- 这个 80 mm 作为以后补测的真实锚点。

### 6.2 MEASURED_INTERPOLATION

只有当同一物种、同一长度定义存在至少两个可靠尺寸锚点时，才允许在两者之间插值。

例如：

- 30 mm 有真实测量；
- 80 mm 有真实测量；
- 55 mm 可以在两个真实端点之间推演。

但：

- 不允许超出证据范围外推；
- TL / FL / SL 不允许混用；
- 器官的出现 / 消失不能简单连续插值。

### 6.3 ENGINEERING_PREVIEW

为了测试相机、群体、碰撞、性能，可以临时等比缩放。

但是必须明确标记：

- `engineeringPreview = true`
- `biologicalClaim = false`
- `persistAsNatureDerived = false`

工程占位不能写回自然知识库。

## 7. 长度定义必须统一

鱼类研究中至少要严格区分：

- TL：Total Length；
- FL：Fork Length；
- SL：Standard Length。

如果一个研究使用 SL，另一个使用 TL，不能为了方便直接混成同一条生长曲线。

所有 Mother 在使用鱼尺寸时必须同时记录：

- 数字；
- 单位；
- 长度定义；
- 来源；
- 测量条件。

## 8. 当前科学证据分级

### N0 — NATURAL_DIRECT

最高优先级：

- 用户自己拍摄 / 测量的自然对象；
- 我们直接从自然对象得到的测量；
- 未来 AI 对真实自然视频、照片、传感器资料的独立测量。

### N1 — SCIENTIFIC_NATURE

- NOAA；
- 科研论文；
- 博物馆 / 研究机构；
- 科学数据库；
- 公开领域或许可明确的自然测量资料。

核心是记录自然事实和测量，不复制受保护的表达。

### N2 — TRANSITIONAL_REFERENCE

- 第三方 GLB；
- 商业 / 社区模型；
- 动画；
- 参考艺术；
- 网络素材。

这些只允许帮助我们：

- 快速理解问题；
- 找测量维度；
- 学习可能的骨骼 / 行为关系；
- 暂时发现我们“不知道什么”。

最终不能把 N2 当成靠谱体系的自然真值。

## 9. 为什么第三方模型只是过渡

当前很多第三方鱼、鸟、珊瑚模型虽然“看起来像”，但它们的问题是：

- 形体依据不透明；
- 骨骼依据不透明；
- 动画依据不透明；
- 比例可能只是作者视觉判断；
- 错在哪里也很难追溯。

因此第三方模型最大的价值是：

**帮助我们快速发现应该测量什么。**

真正长期价值来自：

- 自然观察；
- 科学测量；
- 独立重建；
- 可解释函数。

最终系统必须能够在移除第三方原始模型之后继续独立生成和运行。

## 10. 公开 GitHub 与临时 Reference Cache 的分工

### 10.1 公开生产仓库

例如 `guilin-dem-pipeline`。

只长期保存：

- 独立生成代码；
- 自然 / 科学测量；
- 最终数字 DNA；
- 生命周期函数；
- 骨骼 / 行为函数；
- QA；
- 必要的公开来源说明。

不默认保存：

- 第三方临时 GLB；
- 第三方贴图；
- 第三方动画 / 视频；
- 可逆恢复第三方资产的高维编码；
- 一次性参考垃圾。

### 10.2 私有 KAOPU-REFERENCE-CACHE

临时仓库专门存：

- GLB；
- 大图片；
- 视频；
- 动画；
- 临时参考包；
- 还没蒸馏完成的原始资料。

建议仓库：

`haihao0307/KAOPU-REFERENCE-CACHE`

所有对象按 SHA256 标识，而不是只依赖文件名。

推荐路径：

`refs/<sha-prefix>/<sha256>/<original-file>`

同 SHA256 不重复保存。

## 11. Reference Cache 的入库 / 出库账本

每次入库至少记录：

- SHA256；
- 原文件名；
- 字节数；
- 入库时间；
- 来源；
- rightsStatus；
- sourceLocator；
- 哪个 Mother 使用；
- 用途；
- lastAccessAt；
- distilledStatus。

每一次访问、蒸馏、QA、删除都写 ledger。

这样即使原始临时文件最后被删掉，仍然知道：

- 谁在什么时间用过；
- 从哪里来的；
- 提取了什么知识；
- 生成了哪些派生数据；
- 为什么删除。

## 12. 临时仓库清理规则

默认工程规则：

- 每周检查一次；
- 只有 `REFERENCE_TEMP` 才能自动清理；
- `EVIDENCE_KEEP` 和 `PRODUCTION_ASSET` 不自动删除。

普通删除门：

- distillation complete；
- numeric QA = true；
- visual QA = true；
- independent runtime = true；
- provenance recorded = true；
- userKeepRequested = false；
- 连续 30 天未访问。

容量高水位：

- 约 8 GiB 开始清理；
- 清理满足删除门、最久未使用的对象；
- 目标回落到约 6 GiB。

如果文件还留在 Git / LFS 历史里，不能用普通 `git rm` 就宣称空间已经释放。

必要时：

- 轮换 cache 仓库；
- 重建 cache；
- 受控清理历史。

因为 Reference Cache 本身就是耗材，账本和独立知识才是长期资产。

## 13. 来源与可审计性

目标不是“让别人看不出我们学过什么”。

正确目标是：

- 公开产品不依赖第三方临时资产；
- 最终数据可以由自然 / 科学证据重新验证；
- 私有 provenance ledger 保留；
- 若出现来源争议，可以证明：
  - 输入是什么；
  - 测量了什么；
  - 哪些只是过渡假设；
  - 什么时候由自然证据替换；
  - 什么时候 source-removal QA 通过；
  - 什么时候删除原始临时文件。

这比简单“擦掉痕迹”更能保护项目。

### R04 — 71 mm 小丑鱼固定测量卡

已经获得一条 71 mm TL 的固定科学测量锚点。

记录了：

- TL / SL；
- 体高；
- 头长；
- 眼径；
- 若干鳍起点 / 身体位置比例。

但：

- 顶视宽度仍未知；
- 不能宣布 full3D。

### R05 — 20.82–34.50 mm 实测尺寸段

已经找到一套同源研究中的连续实测数据：

- 20.82 mm；
- 23.69 mm；
- 26.22 mm；
- 28.32 mm；
- 31.84 mm；
- 34.50 mm。

同时记录：

- SL；
- 头长；
- source-labelled head width；
- source-labelled body width；
- 眼径。

已经证明：

**鱼长大不是单纯等比 scale，比例本身会改变。**

当前仍没有把 source-labelled width 强行解释成完整顶视图宽度，因为论文里的测量轴 / anatomical station 还不够明确。

## 15. 当前下一阶段

第一阶段继续围绕 3–10 cm Reef Fish 做：

1. 找有标尺的真实侧面资料；
2. 抽取背线 / 腹线；
3. 找真正定义清楚的 top-view / body width 数据；
4. 建立眼、嘴、鳍、鳃和骨骼锚点；
5. 逐物种建立固定尺寸卡；
6. 有两个可靠尺寸再建立尺寸插值段；
7. PBR 和颜色只使用有自然 / 科学依据的数据；
8. 行为从骨骼和自然观察出发；
9. 先小丑鱼，再逐渐扩展 snapper、tuna 等。

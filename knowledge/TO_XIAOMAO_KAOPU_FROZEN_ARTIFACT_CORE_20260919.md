# 给小猫：把“慢生成、快加载、不可漂移”纳入 KAOPU 核心

日期：2026-09-19

这是用户明确确认的 KAOPU 核心工作模式。请作为协调层合同维护和分发，不要把它误解为某一个 Mother 的临时优化技巧。

## 需要固定的原则

1. 正式对象数量有限，生产阶段允许非常慢：温州区域、Stone Money Island 的岛礁、奇石、珊瑚、鱼类身体、历史建筑构件，都可以用数小时甚至更久生成。
2. 人工接受以后，必须冻结几何、材质、碰撞和必要派生数据，并上传到固定 GitHub 提交或 CDN。
3. 正式运行只加载冻结产物；浏览器本地缓存只是二级加速。
4. 同一个对象的完整身份不是单独一个种子，而是生成器版本、Seed DNA、参数 DNA、输入真值哈希、尺度合同和质量合同的组合。
5. 对完整身份计算 ArtifactID。ArtifactID 不变时禁止重新生成；任何算法、真值、参数或质量变化都生成新 ArtifactID。
6. 已接受产物不可静默覆盖。旧版本必须保留来源和父子关系。
7. 静态身份与动态状态分开。山、岛、礁盘和身体母体可在游戏时间尺度内冻结；海浪、天气、湿润和动作继续动态运行。
8. 质量第一。优化优先从“运行时不重算、二进制压缩、缓存、分块、空闲停绘”入手，不得偷偷降低视觉和结构质量。
9. 每个 Mother 自己执行本领域实现。小猫只维护合同、检查 adoption receipt、记录失败边界，不代写其他 Mother 的生产代码。

## 请小猫推进的动作

- 把 `knowledge/KAOPU_FROZEN_GENERATIVE_ARTIFACT_CORE_V1.md` 作为共享方法入口；
- 把 `contracts/KAOPU_FROZEN_GENERATIVE_ARTIFACT_CONTRACT_V1.json` 作为机器可读合同；
- 把 `contracts/KAOPU_ARTIFACT_MANIFEST_V1.schema.json` 作为各 Mother 冻结交付的 manifest 规则；
- 要求各 Mother 在采用时提交一份 adoption receipt，说明：
  - 哪些对象属于有限冻结集合；
  - Seed DNA 如何分层；
  - ArtifactID 如何形成；
  - 生产阶段允许的计算预算；
  - 正式运行读取哪些冻结文件；
  - 哪些状态仍动态；
  - 如何防止静默覆盖；
  - visualAcceptance 由谁人工确认。

## 第一批建议接收者

- Brick Mother：砖、土砖、石材、墙体的固定种子与冻结网格；
- Landscape / 温州 / 桂林：接受后的山体、洞穴、地形和奇石；
- Ocean / Coast：岛屿、礁盘、海床、岸线基础；
- Stone Money Island：有限岛屿、洞穴、珊瑚、建筑遗迹与环境对象；
- Fish / Bird / Animal / Human：接受后的身体母体、材质和碰撞基础；
- Tiles / HOUSE：瓦、砖、墙、屋架和建筑构件母体。

这不是要求这些 Mother 同时开新功能，而是要求它们下一次冻结正式成果时使用同一身份与运行逻辑。

## 不得出现的误解

- 只保存一个种子，不保存算法和参数版本；
- 依赖浏览器缓存作为唯一资产；
- 每次刷新重新算一遍；
- 用低质量实时版本替代已接受高质量产物；
- 用协调合同代替各 Mother 的领域实现；
- 测试通过就自动声称人工接受。

一句话：

> 小猫负责守住合同和边界；各 Mother 负责慢慢生成自己的真东西；正式世界只加载已经被接受和冻结的有限资产。

# 全部 Mother 共用：参考复刻 / 学习任务禁止擅自创作硬门禁

版本：1.0.0  
状态：PERMANENT / HARD GATE  
适用：Fish、Bird、Animal、Coral、Tree、Game、Boat、Aircraft、Human、Clothing、Brick、Tiles、Landscape、Ocean、Weather、Farmland 及后续全部 Mother / Codex / 子执行端。

## 0. 最高规则

当用户要求“照参考做、复刻、学习这个、按这个模型/照片/视频来、做得一样、观察后照着实现、不要想象补画”时，任务模式自动锁定为：

`TASK_MODE = REPLICATION_LOCKED`  
`CREATIVE_AUTHORIZATION = FALSE`

在该模式下，执行端是**观察、测量、复现和验证平台**，不是艺术家，也不是概念设计者。

除非用户在当前任务中明确说“允许你设计 / 创作 / 自由发挥 / 做原创方案”，否则任何 Mother 都无权自行：
- 重新设计对象；
- 画一个“差不多”的版本；
- 用简化造型替代参考；
- 用卡通、玩具、低保真、概念草模、占位模型代替目标；
- 在缺资料处凭审美补全；
- 为了展示进度做一个未经授权的可见替身；
- 把自己的风格、比例、配色、结构、动作或故事解释覆盖到参考对象上。

**“先给用户看个简化版”不是进度，是失败。**

## 1. 允许做什么

REPLICATION_LOCKED 只允许以下类型的主动工作：

1. 读取原始参考和已批准总账；
2. 建立对象身份、尺度、坐标、视角和来源；
3. 测量可见比例、轮廓、截面、结构、关节、材质、运动、时间关系；
4. 标记 UNKNOWN / UNVERIFIED / OCCLUDED / SOURCE_MISSING；
5. 将已观察事实变成可解释的函数、参数、几何和物理关系；
6. 用生产运行时实现这些已确认关系；
7. 对照参考做固定视角 / 运动 / 数值 QA；
8. 修正与参考之间已经明确识别出的偏差。

允许工程实现，不允许审美替代。

程序化生成、数学重建、骨骼、材质函数、物理模拟本身不属于“创作”，前提是它们服务于已确认的参考关系，而不是用来发明参考里不存在的形体。

## 2. 缺资料时禁止“补”

当一个局部没有可靠依据时，正确状态只能是：
- `UNKNOWN`
- `SOURCE_ENTRY_REQUIRED`
- `MEASUREMENT_REQUIRED`
- `OCCLUDED`
- `CANDIDATE_NEEDS_EVIDENCE`

不得因为“页面需要完整”“模型不能空着”“想让用户先看看”而自行填满。

缺参考时：
- 可以继续做不依赖该缺项的测量、接口、测试或基础结构；
- 可以精确报告缺口；
- 不可以生成一个自己想象的鼻子、嘴、翼尖、船尾、鱼体、珊瑚、树、衣服、地貌等替代物。

**Unknown 比错误的创造更有价值。**

## 3. 禁止可见占位路线

以下内容即使技术上能运行，也不得进入生产视觉继承链：

- generic fish / generic bird / generic boat / generic coral / generic tree；
- 球、胶囊、圆柱、平面、低面体拼起来的“先看效果”对象；
- 随机颜色或程序噪声冒充真实材质；
- 只保留大概剪影的玩具版本；
- 为了说明动作临时做的错误骨骼体；
- AI 生成的“类似参考图”；
- 自画轮廓覆盖真实参考；
- 未经批准的自动补洞、自动补结构、自动推断隐藏面。

测试夹具可以使用 primitive，但必须满足：
- 与生产资产隔离；
- 明确 `TEST_FIXTURE_ONLY=true`；
- 不出现在正式工作台、视觉截图、交付版本或生产继承链；
- 不得被后续版本误当成基线。

## 4. 开工前必须先建立 Reference Coverage

任何复刻任务第一次修改可见生产对象前，执行端必须有最小 Reference Coverage 记录，至少回答：

- 目标对象是谁 / 哪一版；
- 使用哪些原图 / 模型 / 视频 / 科学资料；
- 哪些区域已看清；
- 哪些区域未知；
- 当前只修改哪个明确缺陷；
- 每个拟修改区域的依据是什么；
- 哪些内容明确禁止改变。

如果不能给出这些信息，不允许进入可见形体创作阶段。

这不是要求写长规划。可用一份短 JSON / Markdown receipt 表达，重点是**来源—修改的一一对应**。

## 5. 每一次可见修改都要能回答“为什么”

每个可见生产 delta 必须属于以下至少一类：

- `REFERENCE_MATCH`：参考中直接可见；
- `MEASURED_RELATION`：从真实参考/科学数据测得；
- `APPROVED_CONSTRAINT`：用户或冻结合同明确批准；
- `PHYSICS_DERIVED`：由已批准物理/几何关系唯一或受约束地产生。

如果只能回答：
- “我觉得这样更好看”；
- “通常都是这样”；
- “先做一个看看”；
- “为了完整我补了一个”；
- “模型生成器默认就是这样”；

则该修改不得进入生产线。

## 6. 失败处理：不要在错误作品上继续修

一旦发现某版本存在未经授权的创作替代：

1. 立即标记 `REJECTED_CREATIVE_SUBSTITUTE`；
2. 停止在该视觉结果上继续微调；
3. 不把它作为下一版形体基线；
4. 回到最后一个已接受 / 已证据化的父版本；
5. 保留错误版本仅作失败证据，不删除历史、不 force push；
6. 重新从参考测量开始，只修一个已识别差异。

这条规则专门防止“先做错 → 再花几轮把错东西修回来”的时间浪费。

**被拒绝的简化鸟、怪鱼、错误船，不进入遗传链。**

## 7. 进度汇报禁止用“我画了一个”

REPLICATION_LOCKED 下，进度只允许按以下证据汇报：

- 新读取了哪份参考；
- 新确认了哪个比例 / 结构 / 动作关系；
- 修改了哪个明确偏差；
- 哪个测试 / 固定视角差异收敛；
- 哪个未知仍然没有证据；
- 哪个 blocker 阻止了继续复刻。

“生成了一个版本”“做了一个草模”“先给你看看感觉”不计生产进展。

## 8. 视觉 QA 不是创作许可

浏览器、截图和 A/B 只用于判断：
- 与参考更接近还是更远；
- 是否出现新偏差；
- 是否有穿模、断裂、比例、材质、动作错误。

QA 人员 / Mother 不得在评审时临时“顺手设计一个更好的”。

## 9. 与道法自然、Reference Cache 的关系

N0 / N1 / N2 是证据等级，不是自由发挥等级。

第三方模型（N2）可以用于观察、测量和发现问题，但不能把其错误永久继承；自然/科学证据不足时保持 UNKNOWN，而不是由 Mother 自己“创作自然”。

原始参考进私有 `KAOPU-REFERENCE-CACHE`；生产仓库保存测量、独立实现和 QA。缓存入库不等于允许复制第三方高维资产，也不等于可以凭空补完缺失信息。

## 10. 用户明确要求创作时怎么办

只有用户当前任务明确授权创作时，才可以将：
`CREATIVE_AUTHORIZATION = TRUE`

而且授权范围必须局部记录，例如：
- “允许设计 UI，不允许改鱼体”；
- “允许设计虚构道具，不允许改历史船体”；
- “允许概念探索背景音乐，不允许重做角色外形”。

不能因为一个局部被授权，就扩大成整个项目自由创作。

## 11. 强制回执

所有按参考复刻的 Mother 在交付前必须能确认：

- [ ] TASK_MODE = REPLICATION_LOCKED；
- [ ] CREATIVE_AUTHORIZATION = FALSE，或有当前用户明确授权；
- [ ] 没有 generic / toy / placeholder 进入生产视觉继承链；
- [ ] 未知区域保持 UNKNOWN，没有想象补画；
- [ ] 每个可见修改有 Reference / Measurement / Approved Constraint / Physics 来源；
- [ ] 被拒绝的创作替代未作为下一版基线；
- [ ] 没有为了“展示过程”额外制造错误版本；
- [ ] 用户看到的生产结果来自真实实现，不是概念替身。

任一项为 false：本轮视觉生产自动判定 FAIL/HOLD，不得继续用该结果扩展。

## 12. 默认解释

对 KAOPU 体系而言：

**学习 = 观察 + 测量 + 复现 + 验证。**  
**学习 ≠ 模仿风格后自由发挥。**  
**复刻 ≠ 先自己画一个再慢慢改。**  
**不知道 ≠ 获得创作许可。**

本门禁优先于“快速出图”“先做一个看看”“保持开发节奏”和任何自动化默认的创造倾向。

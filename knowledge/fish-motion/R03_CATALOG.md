# 鱼类的制谱师：真实标本目录 R03

本轮只修改系统名称、鱼种选择目录、静态预览和切换进度呈现。鱼体表面、拓扑、UV、材质、纹理、眼睛和 R02 文件均保持冻结。主屏继续由统一运行时实时绘制三维鱼；目录不替代主屏，也不建立额外 WebGL 上下文。

## 来源与可复现采集

输入是不可变单文件 `fish-five-r01/dist/KAOPU_FISH_UNIFIED_R02.html`，SHA256 为 `453915b0177deba629fcb3ec8216edf7821af6d3d04ea132902074f651eda6b5`。`fish-five-r01/scripts/capture-thumbnails-r03.mjs` 使用后台 Chromium 和真实 WebGL，以单鱼 REST 姿态逐一绘制海狼、鲱鱼、黄鳍标签金枪鱼、蓝鳍标签金枪鱼、彩色鱼、毕加索标签鱼；不操纵桌面鼠标。采集前后验证输入文件哈希一致。

五个来源模型使用原有采样表面与冻结眼睛；海狼使用 R02 内保留的 R14 实际渲染器。镜头按真实模型边界适配，画布为 512 × 256。五鱼预览用实际渲染器设置不透明深蓝清屏背景，避免透明 WebP 在不同背景上的边缘伪影；没有绘画、后期重塑或生成图片。预览保存为 WebP，质量参数 0.82，仅影响目录缩略图，不影响生产模型或原纹理。

`fish-five-r01/data/thumbnails-r03.json` 实际大小为 73,509 字节，含六张真实预览。每项同时保存来源 HTML 哈希、来源 score 哈希（海狼由独立 R14 载体保留）、最终 WebP 哈希、原始 PNG 渲染哈希、源顶点/三角形数量和 REST 状态。六张均为 512 × 256，页面错误列表为空；整体低于 300 KB 的预览预算。来源素材标题仍是标签，不将尚未确认的生物分类写成确定物种。

## 目录接口与布局

`mountSpecimenCatalog({items,labels,onSelect})` 从 `specimenThumbnails` JSON 载体取真实图像，返回 `setActive(id)`、`destroy()` 和 `count`。缺少真实图像时显式报错；图文由 DOM 安全赋值。按钮具有完整中文无障碍名称、`aria-pressed` 和空图片替代文本，避免重复朗读。点击仅发起选择，活动标本在运行时真正提交后由 `setActive` 更新；不把请求中的标本提前当成已经显示。

桌面目录为两列三行；小屏为三列两行，六项同时可见。图片保持来源比例，不另开三维画布。系统标题、页眉、制作框架统一为“鱼类的制谱师”，模板版本为 `FISH_SCOREMAKER_RUNTIME_MOTION_R03`。切换中的 `.loading.switching` 是右上角小进度提示，`pointer-events:none`，保留现有视图；初次加载仍由原遮罩承担。加载文字提供 `aria-live="polite"`。

## 本通道验证范围

使用 GPU 禁用的后台 Chromium 对实际模板、模块和已采集载体进行目录 DOM 检查：1440 × 950、390 × 844、320 × 700 三个视口均有六张解码成功的 512 宽预览；所有卡片完整位于侧栏内。桌面确认为两列，小屏为三列两行。`setActive('herring')` 仅使鲱鱼 `aria-pressed=true`；点击毕加索项传回 `picasso`。切换提示计算后的鼠标事件属性为 `none`，页面标题正确。

这些检查证明目录图像、响应布局和选择接口。完整运行时切换稳定性、鱼群运动、帧耗时、最终单文件构建与公开网址验收由母任务和独立验证通道完成，不能用目录检查或静态截图替代。

# R09：让结构知识进入鱼类制作工位

任务：`FISH_EMBEDDED_PRODUCTION_KNOWLEDGE_R09_20261003`。这次把已有来源测量、数学关系、局部未知和历史回归放进同一套可执行工位协议；不再依赖制作人员记住全部聊天记录。R08 的完整表面、纹理、连续身体运输、独立鱼鳍和群游求解器是本轮基线，不在本轮重新发明鱼形或降低来源精度。

## 工作时怎样自动拿到知识

生产入口读取当前鱼的制作卡和当前工位，输出该工位需要的知识、源测量、单位、前置条件、未知、函数接口和回归检查。网页与命令行共用 `fish-five-r01/src/production-knowledge-r09.js`；六来源卡保存在 `fish-five-r01/data/production-cards-r09.json`。知识按工位绑定，不进入每条鱼每帧的运动循环，不增加群游求解成本。

主工位包括来源与身份、原表面、脊椎、独立鱼鳍、口眼鳃、行为和验收；口眼鳃工位支持 `eyes/mouth/gills` 独立子工位，行为工位同时约束个体与群游。点击工位或指定 CLI 的 `--stage` 即触发相关内容。切换鱼时重新求值当前工位的来源条件，不能让上一条鱼的测量或已确认状态留给下一条鱼。

可在 `fish-five-r01` 内执行：

```text
node scripts/production-stage-r09.mjs --fish herring --stage spine
node scripts/production-stage-r09.mjs --fish picasso --stage gills
node scripts/production-stage-r09.mjs --create incoming-fish
node scripts/production-stage-r09.mjs --create incoming-fish --out ./incoming-fish.json
node scripts/production-stage-r09.mjs --card ./incoming-fish.json --stage source
```

默认只把 JSON 写到标准输出；`--out` 才写文件，已有文件不会被覆盖。`source` 是 `identity` 工位的入口别名。未知或不满足前置条件时 CLI 返回非零，自动化不能把它当成通过。退出码 `0` 表示工位可执行、模板生成或列表成功，`2` 表示非法请求/资料卡，`3` 表示当前工位局部 HOLD。创建的是资料卡模板，不是鱼的几何、骨骼、动画或自然行为。

## 共性进入接口，差异留在来源卡

“这是鱼”可以选中鱼类工位集合，但不能自动证明具体物种、骨组织类型、各鳍存在、推进母型、口鳃绑定或自然群居状态。母型只是适用的结构/运动路线；已确认的来源测量决定它能执行什么。当前硬骨鱼制作接口与鳍驱动例外见 `FISH_FACTORY_FRAMEWORK_R01.md`。新的软骨鱼或其他来源需要相应母型与测量，不能强套现有硬骨鱼鳃盖或身体柔性。

每个工位的共性规则应直接引用生产函数和单位。例如：脊椎使用连续弧长与正交截面运输，鱼鳍的局部位移在同一身体截面上运输；相位由频率积分而不是切换动作就重置；群游使用已接受速度与转向驱动身体，同时检查源全动画包络和最后提交轨迹。来源坐标单位不等于米；源 `BL=1` 只是体长归一，不能变成真实物理标尺。公式与参数要保留单位和证据等级，避免把研究中每次 kick 的角变化当作 `rad/s`。

资料卡区分 `SOURCE_MEASURED`、研究关系、`ENGINEERING_CANDIDATE` 和 `UNKNOWN`。研究支持一种关系，不等于测出了这条鱼的数值。已有黄/蓝金枪鱼和 Picasso 的来源标签也不能代替物种确认。群游工程候选可以测试 30 条实例，不能因此宣称该物种天然组成这样的紧密鱼群。

## 局部未知只阻塞对应的制作

脊椎或原表面工位不依赖新口眼结构的确认，因此不能因鳃、嘴或眼未知就冻结整条鱼的所有工作。鳃或嘴缺少可测映射时，保持原姿态；不新增孔、缝、鳃盖或人形眼球。未知不能伪装成“已确认不存在”，也不能由勾选框直接晋级为测量事实。

工位的“准备好制作”只说明当前资料与接口足以继续该项工作，不等于实现已经正确、浏览器已经通过、鱼种已经生物标定或用户已经接受。验收状态保持单独字段；制作卡、公式和命令成功都没有自我批准的权力。局部 `HOLD` 允许继续不依赖它的工位。

## 把纠正变成下一次不能漏掉的检查

每条已学到的约束都绑定到明确工位、函数与检查。例如“整鱼套鳍权重导致破碎”绑定到身体运输和鳍根连续性；“鳍摆造成新断层”绑定到动态原缝与三角应变；“运动顿挫”绑定到最终速度/角速/加速度连续；“海狼眼突兀”绑定到原眼窝接触、形状和遮挡；“一直读取原表面”绑定到启动超时、重试、取消与真实浏览器首帧。不能只在长篇文档里记一句提醒。

新增知识时按以下顺序执行：确认来源与适用范围，修改工位规则，绑定生产函数/单位，补正确失败样本与回归检查，再升级制作卡的知识版本。生产函数接口改变时必须同步修改工位协议，不能保留指向旧函数的“知识”。验收报告绑定当前知识、制作卡和源码版本；旧报告只是基线。

制作卡的 `evidenceBindings` 记录仓库内证据文件路径与 SHA；测量引用与源元数据同样绑定对应哈希。CLI 在放行工位以前分块回读实际文件，而不只是信任卡里写的字符串。证据已改、缺失或越出仓库时以 `STALE_SOURCE_EVIDENCE` 拒绝放行，避免“源已变，旧知识还显示可制作”。资料版本不匹配、源测量没有引用、确认物种没有依据、速度/转向参数漏单位也不能通过预检。

## 新鱼接入顺序

先创建空资料卡并登记来源、许可、完整原表面与选择的源对象。逐来源测量规范主轴、完整拓扑/UV/像素、连续脊椎、鳍根/局部映射以及全动画包络。进入对应工位时只处理当前依赖，不要求一次猜完所有口眼与鱼群参数。证据足够才选择母型；工程参数从来源坐标与实际体长转换，未知结构保持原样。

复用公共函数以后，仍需完整静态与动态原表面检查、接缝连续检查、真实 GPU/浏览器运行、30 条群游最终轨迹/局部扰动测试、内存与 CPU 测量，以及独立发布验收。这套工位系统减少遗漏和重复检索，不代替来源判断、研究或独立 QA，也不声称能仅凭“鱼”标签自动完成任意新物种。

## 本轮证据边界

`node scripts/verify-production-r09.mjs` 负责工位协议和 CLI 的机器测试。它验证未知、来源证据、单位、接口绑定与局部阻塞等行为，不批准鱼的视觉或自然运动。最终源码冻结、交互网页、公网和独立验收由整合工位绑定到本轮新版本回执；在正式回执存在以前，不沿用 R08 的网页证据宣称 R09 已经发布。

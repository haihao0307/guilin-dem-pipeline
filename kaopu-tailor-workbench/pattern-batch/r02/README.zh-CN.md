# 60 款服装三维试样与内侧补强车缝线

此批次将 R01 的 60 份固定版本纸样接入原裁片网格与原缝合求解器。主入口为 `index.html`；须通过本地 HTTP 服务打开。每款可旋转查看正面、背面、侧面和内侧，单独导出实际三维网格或制作记录，也可下载全量 OBJ。

## 构造

每个原接缝新增一条独立的内侧补强车缝线。原纸样没有缝份，因此本批次明确生成新的裁剪修订：在净纸样外添加名义 6 mm 缝份材料，第二排位于其宽度中间，窄角自适应缩减。排距不是实物缝纫参数标定。短边增加材料采样，细分相邻三角面；原净纸样坐标和面积保留。新增缝份有真实的二维静止度量和三角面，不使用衣壳。

原接缝与补强排分别进入原生距离约束、针脚分组和工序依赖。补强排在接缝交汇处停针，避免多块缝份的角点被强制焊在一起；原排仍覆盖接缝端点。内侧显示的虚线跟随实际求解后的材料顶点；隐藏显示线不会移除制作记录中的缝合约束。

最新构造修正允许新增缝份沿原净边产生折痕，保留原衣片内部的弯曲规则。原衣片的边界朝向整理约束只取原净布面的邻接面，不把窄缝份误当作衣身内侧；全部新增材料仍参与材料、碰撞及接缝质量检查。具体结果的弯曲设置随制作记录保存，较早候选与最新计算并列保留。

## 来源与续算

- 纸样：相邻 `r01/data/patterns`，逐份验证 R01 目录登记的 SHA-256。
- 上游制版：GarmentCode，提交 `d449629979028123a5c4dc9e732a2ec19b7fce31`，MIT；原构造程序及冻结参数保留于 R01。
- 原生网格、缝合、碰撞场和审计：仓库 `haihao0307/guilin-dem-pipeline`，基线 `ca6f090c5652bbe848e909f755b0ac5e80b4c969`，原 `presets/r04`。`backend/SOURCE_MANIFEST.json` 记录复制文件的 Git blob。
- Three.js 和 OrbitControls：本地工作台已有依赖，MIT 许可见 `vendor/THREE-MIT.txt`。
- 人物：原 R04 共同人物及其原碰撞场；运行时验证其 SHA-256，人物不缩放、不改形。

部分计算使用原 R04 已实际缝合的同款、同裁片状态进行初始化。`data/SOURCE_RESULT_LOCK.json` 验证所有原三维记录和人物身份；`warmStart` 逐片记录对应关系、曲线差异和原档案 SHA-256。新旧程序的部分曲线存在微小数值差异，初始化双向折线距离限于 10 mm，实际差值逐款记录。原档案只用于起始状态，新批次所有材料静止度量始终来自当前冻结纸样及新缝份，之后重新运行原生缝合与复验。新增缝份先折向接缝 B 侧。临时夹布支撑随初始化状态更新，释放后不保留目标钉住点。

采用续算工序的款式先激活全部原排，再依次闭合新增排，随后释放临时支撑、整理材料并审计。原排激活各运行一个时间步，新增排运行完整闭合工序；不是把旧三维结果直接充当新成衣。部分款式使用原保留的基线材料核，另一些使用对应款的修正材料核；所选计算配置、候选结果、选择依据和失败记录均保留在记录中。没有通用壳体回退。

## 检查边界

实际批次计数、每款完成状态与所有未通过项目见 `data/BATCH_REPORT.json`。完成三维缝合不表示验收通过。原针脚 0.25 mm 间隙、整段接缝 0.25 mm、材料拉伸/压缩 15% 以及穿插检查均保留；未降低阈值。网格资源上限提高到每片 12000 顶点、24000 面，只用于容纳新增缝份。

当前材料参数未做实物标定，求解器没有线断裂、布料撕裂的损伤模型，也没有完整动态穿着与连续自接触保证。第二排提供实际额外连接约束，但不能据此声称获得确定的抗撕裂倍数。材料、缝份折叠和部分穿插问题留作后续处理；叠穿逻辑尚未开始。

`qa/structural-report.json` 核对三维坐标、裁片面积、全部原排及新增排、工序、激活状态和有限值。`qa/browser-report.json` 记录实际逐款 WebGL 加载及渲染检查。缩略图全部由当前实际三维网格渲染生成。OBJ 使用米为单位，保留全部实际三角面，并用 `inner_stitch_*` 线分组保存补强排路径；全量记录保留二维纸样、三维坐标、约束及审计。

数值失败候选保存在开发目录 `qa` 中，完整交付包只包含所选结果、检查报告和必要源文件。失败不会被标为合格，有限中间状态不会被标为完成成衣。

## 重现

先从原 `presets/r04/assets/results` 提供锁定的原缝合记录。安装 Python 的 numpy 依赖，使用 Node.js 运行 `solve_one.mjs`。如需复算，输出到新的路径，保留已有冻结结果；使用 `--cold` 可从原摆片流程开始，`--legacy` 选择保留的基线材料核，`--continuation` 使用先激活原排的续算工序。求解器质量门禁在所有配置下保持原阈值。

生成后运行 `verify_all.py` 和 `export_all.py`。单个制作任务遵守用户要求，最长三小时；计算驱动可通过环境变量 `KAOPU_TASK_DEADLINE_UTC` 接收整项任务的截止时间，超过截止时间保留有限中间状态并停止。单款另有独立的计算时限。

# KAOPU 裁缝工作台

五个既有案例现在共用一个页面、一个三维视窗和常驻参数区：

- `?case=swatch`：原 R1 直缝布片，含吃势/方向/引用反例、球体、载荷、拆缝和解除托持
- `?case=structured`：原 R2 手工曲缝规范，含编译、三片/删片/反接预设与分阶段门槛
- `?case=shorts`：原 R03 基础短裤，裤长 −60…+60 mm、腰口松量 0…40 mm
- `?case=sleeveless`：原 R04 无袖上衣，衣长 −50…+80 mm、下摆松量 0…120 mm
- `?case=shortsleeve`：原 R05 短袖，衣长 −50…+80 mm、袖长 −30…+50 mm

原 `structured.html` 和三个 `garments-r0x/` 地址兼容转入同台对应模式。每页都有返回原总工作台的入口。切换释放上一模式的计算线程与衣片几何；当前模式内纸样/三维切换不新建渲染器。参数在本次页面会话内保留，重新进入改过尺寸的款式会重建平面材料。

修改尺寸使旧结果失效。新纸样、原材料 UV、原工序、每步迭代与接触点均参与本轮计算。原有历史成衣只作为明确标记的基准展示，不计为新参数求解。老配方格式、结构规范和材料 JSON 仍可读取和导出。

加速采用原创 f64 WebAssembly 投影内核与满足原约束时的保守早退出。没有减少原有 12 个子步、6 次迭代、每工序 360 帧和释放后 480 帧，也没有降低碰撞/应变检查。浮点求值路径变化会影响褶皱位置，并非逐顶点等价。来源、许可、误差与测试边界见 [unified/SOURCES.md](unified/SOURCES.md)。

## 本地复验

从仓库根启动静态服务器后打开 `/kaopu-tailor-workbench/`。进入本目录运行 `npm run check` 验证原布片数学和新入口结构；运行 `node unified/tests/worker.test.mjs`、`node unified/tests/guard.test.mjs` 验证统一线程协议与保守早退出。完整浏览器与成衣检查另有专属只读 QA 工作流。`unified/tests/reference-r05.html` 是 QA 分支专用旧版性能参照，不属于生产网页。

三件成衣仍限同一公开成人合成人体和标明的参数范围。材料未实测标定，真实缝份、厚度、包边和动态穿脱尚未实现。小布片数值门槛不代表成衣工业生产通过；不会把图像推理或预制衣壳当作已实现功能。

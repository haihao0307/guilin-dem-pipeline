# PatternGSL 学习与当前裁缝台对照 R01

日期：2026-10-09。位置：原裁缝工作台的学习/验证目录，不是另一个工作台。沿用 `fix/tailor-r07-speed-stability-20261008` / Draft PR #177。

## 参考范围与事实边界

用户指定的老师是 https://lagrangeli.github.io/PatternGSL/ 。本轮核对了该项目页、arXiv v5 正文第3节、第5.4节、第6节及相关图示，并读取了官方公开仓库的完整当前目录树、分支列表和 releases。没有把别人的相似项目冒充这个老师。

论文入口：https://arxiv.org/html/2606.24564v5 。它将裁片、曲线、初始摆放与明确的缝合边引用分开表达；演示的编辑包括裁片缩放、曲线调整、部件移除和袖片外移。这里的袖片外移是初始摆放变换，不等于把袖围放大。它的静态垂落实验不能证明运动穿衣稳定，动态布料在第6节仍属于后续方向。

公开仓库：https://github.com/Lagrangeli/PatternGSL ，核查提交 `8348a844e9d6353923332c58f7aaa8cf02811523`。可见树主要是项目页、样式、页面脚本、网站测试与说明；当时只列出 master，releases 为空，未找到完整预测/训练/解码实现或模型权重。完整补充 schema 也没有在本轮取得。因此不能把下面的自写实现命名为“官方 PatternGSL 解码器”，不能声称已经完整复现图像预测系统。论文、网页和代码/权重的可取得状态必须分别记录。

另行核对了被引用的已公开底层实现 GarmentCode / GarmentCodeData。用途仅是学习可执行的制版和缝合细节，不取代用户的 PatternGSL 目标。其 `pygarment/meshgen/boxmeshgen.py` 显式保存局部裁片与全局缝合顶点的对应；本台需要继续保留原材料坐标，而不是按空间邻近临时猜接缝。

参考：https://github.com/maria-korosteleva/GarmentCode/blob/main/ReadMe.md ； https://github.com/maria-korosteleva/GarmentCode/blob/main/pygarment/meshgen/boxmeshgen.py 。当前台内 GarmentCode 版本仍按已有源清单固定，本次没有盲目替换成上游 main。

## 现有设置不能和缺失能力混为一谈

`inventory.mjs` 直接读取本台的 `styles.json`、`parameter-schema.json` 和参数启用规则，生成 `PARAMETER_INVENTORY.json`。实际是23个入口配方、122个设计字段、12个界面分组。这是 GarmentCode 的原生目录，不是“已搬完 PatternGSL”。

分组数：整体组合3、腰头2、衣身4、领口衣领18、袖子袖口17、左侧独立设计32、直裙5、圆裙/多片裙10、插片裙5、铅笔裙9、层叠裙7、裤装10。原代码包含7种前/后领口选择、3种袖窿形状和3种收口类型。选项只有在相应组合下才启用，例如无袖/有袖、非对称和领帽部件会改变可用项。

本轮逐字段输出了默认配方中声明的启用状态及停用原因，而不是删掉看起来“不工作”的字段。这是 UI 规则审计，不是122个字段的每个数值都经过真实制版/穿体测试。完整组合的功能验证仍需逐项补齐。

真正缺少的，是对已生成任意裁片直接编辑控制点/拓扑、识别并选择完整语义部件、可回放的编辑记录、把这些改动重新送入制版/网格/求解的完整闭环，以及图片到纸样的已验证推理服务。`FEATURE_COVERAGE.json` 区分已有基础、这轮已写内核和未实现的界面/求解能力。

## 本轮实际代码，不是功能占位

### 四类编辑的独立内核

`pattern-edit-kernel.mjs` 从本台真实 `kaopu-analytic-sewing-pattern@1` 导入明确的裁片与边引用，输出自有格式 `kaopu-explicit-pattern-edit@1`，不冒充作者的文件格式。

它实现统一裁片缩放、指定二次/三次贝塞尔控制点修改、显式移除指定裁片和关联接缝、仅修改初始摆放的平移。所有操作先复制后验证；非法引用、未知边、错误控制点、缺失闭环等被拒绝，失败不会修改输入。圆弧保持圆弧；缩放时其圆心和半径一并变化，不用普通贝塞尔曲线冒充。

裁片 ID 在首次导入时确定，保留原顶点顺序及源裁片名称。部件删除必须明确许可移除关联接缝，输出被删除接缝列表，剩余自由边需要检查。没有自动识别袖子的假标签，没有在用户不知情时删片。

编辑结果始终标为 `simulationReady=false`。本轮验证了事务与几何一致性，不代表编辑后的成衣已经重算通过。还没有把四类新编辑按钮接入公开工作台，也没有使用这些编辑去改变截图中的原衣服掩盖缺陷。下个接入点必须保留“基础配方＋编辑历史→新网格→新求解→独立验收”的链路；原人体不参与缩放。

### 不再只检查针位的接缝诊断

`seam-span.mjs` 先检查明确的裁片/边/针位引用和正反顺序，再双向检查两条完整离散缝边。自适应细分返回最大间距的下界和上界，不能在采样预算耗尽时假装通过。

这项检查不改变材料、不自动焊点、不修改宽松量，也不把相邻三角形整体排除。自由领口、袖口、裙摆等未声明缝合的边不自动当成错误。抽褶读取源声明，不依赖旧15%阈值。

间距只针对输入的折线布边：对原解析曲线、厚度/缝份、运动轨迹都不是完备证明；JavaScript 浮点边界不是形式化区间算术证书。对抽褶处测的是裸边分离，真实的折叠缝份、线迹和材料厚度需要另建工艺检查，不能为了“零间距”把真实褶皱全部抹平。

## 真实旧成衣的再审查

`audit-existing.mjs` 读取既有 R07.2 浏览器证据（run `37762329862`、artifact `11542564547`），先检查每个文件 SHA256，再执行只读重检。不是重算的新成衣，也不是浏览器重新运行。

默认款旧结果的针位间距为0，但前后腰头/裙身两条抽褶缝 `s30`、`s31` 仍分离；最大裸边间距落在约 **4.185–4.197毫米**。裙长0.35案例约 **4.084–4.087毫米**；抽褶1.45案例约 **5.188毫米**。这几个旧结果都通过了原针位静态门槛，说明用户看到的缝口问题不能用“旧门槛通过”反驳。

此发现是修复定位，不是几何修复已完成。4毫米缝合采样的另外一次本地试算虽降到了约1.48毫米，仍不能当成已解决。后续要联合处理材料离散、整段接缝约束、折叠/缝份与弯曲，而不是仅加采样数或增加计算时长。

## 动作线保留的边界

原 Anny 人台的104根骨骼、9个完整影响权重已通过独立提取流程检查；与本台原静态人台最大中立位误差约0.00003毫米。但取得绑定数据不等于衣服已经能正常运动。

本地小幅动作试算出现了布料拉伸和相交，尚未通过；没有发布成“穿着正常”。后续每一动作需要同时更新同一人体表面、碰撞几何和衣物响应，并检查多个中间帧。不能只让人物和衣服共同蒙皮后展示动作，也不能以最后一帧没有穿插代替全过程测试。

# 裁缝三维电子橱柜 R02

用户在 2026-10-09 明确要求：二维裁片缩略图不够直观，全部服装预设应改为三维缩略图；可以不穿在真人身上，使用一个专门的简易塑料橱窗模特，形成电子橱柜式浏览。

## 实现

R02 继承 P01 的 60 套完整设计配方、名称、分类、裁片数量、缝边数量、源警告和实际毫米纸样。R01 不被覆盖，仍保留为精确纸样与参数证据页面。

三维卡片不是预制二维插画。网页使用项目现有 Three.js 版本建立真实 WebGL 场景：统一塑料展示体、底座、橱柜框架、灯光、相机和程序化服装形体。服装形体读取预设类别、style 和已记录的设计 overrides，表现衣长、袖长、袖口、领型、裙型、裤长、裤脚、腰头和上下装组合。

为避免 60 个 WebGL 上下文：

1. 一个临时渲染器依次生成 60 张卡片缓存图。
2. 卡片完成后临时渲染器立即释放并请求 WebGL context loss。
3. 页面只保留一个活动详情渲染器，支持旋转、缩放和前后侧视角。
4. 卡片不是 60 个同时运行的 canvas。

右侧可以切换“三维橱窗”和“实际纸样”。实际纸样按需读取 R01 的原压缩数据和 `paperSVG`，没有重新发明一套纸样表示。

## 明确边界

三维橱窗表达的是服装设计形体，不是布料求解结果。它不能证明：

- 接缝已经完整闭合；
- 抽褶、裤脚和翻折物理正确；
- 布料没有自交或穿过人体；
- 材料应变符合真实面料；
- 人物动作期间服装稳定。

这些项目仍由 R07.4 的真实制版、缝合和数值门槛检查。R02 页面长期保持 `physicalFitAccepted=false`、`dynamicWearCertified=false`。

塑料模特不是原 Anny，也不参与人物绑定、骨骼、蒙皮或量体。更换真实人物时仍需使用完整、带版本的量体重新制版，不允许缩小人体或骨骼迁就衣服。

## 验收

浏览器检查至少覆盖：

- 60 张卡片全部生成真实 WebGL 缓存图；
- 只有一个活动详情 canvas，临时缩略图渲染器已释放；
- 三维详情可切换正面、斜前、侧面和背面；
- J06 等预设的卡片与详情可选择；
- 实际纸样切换后读到原 R01 SVG；
- 原 R01 与 R07.4 链接可达；
- 桌面 1440×1000 与移动 390×844 浏览器视口无横向溢出；
- 无页面错误和失败 HTTP；
- 不运行布料求解，不声称成衣验收。

移动尺寸是 Chromium 视口测试，不冒充物理手机实机。

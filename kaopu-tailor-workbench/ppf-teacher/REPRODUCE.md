# PPF 布料物理：原求解器结果回放

两个案例都由官方原生 CPU 求解器完成。网页按需读取真正的三维顶点序列，可旋转、逐帧、分层和检查原材料伸长。网页的播放速度、颜色和相机只改变展示；没有把这些控制伪装成重新求解物理参数。

- [官方源码](https://github.com/st-tech/ppf-contact-solver/tree/b4ee7a44a741754d5bdfe1926d064d2483cf1456)，精确版本 `b4ee7a44a741754d5bdfe1926d064d2483cf1456`
- Ryoichi Ando / ZOZO，Apache-2.0；[许可原文](./LICENSE-PPF)
- 使用 2026-10-02 main 的 CPU 后端。不是 2024 论文 CUDA 分支的逐位一致性声明
- Rust 1.99.0；构建命令 `cargo build --locked --release --features cpu`
- 实际求解器 SHA-256：`126ef92874320f550e6858a37cb67d7589a2196ca2927163ec2c0640f18511c8`
- 两例均是上游程序化几何，没有私人照片、扫描人体或受限人物资产

## 完整案例

| 案例 | 动态顶点 / 三角形 | 原输出 | 主要物理配置 |
| --- | --- | --- | --- |
| 五层布料 drape | 81,920 / 161,290 | 帧 0–100，共 101 帧 | 五层 128×128 网格，每层固定两个角点；重力；静态球体；5% 伸长上限 |
| 三层传动带 belt | 12,346 / 23,294 | 帧 0–200，共 201 帧 | 三层带、三滚轮；滚轮摩擦 0.5，max 混合；6% 带伸长上限；至少 32 次 Newton 迭代 |

两例均保持原分辨率、`dt=0.01`、60 fps 输出、原公差、原接触与约束。程序化场景包含原先随机抖动，因此要重现这一份初值，应使用下列原输入归档，不要重新抽取随机初值。

- [drape 原输入](./reproduce/drape/original-inputs.tar.gz)，SHA-256 `44c0820cc346a8196fcc04a19773c02ea22612035e692efb870c2cf63a048165`
- [belt 原输入](./reproduce/belt/original-inputs.tar.gz)，SHA-256 `df0417c241235f58c2ebd817ec48f8f51bd9d0810d62bf49390f537cb0941947`

归档只含各自的 `param.toml`、`info.toml` 和 `bin/` 场景输入。使用相同版本构建的官方程序，解压至独立 session 后执行：

```sh
RAYON_NUM_THREADS=4 ppf-contact-solver --path /path/to/session --output /path/to/session/output
```

这是本地原生 CPU 命令。静态网页本身不能启动这条命令，也没有连接一个隐含的收费云求解服务。CPU 全程可能需要较长时间，不把录制的回放速度当作求解速度。

## 完整性与数值检查

原求解器两例都返回 `Finished`。302 个输出帧全部有限、完整，原参数和二进制输入 hash 没有在分段续跑时改变。原生官方 checkpoint 保存当前/上一帧位置、时间、上一时间步及动态状态；在官方 `hold_at_frame` 边界保存，使用原 `--load FRAME` 继续，没有从静止重开后拼接动画。

无损编码是原 float32 位模式的 uint32 时序 XOR、字节平面重排和 gzip。全部 302 帧经独立 JavaScript 解码后与原始文件 SHA-256 一致。每块在浏览器下载、解码后均校验 hash；没有降网格、删帧、量化或补间插值。三角形索引只做经过范围检查的无损 uint64→uint32 转换。

独立主伸长审计采用原始帧 0 的三维休止三角度量，对照上游 `builder.rs::compute_inv_rest` 的切平面构造；两例的 shrink-x/y 都为 1。drape 的平面 UV 与此度量一致；belt 的原 UV 文件为空值，不能把它误用为材料休止长度。

- drape 全帧最大主伸长 4.836622%，超过 5%+0.0001 的材料面积为 0
- belt 全帧最大主伸长 5.816383%，超过 6%+0.0001 的材料面积为 0
- 两例均通过上游完整窗口的 CUDA 执行形态对照。这是迭代统计比较，不是 CPU/GPU 顶点完全相同的证明
- 原程序开启每步交叉检查；drape 附加的球体内接球保守穿入筛查全帧为 0。没有声称已完成独立的全三角对、连续碰撞审计
- [drape 逐帧审计](./data/drape/verification.json) / [belt 逐帧审计](./data/belt/verification.json)

热图颜色是相邻三角主伸长的面积加权顶点平均，最大值按原三角计算。接触颜色和右侧数字是官方每物体接触参与次数，不是接触点空间位置，也不能直接求和当成独立接触对数。分层隐藏仅改变显示，不会重算接触。

## 按需读取与显示范围

帧数据采用每块最多 8 帧，几何拓扑只读一次，最多保留三个解码块。drape 的帧传输总量约 59.8 MB，belt 约 11.5 MB；初次打开只下载所选原帧块和拓扑/统计，完整记录不会一次塞入内存。跳转时界面显示正在加载与已缓存的帧范围。

材质颜色、平滑法线、灯光和展示地面属于显示层；顶点与拓扑保持原结果。极薄的重叠布面默认不接收阴影贴图，避免有限分辨率产生黑点；布料仍投影到展示地面，阴影开关可做逐顶点不变的对照。诊断模式可以显示三角面和原网格。实际接触响应来自录制中的原 PPF 求解器，不来自显示地面或网页阴影。

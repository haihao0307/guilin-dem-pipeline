# KAOPU Crab Triad R01 执行顺序

## T0 — 分支与契约

- [x] 新建独立分支；
- [x] 固定 Composer／Score／Instrument 边界；
- [x] 建立零身份预设、完整表面、静态先于绑定的硬门；
- [x] 建立谱格式与纯乐器代码骨架。

## T1 — 第一只老师进入

- [ ] 固定老师文件、版本、SHA-256、许可与来源；
- [ ] 记录文件格式、对象树、网格数量、顶点／三角／法线／UV／材质数量；
- [ ] 检查缺失部位、穿插、重复面、镜像、非流形与隐藏几何；
- [ ] 决定第一阶段的真实领域边界：Brachyura 或单独验证的 Anomura 蟹形对象。

## T2 — 完整表面解码与语义分区

- [ ] 解码所有正式表面数据；
- [ ] 建立背甲、胸板、腹部、眼柄、触角、口器、螯足、步足等区域账本；
- [ ] 为每个附肢记录左右、角色、节段、连接点、局部轴和置信度；
- [ ] 明确未知区域，禁止自动补形。

## T3 — 制谱师拟合 Source Score

- [ ] 为全部表面建立参数图表、接缝和邻接；
- [ ] 拟合 `P_chart(u,v)`、法线和局部微形态；
- [ ] 将关节链、左右不对称、螯钳与附肢信息写入 Source Score；
- [ ] 输出全量位置、法线、轮廓和覆盖率误差报告。

## T4 — 乐器首次静态演奏

- [ ] 乐器读取外部谱并生成正式静态表面；
- [ ] 老师只作为透明对照层，不进入正式结果；
- [ ] 前、后、左、右、上、下和局部放大比较；
- [ ] 不绑骨、不做步态，直到用户确认静态形体。

## T5 — 静态形体用户验收

- [ ] 用户确认形体、部件数量、位置和表面；
- [ ] 冻结第一只对象的静态 Resolved Score；
- [ ] 未通过则返回 T2/T3，不允许用动作掩盖形体问题。

## T6 — 绑定与基础动作

- [ ] 按谱建立刚性外骨骼区域与分节关节链；
- [ ] 验证每一条腿、螯、眼柄和触角的局部轴与限制；
- [ ] 加入站立、横移、转向、抬螯、开合钳和诊断序列；
- [ ] 足端接触和身体高度由谱与地面条件共同求解。

## T7 — 第二只独立对象验证乐器

- [ ] 用不同形态的第二只蟹形老师重新制谱；
- [ ] 只有两只对象共同需要的运算才可提升为乐器公共能力；
- [ ] 第一只对象独有的参数继续留在谱中；
- [ ] 不能演奏第二只对象时，修改乐器框架而不是增加名称预设。

## T8 — 正式工作台和发布

- [ ] 三栏工作台：老师／谱驱动结果／数据与误差；
- [ ] 单击直接打开的固定公开 HTTPS；
- [ ] 桌面与手机真实浏览器 QA；
- [ ] 独立空播放器导入外部谱重演；
- [ ] 构建证明、公开证明、全量包与持续 Markdown 总账。

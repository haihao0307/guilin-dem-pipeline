# R05 work session status — 2026-10-25

## Research conclusions

1. Lace is not one generic construction. Museum sources distinguish needle lace (buttonhole/loop stitch construction, often firmer/crisper) from bobbin lace (crossed/plaited threads, often softer) and describe motifs, filling, joining bars/ground and edge finish as distinct structures.
2. NVIDIA's 2025 ray-wave fabric model and Cornell's micron-resolution work support multi-scale yarn/fiber appearance, view/light-dependent reflection and transmission, and explicit performance approximations. They are woven/knit models; their optical principles are transferable, but their topology and measured performance are not direct evidence for this lace generator.
3. R04's own report says its fill-curvature improvement was visually limited and added about 24.16% total triangles over R03. Therefore the next experiment should not add geometry density by default.

## Regression correction after correlated shader-phase change

The first CI run after adding phase-correlated irregularity exposed two test/geometry issues: the exact ellipse-radius assertion accidentally used the default plied profile, and the stronger 1.8% lobe amplitude caused the existing low-resolution swept-face/normal agreement check to fall below its 0.90 bound. The ellipse test now explicitly disables the envelope, and the lobe amplitude is restored to 1.2% with bounded deterministic modulation. The phase-correlated shading breakup remains. The next run must pass both checks before any further visual conclusions.

## R05.4 phase-wobble trial
R05.3 with phase wobble 0.16 passed the existing geometry/normal gate (lowest triangle-normal agreement 0.9022) and produced a geometry-only A/B delta of 0.261/255 overall and 0.351/255 macro. R05.4 increases phase wobble to 0.24 while keeping lobe amplitude at 1.2%. This is intended to make the three-lobe twist less machined without violating the radial-normal constraint; its acceptance depends on fresh CI and A/B, not on the expected effect.


## R05.5 short-fibre presentation control — 2026-10-25
- Added three reversible modes over the existing seeded short-fuzz geometry: off, soft short fuzz, and directional short fibres.
- The soft mode lowers raster support and opacity; the directional mode keeps the existing light-driven response. Switching modes creates no new geometry and does not increase fibre count.
- Saved/restored the selected mode in the R05 recipe, with older R05 recipes defaulting to directional mode 2. Input values are validated before mutating the live specimen.
- Added shader-level tests for the mode uniform and opacity gate, plus UI wiring tests for all three buttons and recipe persistence.
- This is a useful visual-review control, not a visual acceptance claim. It still requires the live browser to compare silhouette softness, dark-background visibility, grazing light and backlight, and to check for halos/aliasing.

## R05.6 sparse fibre coverage across the lace structure — 2026-10-25
- Extended the existing deterministic short-fibre generator from outline/trim to all four structural layers: ground net, fill, motif outline and trim.
- Used a deliberately uneven density hierarchy (2.5 / 5 / 18 / 14 fibres per centimetre respectively). Net and fill fibres are shorter and finer than motif and trim fibres; the opaque swept-yarn core and all core path topology remain unchanged.
- Added CPU geometry tests for per-layer fibre counts, expected vertices/indices per fibre, finite attributes, and density ordering. Updated the standalone manifest to disclose all four layers and the three presentation modes.
- Trade-off: two additional fibre draw batches are present and extra short-fibre geometry is generated for net/fill. The exact total varies by pattern and seed. The workbench's live geometry counter must be checked on all three specimen presets; a visual win does not excuse an unacceptable frame-time or memory increase.
- Visual gate remains open: the new short fibres must be judged at overall/macro scale under studio, grazing and backlight. Watch for noisy net holes, silhouette fuzz, aliasing, and over-softening. No production claim until live browser/WebGL QA is completed.
